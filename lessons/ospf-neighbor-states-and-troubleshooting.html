OSPF neighbor states and troubleshooting

How OSPF routers become neighbors

  • CCNA 3.4Single-area OSPFv2

No neighbour, no routes

OSPF routers only share routes with routers they have formed an adjacency with. When OSPF routes are missing, the first question is always the same: is the neighbour there, and what state is it in?

This lesson covers what two routers must agree on, the states they pass through, and how to read the output when it goes wrong.

What must match

Two routers on a link become neighbours only if all of these are true:

  • They are in the same subnet, with the same mask.
  • The interfaces are in the same area.
  • The hello and dead timers match. The defaults on Ethernet are 10 and 40 seconds.
  • Their router IDs are different.
  • Authentication matches, if it is used.
  • Neither interface is passive. A passive interface sends no hellos.
  • The MTU matches. If it does not, the routers see each other but get stuck part way.

These do not have to match: the OSPF process ID, which only matters inside one router, and the interface cost.

The states

A neighbour moves through these states in order:

  1. Down: no hello heard.
  2. Init: a hello was received, but it did not list this router's ID. The neighbour has not heard us yet.
  3. 2-Way: each router has seen itself in the other's hello. On Ethernet, the DR and BDR are chosen here.
  4. ExStart: the two decide who leads the database exchange.
  5. Exchange: they swap summaries of their link-state databases.
  6. Loading: each asks for the entries it is missing.
  7. Full: the databases match. Routes can now be calculated.

2-Way can be normal

On a shared Ethernet segment, routers form a Full adjacency only with the DR and the BDR. Two routers that are neither (DROTHERs) stay at 2-Way with each other, and that is correct.

In show ip ospf neighbor the State column shows both the state and the neighbour's role: FULL/DR, FULL/BDR, 2WAY/DROTHER. On a point-to-point link there is no DR, and it shows FULL/ -.

Reading the symptoms

  • No neighbour listed at all: hellos are not arriving or are being rejected. Check that the interface is up, that OSPF is enabled on it, that it is not passive, and that area, subnet and timers match.
  • Stuck in Init: this router hears the neighbour, but the neighbour does not hear this router. Look for a one-way problem, such as an ACL blocking OSPF in one direction.
  • Stuck in ExStart or Exchange: almost always an MTU mismatch.
  • Full, but a route is missing: the neighbour is fine. The missing network is not being advertised; check the network statements on the router that owns it.

The commands

  • show ip ospf neighbor: neighbours, their state, role and dead timer counting down.
  • show ip ospf interface g0/0: area, network type, cost, hello and dead timers, DR and BDR, and whether the interface is passive.
  • show ip ospf interface brief: one line per OSPF interface with area and cost.
  • show ip protocols: router ID, networks being advertised and passive interfaces.
  • show ip route ospf: the routes learned, marked O.

Compare show ip ospf interface on both ends of a link. Any setting that differs in the list above is the fault.

Hello facts worth knowing

Hellos go to the multicast address 224.0.0.5, all OSPF routers. Updates to the DR and BDR go to 224.0.0.6. OSPF is carried directly in IP as protocol 89; it does not use TCP or UDP.

The dead timer is four times the hello timer by default. Change the hello with ip ospf hello-interval on an interface and the dead timer follows.

Key terms

Adjacency
A full OSPF relationship in which two routers have exchanged their link-state databases.
Hello timer
How often an OSPF interface sends a hello; 10 seconds by default on Ethernet.
Dead timer
How long a router waits without a hello before declaring a neighbour down; 40 seconds by default on Ethernet.
2-Way
The neighbour state in which both routers have seen each other's hellos.
Full
The neighbour state in which both link-state databases match.
DROTHER
A router on a shared segment that is neither the DR nor the BDR.
Passive interface
An interface whose network is advertised but which sends no hellos, so no neighbours form on it.

For the exam

  • 3.4: configure and verify single-area OSPFv2, including neighbor adjacencies, point-to-point, broadcast (DR/BDR selection) and router ID.
  • Must match: area, subnet and mask, hello and dead timers, authentication, MTU. Router IDs must differ. Process IDs need not match.
  • Default timers on Ethernet are hello 10 and dead 40.
  • 2WAY/DROTHER between two non-DR routers is normal. FULL is expected with the DR and BDR.
  • Hellos go to 224.0.0.5.

Common mistakes

  • Making the LAN-facing interface and the link to the neighbour both passive. A passive interface forms no adjacency.
  • Putting the two ends of a link in different areas. No neighbour ever appears, even though both interfaces are up and can ping each other.
  • Treating 2WAY/DROTHER as a fault and resetting OSPF.
  • Assuming the process IDs must match and changing them.

Quick check

1. Which of these does NOT have to match for two routers to become OSPF neighbours?

  1. Area ID
  2. Hello timer
  3. Process ID
  4. Subnet mask
Show the answer

C. Process ID

The process ID is local to each router. Area, timers and subnet must all agree.

2. R1 and R2 are both DROTHERs on a shared Ethernet segment. What state should they show for each other?

  1. FULL
  2. 2WAY
  3. INIT
  4. EXSTART
Show the answer

B. 2WAY

DROTHERs form Full adjacencies only with the DR and BDR. Between themselves they stay at 2-Way.

3. A neighbour is stuck in ExStart. What is the usual cause?

  1. MTU mismatch
  2. Mismatched hello timers
  3. Duplicate router IDs
  4. A passive interface
Show the answer

A. MTU mismatch

The routers have exchanged hellos, so timers and area match. Getting stuck at the start of the database exchange points to different MTUs.

4. What are the default OSPF hello and dead timers on an Ethernet interface?

  1. 5 and 20 seconds
  2. 30 and 120 seconds
  3. 10 and 30 seconds
  4. 10 and 40 seconds
Show the answer

D. 10 and 40 seconds

Hello is 10 seconds and dead is four times that, 40 seconds.

5. R1 shows no OSPF neighbour on G0/0, and G0/0 is up. Which command shows the timers, area and passive setting for that interface?

  1. show ip route ospf
  2. show ip ospf interface g0/0
  3. show ip ospf database
  4. show cdp neighbors
Show the answer

B. show ip ospf interface g0/0

show ip ospf interface shows everything that must match with the neighbour. Compare it on both ends.

Securing and configuring a WLAN

How WPA2 and WPA3 secure a wireless LAN

  • 5.9
  • 5.10WLAN with WPA2 PSK
  • 2.9

The problem: anyone can listen

Radio does not stop at the office wall. Anyone in the car park can capture wireless frames, and anyone can try to join. A secure WLAN therefore needs three things: authentication (only allowed users join), encryption (captured frames are unreadable) and integrity (frames cannot be changed in transit, checked with a message integrity check, or MIC).

From WEP to WPA3

The original 802.11 offered open authentication (anyone may join) and WEP, which used the RC4 cipher with a short static key. WEP can be cracked in minutes and must not be used. The Wi-Fi Alliance then certified three generations:

  1. WPA: a stopgap that ran on WEP hardware, using TKIP for encryption. Now deprecated.
  2. WPA2: based on 802.11i, using AES-CCMP for encryption and integrity. The long-standing baseline.
  3. WPA3: uses AES with GCMP (the enterprise 192-bit mode uses GCMP-256), requires Protected Management Frames (PMF) so attackers cannot forge disconnect messages, and replaces the pre-shared key exchange with SAE.

Personal and Enterprise

Each WPA generation has two ways to authenticate:

  • Personal: everyone shares one passphrase, the PSK (pre-shared key), 8 to 63 characters. Simple, but everyone who knows it can join, and changing it means changing every device. With WPA2-PSK, an attacker who captures the four-way handshake can try passwords offline. WPA3-Personal uses SAE (Simultaneous Authentication of Equals), which defeats that offline guessing and gives forward secrecy.
  • Enterprise: each user logs in with their own credentials using 802.1X. The client (the supplicant) talks EAP to the AP or WLC (the authenticator), which asks a RADIUS server (the authentication server). One user can be removed without touching anyone else.

Either way, the result is a key the client and AP share, from which a four-way handshake derives fresh encryption keys for that session.

Building a WPA2-PSK WLAN on a WLC

On a Cisco AireOS WLC, in the web GUI:

  1. Dynamic interface first. Under Controller > Interfaces > New, give it a name and VLAN ID, then an IP address, mask, gateway, physical port and DHCP server for that VLAN. This is where the WLAN's clients will land.
  2. Create the WLAN. Under WLANs, choose Create New and Go. Enter a profile name (the WLC's own label), the SSID (the name clients see) and an ID number.
  3. General tab: tick Status: Enabled and choose the dynamic interface from step 1, which maps the SSID to its VLAN. Broadcast SSID controls whether beacons name it.
  4. Security tab, Layer 2: choose WPA+WPA2, tick the WPA2 Policy with AES encryption, and under authentication key management untick 802.1X and tick PSK. Choose ASCII and type the passphrase.
  5. Click Apply. For Enterprise instead, leave 802.1X ticked and pick a RADIUS server on the AAA Servers tab, after adding it under Security > AAA > RADIUS with its IP address and shared secret.

QoS and Advanced tabs

The QoS tab picks a profile that sets how the WLAN's traffic is prioritised:

  • Platinum: voice.
  • Gold: video.
  • Silver: best effort, the default.
  • Bronze: background traffic.

The Advanced tab holds settings such as Allow AAA Override (let RADIUS assign a VLAN or policy per user), session timeout, client exclusion after repeated failed logins, whether clients must get their address by DHCP, peer-to-peer blocking and FlexConnect local switching.

Check it worked

On the WLC, the WLANs list shows each WLAN as enabled, with its SSID and security policy (for example [WPA2][Auth(PSK)]). The Monitor > Clients page lists connected clients with their AP, WLAN, IP address and status. On a client, check it joined the right SSID and got an address in the expected VLAN's subnet. A client that associates but never gets an address points at the interface mapping or the DHCP server; one that is refused at once points at the passphrase or security settings.

Key terms

WPA2
Wi-Fi Alliance security certification using AES-CCMP; Personal (PSK) or Enterprise (802.1X).
WPA3
Current certification: GCMP, required PMF, and SAE in place of PSK for Personal mode.
PSK
Pre-shared key: one passphrase, 8 to 63 characters, shared by every user of a WLAN.
SAE
Simultaneous Authentication of Equals: WPA3-Personal's key exchange, resistant to offline password guessing.
802.1X
Port-based access control: each user authenticates with EAP to a RADIUS server.
TKIP
The WPA-era encryption built to run on WEP hardware; deprecated.
CCMP
The AES-based encryption and integrity protocol of WPA2.
Dynamic interface
A WLC interface tied to a VLAN; a WLAN mapped to it puts its clients in that VLAN.
PMF
Protected Management Frames: stops forged disassociation and deauthentication frames.

For the exam

  • 5.9: describe wireless security protocols (WPA, WPA2, WPA3). 5.10: configure and verify a WLAN within the GUI using WPA2 PSK. 2.9: interpret the WLAN GUI configuration for client connectivity: WLAN creation, security settings, QoS profiles and advanced settings.
  • Match each generation to its encryption: WPA with TKIP, WPA2 with AES-CCMP, WPA3 with GCMP.
  • WPA3-Personal uses SAE; WPA3 makes PMF mandatory.
  • Enterprise mode: supplicant, authenticator, authentication server (RADIUS), using EAP.
  • QoS profiles: Platinum voice, Gold video, Silver best effort (default), Bronze background.
  • Profile name is the WLC's label; SSID is what clients see. They can differ.

Common mistakes

  • Leaving 802.1X ticked alongside PSK when only a passphrase is intended: clients are asked for credentials no one has, or behave unpredictably.
  • Mapping the WLAN to the management interface instead of its dynamic interface: clients land in the wrong VLAN and get the wrong addresses or none.
  • Choosing TKIP for compatibility: modern clients may refuse it and throughput is limited; use AES.
  • Forgetting to enable the WLAN: it is configured but never broadcast.
  • A passphrase shorter than 8 characters: the WLC rejects it.

Quick check

1. Which encryption protocol does WPA2 use?

  1. TKIP
  2. RC4
  3. AES-CCMP
  4. GCMP-256
Show the answer

C. AES-CCMP

WPA2 is built on AES-CCMP. TKIP belongs to WPA, RC4 to WEP, and GCMP to WPA3.

2. What does WPA3-Personal use in place of the WPA2 pre-shared key exchange?

  1. SAE
  2. TKIP
  3. 802.1X
  4. WEP
Show the answer

A. SAE

SAE protects the passphrase from offline guessing even if an attacker records the handshake. 802.1X is the Enterprise method, not Personal.

3. On the WLC, a new WLAN's clients get addresses from the wrong subnet. Which setting should you check first?

  1. The QoS profile
  2. The interface chosen on the General tab
  3. The session timeout
  4. The SSID broadcast setting
Show the answer

B. The interface chosen on the General tab

The interface (or interface group) on the General tab maps the WLAN to its VLAN, which decides which subnet clients join.

4. A WLAN carries voice calls. Which QoS profile fits it?

  1. Silver
  2. Bronze
  3. Gold
  4. Platinum
Show the answer

D. Platinum

Platinum is for voice. Gold is for video, Silver is best effort (the default) and Bronze is background.

5. In WPA2-Enterprise, which device checks the user's credentials?

  1. The client, as supplicant
  2. The AP or WLC, as authenticator
  3. The RADIUS server, as authentication server
  4. The DHCP server
Show the answer

C. The RADIUS server, as authentication server

The authenticator only relays EAP messages; the RADIUS server decides whether the credentials are valid.

Per-VLAN root bridges

How spanning tree picks a root for each VLAN

  • 2.5Rapid PVST+ interpretation

The problem

Redundant switch links protect against a failed cable, but they form loops, and a broadcast caught in a Layer 2 loop circles for ever. Spanning Tree Protocol (STP) prevents that by blocking just enough ports to leave one loop-free path, a tree, centred on one switch: the root bridge.

Which switch is root matters. Here the old access switch ASW1 is root for both VLANs, so traffic is pulled through the weakest box, and one of the distribution uplinks sits idle.

How the root is elected

Switches exchange messages called BPDUs. Each carries a bridge ID: a priority plus the switch's MAC address. The lowest bridge ID becomes root.

  • The default priority is 32768. Priority goes up in steps of 4096, because its low bits carry the VLAN number (the extended system ID). So DSW1 shows priority 32778 in VLAN 10 by default.
  • When priorities tie, the lowest MAC wins. ASW1's 0009.7c11.0100 is lower than both distribution switches', so ASW1 wins every VLAN.

Changing the priority is how you choose the root yourself.

One tree per VLAN

PVST+ runs a separate spanning tree for every VLAN, and Rapid PVST+ is its faster version based on 802.1w. It reconverges in about a second where classic STP can take 30 to 50 seconds. Because each VLAN has its own tree, each can have its own root.

spanning-tree vlan 10 root primary is a macro. It sets priority 24576, or lower if needed to beat the current root. root secondary sets 28672, so that switch becomes root if the primary fails. DSW1 is primary for 10 and secondary for 20; DSW2 is the mirror.

Port roles after the change

Every non-root switch picks one root port: its lowest-cost path to the root. A Gigabit link costs 4 by default. Every link has one designated port, the side closer to the root, which forwards. In Rapid PVST+, a port that is neither becomes an alternate port and is discarding.

  1. VLAN 10, root DSW1: ASW1 reaches it directly through Gi0/1 (cost 4), so Gi0/1 is its root port.
  2. On the ASW1 to DSW2 link, both ends are cost 4 from the root. The tie goes to the lower bridge ID, DSW2 at 28672, so DSW2's end is designated and ASW1 Gi0/2 is alternate.
  3. VLAN 20 is the mirror image: root port Gi0/2, alternate Gi0/1.

Both uplinks now carry traffic, one VLAN each.

Check it worked

show spanning-tree vlan 10 on ASW1 shows the root's bridge ID, this switch's own, and each port's role (Root, Desg, Altn) and state (FWD or BLK). Run it for VLAN 20 too. Then ping PC3 from PC1 and PC4 from PC2: spanning tree changes paths, never reachability.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Before: the oldest switch wins All three switches have priority 32768, so the lowest MAC decides. ASW1's BPDUs claim root for both VLANs, and traffic is forced through the access switch.
  2. DSW1 claims VLAN 10 After root primary, DSW1 sends VLAN 10 BPDUs with priority 24576 plus 10. That beats ASW1, and every switch accepts DSW1 as root for VLAN 10.
  3. One uplink blocks for VLAN 10 For VLAN 10, ASW1 Gi0/1 to DSW1 is the root port. On the DSW2 link DSW2 has the lower bridge ID, so ASW1 Gi0/2 becomes alternate and discards VLAN 10 frames.
  4. DSW2 claims VLAN 20 DSW2 is primary for VLAN 20, so in that tree ASW1 Gi0/2 is the root port and Gi0/1 is the one that discards.
  5. VLAN 10 uses the left uplink PC1's frames to PC3 go up Gi0/1 to DSW1, the VLAN 10 root, then across to DSW2.
  6. VLAN 20 uses the right uplink PC2's frames to PC4 go up Gi0/2 to DSW2, the VLAN 20 root. Both uplinks now carry traffic.

Key terms

Root bridge
The switch at the centre of a spanning tree. The one with the lowest bridge ID.
Bridge ID
Priority plus MAC address. Lower is better.
BPDU
Bridge protocol data unit: the message switches exchange to build the spanning tree.
Root port
A non-root switch's port with the lowest-cost path to the root. Forwards.
Designated port
The forwarding port on each link, on the side closer to the root.
Alternate port
In Rapid PVST+, a backup path to the root that is discarding.
Rapid PVST+
Cisco's per-VLAN version of Rapid STP (802.1w). One tree per VLAN, fast convergence.
Extended system ID
The VLAN number added into the bridge priority, which is why priorities step by 4096.

For the exam

  • 2.5: interpret basic operations of Rapid PVST+: root port, root bridge (primary/secondary), and other port names; port states and roles.
  • Default priority 32768; it must be a multiple of 4096. Lowest bridge ID wins; on a tie, lowest MAC.
  • root primary sets 24576 (or lower if needed); root secondary sets 28672.
  • Rapid PVST+ port states: discarding, learning, forwarding. Roles: root, designated, alternate, backup.
  • Default port cost (short method): 4 for 1 Gbps, 19 for 100 Mbps.

Common mistakes

  • Leaving all priorities at the default: the switch with the lowest MAC, often the oldest, becomes root.
  • Setting a priority that is not a multiple of 4096: IOS rejects it.
  • Making the same switch primary for every VLAN: the other uplink stays blocked and the load is not shared.
  • Expecting root primary to keep a switch root forever: it sets a value once, and a switch added later with a lower priority can still take over.

Quick check

1. All three switches have priority 32768. Which becomes root?

  1. The switch with the most ports
  2. The switch with the lowest MAC address
  3. The switch with the highest MAC address
  4. The switch powered on first
Show the answer

B. The switch with the lowest MAC address

With equal priority, the bridge ID tie is broken by the lowest MAC address. Boot order does not matter.

2. What priority does spanning-tree vlan 20 root secondary set?

  1. 24576
  2. 32768
  3. 28672
  4. 4096
Show the answer

C. 28672

Secondary sets 28672: lower than the default 32768, but higher than the primary's 24576, so it takes over only if the primary fails.

3. Why can DSW1 be root for VLAN 10 and DSW2 root for VLAN 20 at the same time?

  1. Rapid PVST+ runs a separate spanning tree per VLAN
  2. Each switch has two MAC addresses
  3. The trunks carry only one VLAN each
  4. STP ignores VLANs
Show the answer

A. Rapid PVST+ runs a separate spanning tree per VLAN

PVST+ and Rapid PVST+ build one tree per VLAN, each with its own root election.

4. In VLAN 10, DSW1 is root. Which port on ASW1 is alternate (discarding)?

  1. Gi0/1, towards DSW1
  2. Fa0/1, towards PC1
  3. Gi0/2, towards DSW2
  4. None; all ports forward
Show the answer

C. Gi0/2, towards DSW2

Gi0/1 is the lowest-cost path to DSW1, so it is the root port. On the DSW2 link DSW2 has the lower bridge ID, so ASW1's end is alternate.

5. An engineer types spanning-tree vlan 10 priority 30000. What happens?

  1. It is accepted
  2. It is rejected: the priority must be a multiple of 4096
  3. It is rounded to 28672
  4. The switch becomes root
Show the answer

B. It is rejected: the priority must be a multiple of 4096

The low bits of the priority field carry the VLAN number, so only multiples of 4096 (0 to 61440) are allowed.

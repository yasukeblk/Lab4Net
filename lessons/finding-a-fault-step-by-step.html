Finding a fault step by step

How to find where a network is broken

  • CCNA 1.4
  • CCNA 3.1Routing-table interpretation

Have a method

Troubleshooting questions give you a diagram, some output and a symptom. Guessing is slow. A method is fast: start at the bottom layer, test outward one step at a time, and stop where the test first fails. The fault is between the last thing that worked and the first that did not.

Layers 1 and 2: is the interface up?

show ip interface brief on a router gives two columns for each interface. Learn the four combinations:

  • up / up: working.
  • administratively down / down: the interface has the shutdown command. Fix with no shutdown.
  • down / down: a layer 1 problem. No cable, a bad cable, or the other end is off or shut.
  • up / down: a layer 2 problem. The signal is there but the two ends do not agree on the link protocol.

On a switch, show interfaces status gives one word per port: connected, notconnect, disabled (shut down) or err-disabled (shut by a feature such as port security or BPDU Guard).

Layer 3: ping outward

From the device with the problem, ping in this order:

  1. Its own address. Proves the interface and IP stack are up.
  2. Its default gateway. Proves the local link, VLAN, address and mask.
  3. The far side of the gateway, or the next router. Proves the first hop routes.
  4. The destination.

Cisco ping output uses one character per packet: ! is a reply, . is a timeout, and U means a router sent back "destination unreachable", usually because it has no route.

A single lost packet at the start, .!!!!, is ARP at work and is not a fault.

Traceroute shows the path

traceroute (on Windows, tracert) lists the routers on the way to a destination.

It sends packets with a TTL of 1, then 2, then 3. Each router that lowers the TTL to zero drops the packet and reports back, which reveals that router's address. The last line that answers is the last hop that works. The fault is at that router or just after it.

Lines of * * * mean no answer came back for that hop. On a Cisco device, stop a long trace with Ctrl+Shift+6.

Remember the way back

A ping needs two routes: one to the destination and one back to the source. If a trace reaches the last router but the host never answers, check the host's default gateway and the routers' routes back to the source subnet.

Test this with an extended ping that sets the source: ping 192.168.20.10 source g0/1. If a ping from the router's nearest interface works but a ping sourced from its LAN interface fails, the far end has no route back to that LAN.

Read the routing table

On each router along the path, ask: does it have a route for the destination? show ip route 192.168.20.10 shows the route that would be used, or % Network not in table.

Check the route points the right way: correct next hop, and an exit interface that is up. If there is a default route, the line Gateway of last resort near the top says where it leads. A wrong default route sends everything unknown to the wrong place.

When the link is up but slow

If everything pings but the connection is slow or drops, look at the interface counters with show interfaces g0/1:

  • CRC and input errors climbing: a bad cable, interference or a duplex mismatch.
  • Late collisions: the classic sign of a duplex mismatch. The half-duplex side counts them.
  • Runts and giants: frames that are too small or too large.

The top of the same output shows the negotiated speed and duplex. Both ends must agree.

Key terms

Administratively down
The interface state caused by the shutdown command.
Err-disabled
A switch port state in which a protection feature has shut the port.
Traceroute
A tool that lists each router on the path by sending packets with rising TTL values.
Extended ping
A ping with options set, such as the source interface.
Gateway of last resort
The next hop of the default route, shown at the top of the routing table.
Late collision
A collision detected after the first 64 bytes of a frame; a sign of a duplex mismatch.
CRC error
A received frame whose checksum failed, meaning it was damaged on the way.

For the exam

  • 1.4: identify interface and cable issues (collisions, errors, mismatched duplex and speed). 3.1: interpret the components of the routing table.
  • administratively down/down is shutdown. down/down is layer 1. up/down is layer 2.
  • In ping output, ! is success, . is a timeout and U is unreachable.
  • Traceroute relies on TTL expiring at each hop. The last hop that answers is the last one that works.
  • Late collisions on a full-duplex capable link point to a duplex mismatch.

Common mistakes

  • Changing configuration before finding where the fault is. Test first, then change one thing.
  • Checking only the route to the destination. The reply needs a route back to the source.
  • Reading down/down as a shutdown. A shut interface says administratively down.

Quick check

1. An interface shows "administratively down" and "down". What fixes it?

  1. Replacing the cable
  2. Setting the speed and duplex
  3. Entering no shutdown on the interface
  4. Adding a default route
Show the answer

C. Entering no shutdown on the interface

Administratively down means the shutdown command is on the interface. no shutdown brings it up.

2. A ping from a Cisco router returns U.U.U. What does U mean?

  1. The destination replied late
  2. A router reported the destination unreachable
  3. The packet was sent as UDP
  4. The interface is up
Show the answer

B. A router reported the destination unreachable

U is a "destination unreachable" message, usually from a router with no route to the destination. A dot is a timeout.

3. How does traceroute discover each router on a path?

  1. It sends packets with increasing TTL values
  2. It reads the routing table of each router
  3. It uses CDP
  4. It sends ARP requests to each hop
Show the answer

A. It sends packets with increasing TTL values

A router that lowers the TTL to zero drops the packet and reports back, which reveals its address. Raising the TTL by one each time reveals the next router.

4. PC1 can ping its gateway R1. A ping from R1 to PC2 works, but PC1 cannot ping PC2. What should you check first?

  1. The cable between PC1 and the switch
  2. PC1's subnet mask
  3. The speed of R1's interface
  4. Whether PC2 and the routers near it have a route back to PC1's subnet
Show the answer

D. Whether PC2 and the routers near it have a route back to PC1's subnet

PC1 reaches its gateway, so its own link is fine. R1 reaches PC2 from an address PC2 can answer. The likely gap is the return route to PC1's subnet, or PC2's default gateway.

5. An interface has a rising count of late collisions. What is the most likely cause?

  1. A duplex mismatch
  2. A wrong subnet mask
  3. A missing VLAN
  4. An ACL
Show the answer

A. A duplex mismatch

Late collisions happen when one end is half duplex and the other is full. Check the duplex setting on both ends.

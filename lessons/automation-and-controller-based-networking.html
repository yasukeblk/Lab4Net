Automation and controller-based networking

How controllers change network management

  • 6.1
  • 6.2
  • 6.3

The problem with one box at a time

In a traditional network, every router and switch is configured on its own, usually by someone typing CLI commands over SSH. That works for ten devices. For five hundred, it is slow, and each typo or forgotten device makes the network a little less consistent. This drift from the intended configuration causes outages that are hard to trace.

Network automation means software makes the changes instead. The benefits the exam expects you to know: fewer human errors, the same change applied the same way everywhere, faster rollout, easier compliance checks, and staff time freed for design work instead of repetitive tasks.

Three planes

Every network device does three jobs, called planes:

  • Data plane (forwarding plane): moves packets and frames from one interface to another, using tables already built. This is most of the work and is done in hardware.
  • Control plane: builds those tables. OSPF, STP, ARP and MAC learning are all control plane.
  • Management plane: how people and tools reach the device to configure and monitor it: SSH, SNMP, syslog, APIs.

Traditional versus controller-based

In a traditional network the control plane is distributed. Each device runs its own protocols, talks to its neighbours and makes its own decisions, and each is managed separately.

In a controller-based network, also called software-defined networking (SDN), a central controller holds the view of the whole network. It works out the policy and configuration and pushes it to the devices. Some or all control plane work moves from the devices to the controller. The devices keep forwarding packets themselves: the data plane stays on the device.

The operator stops configuring boxes and instead tells the controller what outcome is wanted, for example which groups of users may reach which applications. This is often called intent-based networking.

Northbound and southbound APIs

An API (Application Programming Interface) is a defined way for one program to talk to another. A controller has two kinds, named by their direction in the usual diagram, where applications sit above the controller and devices below it.

  • Northbound APIs face up, to applications, scripts and dashboards. They are usually REST APIs that exchange JSON.
  • Southbound APIs face down, to the network devices. Examples are NETCONF, RESTCONF, OpenFlow and OpFlex. Some controllers also still use SSH and SNMP southbound.

Underlay, overlay and fabric

  • The underlay is the physical network: the cables, switches and the IP routing that lets every device reach every other.
  • The overlay is a set of virtual networks built on top, using tunnels. A tunnel wraps the original packet inside a new header so it crosses the underlay as if the two ends were directly connected. VXLAN is a common tunnel type.
  • The fabric is the underlay and overlay together, managed as one system.

The overlay lets the controller create segments and apply policy without changing the physical network for each one.

What changes for the engineer

In a traditional network a change to a security policy may mean logging in to dozens of switches and editing ACLs on each. With a controller the engineer edits the policy once, and the controller works out which devices need which configuration and pushes it. The controller also collects status from every device, so it can show the health of the whole network in one place and check that each device still matches what it was told.

The work moves from typing commands to defining policy, reading dashboards and writing scripts against the controller's API.

Cisco examples

Cisco SD-Access builds a campus fabric managed by Catalyst Center (formerly DNA Center). Its overlay uses LISP for the control plane and VXLAN for the data plane. Cisco SD-WAN uses a controller-based design for WAN links between sites. Cisco ACI runs data centre spine-leaf fabrics from a controller called the APIC.

The exam does not ask you to configure these. It asks you to recognise the parts and explain what changes when control moves to a controller.

Key terms

Data plane
The part of a device that forwards packets using tables already built.
Control plane
The part that builds forwarding tables, through protocols such as OSPF and STP.
Management plane
The access used to configure and monitor a device, such as SSH, SNMP and APIs.
SDN
Software-defined networking: a central controller programs network devices.
Northbound API
The controller interface used by applications and scripts, usually REST.
Southbound API
The controller interface used to program devices, such as NETCONF or OpenFlow.
Underlay
The physical network and its IP routing.
Overlay
Virtual networks carried in tunnels across the underlay.
Fabric
Underlay and overlay managed together as one system.
Configuration drift
Devices slowly moving away from their intended configuration through manual changes.

For the exam

  • 6.1: explain how automation impacts network management. 6.2: compare traditional networks with controller-based networking. 6.3: describe controller-based, software-defined architecture (overlay, underlay, and fabric), separation of control plane and data plane, and northbound and southbound APIs.
  • Controllers centralise the control plane. The data plane stays on the devices.
  • Northbound faces applications (REST, JSON). Southbound faces devices (NETCONF, RESTCONF, OpenFlow, OpFlex).
  • The overlay is built from tunnels such as VXLAN, and the underlay is the routed physical network.
  • Know the benefits of automation: consistency, fewer errors, speed, scale.

Common mistakes

  • Saying a controller forwards the user traffic: it does not. Packets still flow device to device in the data plane.
  • Swapping north and south: think of the diagram, with applications on top and switches underneath.
  • Thinking an overlay replaces the underlay: the tunnels only work if the underlay can already route between their end points.
  • Assuming automation means no CLI knowledge is needed: troubleshooting still needs you to read what the devices are doing.

Quick check

1. In a controller-based network, which plane is centralised on the controller?

  1. The data plane
  2. The control plane
  3. The management plane only
  4. None, all planes stay on the devices
Show the answer

B. The control plane

The controller takes over the control plane decisions and pushes the results down. Forwarding (the data plane) still happens on each device.

2. A Python script asks the controller for a list of all switches. Which interface does it use?

  1. A southbound API
  2. The data plane
  3. A northbound API
  4. The console port
Show the answer

C. A northbound API

Applications and scripts talk to the controller through its northbound API, usually REST. Southbound APIs are how the controller talks to the devices.

3. Which of these is a southbound API?

  1. NETCONF
  2. A web dashboard
  3. A REST call from a ticketing system
  4. SMTP
Show the answer

A. NETCONF

NETCONF is used by a controller or tool to configure devices, so it is southbound. The dashboard and the ticketing system are applications using the northbound side.

4. What is an overlay network?

  1. The physical cabling between switches
  2. A routing protocol that replaces OSPF
  3. A backup copy of the configuration
  4. Virtual networks built from tunnels that run across the physical network
Show the answer

D. Virtual networks built from tunnels that run across the physical network

The overlay uses tunnels, such as VXLAN, on top of the routed underlay. The physical cabling and routing are the underlay.

5. Which is a main benefit of network automation?

  1. Devices no longer need a data plane
  2. Changes are applied the same way everywhere, with fewer human errors
  3. Routing protocols are no longer needed anywhere
  4. Links get more bandwidth
Show the answer

B. Changes are applied the same way everywhere, with fewer human errors

Automation removes repetitive manual typing, so changes are consistent and faster. It does not change what devices need to forward traffic or add bandwidth.

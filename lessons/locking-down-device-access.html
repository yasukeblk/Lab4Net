Locking down device access

How to secure logins on a router

  • 5.3Local device access control
  • 4.8SSH management

The problem: anyone can log in

R1 was left with shared passwords stored as readable text and Telnet open to every subnet. Anyone who sees the config learns the passwords, and anyone on the user LAN can try them. Nobody can tell who logged in, because everyone shares one password.

Securing device access means answering four questions: who may log in, how (which protocol), from where, and for how long.

Passwords that cannot be read

IOS stores passwords in different ways, shown by a type number in the config:

  • Type 0: clear text. Anyone reading the config can see it.
  • Type 7: what service password-encryption produces for line and enable password passwords. It stops someone reading over your shoulder, but it is easily reversed.
  • Type 5 (MD5), and on newer software types 8 and 9: one-way hashes, used by enable secret and username ... secret. They cannot simply be decoded.

If both enable password and enable secret exist, the secret wins. Remove the old one with no enable password so it is not left lying in the config.

Who: individual accounts

username admin privilege 15 secret Adm1n-Pass creates a local account. Privilege 15 is full access, straight into privileged EXEC mode. Personal accounts mean every login can be traced to a person, and one person leaving means deleting one account, not changing a shared password.

login local on a line makes it ask for a username and password from this list. In this lab it goes on both the VTY lines and the console. The console is physical access and deserves the same rules.

How and for how long

transport input ssh on the VTY lines refuses Telnet, which sends credentials in clear text. SSH encrypts them.

exec-timeout 5 0 ends a session after 5 minutes and 0 seconds with no input. The default is 10 minutes, and exec-timeout 0 0 turns the timeout off, which is a bad idea on any line people can walk away from.

From where: access-class

A standard ACL matches only the source address, which is exactly the question here. ACL 10, permit 192.168.10.0 0.0.0.255, matches the admin subnet. Everything else hits the implicit deny at the end of every ACL.

access-class 10 in applies it to the VTY lines, not to an interface. It filters who may open a session to the router, whichever of the router's addresses they connect to. User traffic passing through R1 is not affected.

Finally, all of this is in the running config, in RAM. copy running-config startup-config saves it, or a reload undoes the work.

Check it worked

  1. show running-config: no readable passwords, and a type 5 or similar hash for the secrets.
  2. SSH from ADMIN as admin works.
  3. SSH from PC1 is refused. show access-lists shows the match counters.
  4. show startup-config contains the same settings.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Before: anyone, any protocol From the user subnet, PC1 can Telnet to R1 and type the shared password. Anyone capturing the traffic can read that password too.
  2. SSH from the admin subnet ADMIN opens SSH to 192.168.10.1. Source 192.168.10.10 matches ACL 10, so access-class lets the session start.
  3. Personal login login local asks for a username and password. admin with Adm1n-Pass is checked against the hashed secret, and privilege 15 gives full access.
  4. User subnet refused PC1 at 192.168.20.10 tries SSH. ACL 10 has no permit for it, so the implicit deny refuses the session before a login prompt appears.
  5. Idle session closed If the admin walks away, exec-timeout 5 0 closes the session after 5 minutes without input, so nobody can use it.

Key terms

enable secret
The password for privileged EXEC mode, stored as a one-way hash. Overrides enable password.
service password-encryption
Turns clear-text passwords in the config into type 7, which hides them from view but is reversible.
Privilege level 15
Full administrative access. Level 1 is user EXEC.
exec-timeout
How long an idle session stays open, in minutes and seconds. Default 10 minutes.
access-class
Applies an ACL to VTY lines to control who may open remote sessions.
Standard ACL
An ACL that matches only the source IP address. Numbered 1 to 99 or 1300 to 1999.
Implicit deny
The invisible deny everything at the end of every ACL.

For the exam

  • 5.3: configure and verify device access control using local passwords. 4.8: configure network devices for remote access using SSH.
  • Type 7 is reversible; enable secret and username secret are hashed.
  • If enable password and enable secret are both set, enable secret is used.
  • access-class applies an ACL to VTY lines; ip access-group applies one to an interface.
  • exec-timeout takes minutes then seconds; the default is 10 minutes, 0 0 disables it.

Common mistakes

  • Applying the VTY ACL with ip access-group under the line, or forgetting the admin subnet in it: either the filter does nothing or you lock yourself out.
  • Using username admin password instead of secret: the password is stored reversibly.
  • Hardening the VTY lines but leaving the console with no login.
  • Not saving: after a reload the old clear-text passwords and Telnet come back.

Quick check

1. Which password storage is reversible and should not be relied on alone?

  1. enable secret
  2. username ... secret
  3. Type 7, from service password-encryption
  4. Type 9
Show the answer

C. Type 7, from service password-encryption

Type 7 only hides passwords from casual view and is easily decoded. The secret forms are one-way hashes.

2. Both enable password and enable secret are configured with different values. Which one works?

  1. enable password
  2. enable secret
  3. Either one
  4. Neither, until one is removed
Show the answer

B. enable secret

enable secret takes precedence. The old enable password should still be removed so it is not left in the config.

3. How do you allow only 192.168.10.0/24 to open SSH sessions to R1?

  1. A standard ACL applied to the VTY lines with access-class in
  2. A standard ACL applied to G0/1 with ip access-group in
  3. transport input ssh on G0/0
  4. An extended ACL on the console line
Show the answer

A. A standard ACL applied to the VTY lines with access-class in

access-class filters sessions to the VTY lines themselves. An interface ACL would also affect traffic passing through and only covers that one interface.

4. What does exec-timeout 5 0 do?

  1. Locks the line for 5 minutes after a failed login
  2. Closes a session after 5 minutes with no input
  3. Allows 5 login attempts
  4. Delays the login prompt by 5 seconds
Show the answer

B. Closes a session after 5 minutes with no input

The arguments are minutes and seconds of idle time. 0 0 would disable the timeout.

5. After hardening R1, the router reloads and Telnet works again. What was missed?

  1. service password-encryption
  2. copy running-config startup-config
  3. login local
  4. exec-timeout
Show the answer

B. copy running-config startup-config

All changes live in the running config until they are saved. A reload loads startup-config, which still had the old settings.

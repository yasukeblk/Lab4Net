REST APIs and JSON

How scripts talk to network devices

  • 6.5
  • 6.7

What an API is for

The CLI was built for people: it prints text that is easy to read but hard for a program to pick apart. An API (Application Programming Interface) is built for programs. A script sends a structured request and gets back structured data it can use directly. Controllers such as Catalyst Center, and many modern devices, offer APIs for this.

REST in plain terms

REST (Representational State Transfer) is a style of API that uses ordinary HTTP, the same protocol as web pages, normally over HTTPS. Each thing the API manages, such as a device, an interface or a VLAN, is a resource with its own address, its URI, for example https://controller/api/v1/devices.

REST APIs are stateless: the server keeps no memory of earlier requests, so every request must carry everything needed, including proof of who is asking. They follow a client-server model, and responses can be marked as cacheable.

CRUD and the HTTP verbs

Almost everything a program does with data is one of four actions, called CRUD. REST maps each one to an HTTP verb (also called a method):

  • Create: POST adds a new resource.
  • Read: GET retrieves a resource without changing it.
  • Update: PUT replaces a resource completely. PATCH changes only the fields sent.
  • Delete: DELETE removes a resource.

The server answers with a status code. 2xx means success: 200 OK, 201 Created, 204 No Content. 4xx means the client made a mistake: 400 Bad Request, 401 Unauthorized (not authenticated), 403 Forbidden (authenticated but not allowed), 404 Not Found. 5xx means the server failed, such as 500 Internal Server Error.

Authentication

Because REST is stateless, each request proves who sent it, usually in an HTTP header.

  • Basic authentication: the username and password are joined and Base64-encoded into the Authorization header. Base64 is encoding, not encryption, so this is only safe over HTTPS.
  • API key: a long secret value issued to a user or application and sent with each request.
  • Token: the client logs in once and receives a token, often valid for a limited time, then sends that token with later requests. Bearer tokens and OAuth work this way. Catalyst Center hands out a token that is then sent in a header on each call.

Data encoding

The data in a request or response must be in a format both sides understand. The common ones are JSON, XML and YAML. The Content-Type header says which format the body is in, and the Accept header says which format the client wants back, for example application/json.

Putting it together, one request has four parts: the verb, the URI of the resource, the headers (authentication and formats), and for POST, PUT and PATCH a body holding the data. A script that wants the device list sends a GET to the devices URI with its token in a header. The controller replies with a status code of 200 and a JSON body listing each device, which the script can loop through without parsing any CLI text.

Reading JSON

JSON (JavaScript Object Notation) is plain text built from a few pieces:

  • An object is wrapped in curly braces { } and holds key-value pairs, separated by commas. Each key is a string in double quotes, followed by a colon and the value.
  • An array is an ordered list in square brackets [ ], separated by commas.
  • A value can be a string in double quotes, a number, true or false, null, an object or an array.

For example: {"hostname": "R1", "interfaces": [{"name": "G0/0", "enabled": true}]}. That is one object with two keys. The value of interfaces is an array holding one object. Spaces and line breaks between items do not matter. Single quotes, comments and a comma after the last item are not allowed.

Key terms

API
A defined way for one program to request data or actions from another.
REST
An API style that uses HTTP verbs on resources identified by URIs, and keeps no session state.
CRUD
Create, Read, Update, Delete: the four basic actions on data.
URI
The address of a resource in a REST API.
Status code
A three-digit number in the HTTP response showing success or the kind of failure.
Token authentication
Logging in once to receive a token, then sending it with each request.
JSON object
A set of key-value pairs inside curly braces.
JSON array
An ordered list of values inside square brackets.

For the exam

  • 6.5: describe characteristics of REST-based APIs (authentication types, CRUD, HTTP verbs, and data encoding). 6.7: recognize components of JSON-encoded data.
  • CRUD to HTTP: Create = POST, Read = GET, Update = PUT or PATCH, Delete = DELETE.
  • REST is stateless and client-server. Requests carry their own authentication.
  • JSON keys are double-quoted strings. Objects use { }, arrays use [ ], booleans are true and false in lower case.
  • Know the status code families: 2xx success, 4xx client error, 5xx server error.

Common mistakes

  • Thinking Basic authentication encrypts the password: Base64 is reversible by anyone, so it needs HTTPS.
  • Using POST to read data: a read is a GET, and the exam maps verbs to CRUD exactly.
  • Counting a whole JSON document as one key-value pair: count the keys inside each object, and remember nested objects have their own.
  • Writing JSON with single quotes or a trailing comma: the parser rejects it, and the API returns 400 Bad Request.

Quick check

1. Which HTTP verb creates a new resource in a REST API?

  1. GET
  2. PUT
  3. POST
  4. DELETE
Show the answer

C. POST

POST is Create. PUT updates (replaces) an existing resource, and GET only reads.

2. A request is rejected with 401. What does that mean?

  1. The request was not authenticated
  2. The resource does not exist
  3. The server crashed
  4. The request succeeded with no content
Show the answer

A. The request was not authenticated

401 Unauthorized means the server does not know who you are, for example a missing or expired token. 404 is not found, 5xx is a server failure and 204 is success with no body.

3. In {"vlans": [10, 20, 30], "site": "HQ"}, what is the value of vlans?

  1. An object
  2. A string
  3. A key-value pair
  4. An array
Show the answer

D. An array

Square brackets mark an array, here a list of three numbers. The whole thing in curly braces is the object, holding two key-value pairs.

4. Why must each REST request carry its own authentication?

  1. Because JSON cannot hold a password
  2. Because REST is stateless, so the server keeps no session between requests
  3. Because HTTPS removes the headers
  4. Because only GET requests are authenticated
Show the answer

B. Because REST is stateless, so the server keeps no session between requests

A stateless server does not remember earlier requests, so every request must prove who sent it, usually with a token or key in a header.

5. Which of these is valid JSON?

  1. {"enabled": true}
  2. {'enabled': true}
  3. {"enabled": True,}
  4. {enabled = true}
Show the answer

A. {"enabled": true}

JSON needs double-quoted keys, a colon, and lower-case true. Single quotes, a capital True, a trailing comma and an equals sign are all invalid.

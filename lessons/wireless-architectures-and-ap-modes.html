Wireless architectures and AP modes

How access points and controllers fit together

  • 2.6
  • 2.7WLAN physical connections

The problem: many APs to manage

A home needs one access point. A hospital or campus needs hundreds. Each one needs the same SSIDs, the same security, sensible channels and power levels, and clients must roam between them without dropping a call. Configuring hundreds of APs one by one is slow and error-prone, and no single AP can see the whole picture of which channels its neighbours use. So Cisco offers several architectures that differ in where the brains live.

Autonomous and cloud-based APs

An autonomous AP is self-contained. It is configured on its own (by its CLI or web page) and bridges wireless traffic straight onto the wired network. Each SSID maps to a VLAN, so an autonomous AP serving several SSIDs connects to a switch trunk port. It suits small sites, but every AP is a separate box to manage.

A cloud-based AP, such as Cisco Meraki, is managed from a dashboard on the internet. The AP downloads its settings from the cloud, but user traffic still goes from the AP onto the local network, not through the cloud.

Lightweight APs and the WLC

In the split-MAC architecture the work is divided. A lightweight AP handles the real-time radio jobs: sending beacons, answering probes, acknowledging frames and encrypting traffic. A wireless LAN controller (WLC) handles the management jobs: authentication, association, roaming, security policy, QoS and choosing channels and power for every AP.

The AP and WLC talk over CAPWAP (Control and Provisioning of Wireless Access Points), which builds two tunnels between them:

  • Control tunnel on UDP 5246, always encrypted with DTLS.
  • Data tunnel on UDP 5247, carrying client traffic to the WLC; encryption is optional.

Because client traffic of every SSID travels inside the tunnel, the WLC is where it meets the wired VLANs.

Where the WLC sits

Cisco describes four deployment models:

  1. Unified (centralized): a hardware WLC in a central place such as the data centre, for large sites.
  2. Cloud: a WLC running as a virtual machine in a data centre or public cloud.
  3. Embedded: the WLC runs inside a switch, for smaller sites.
  4. Mobility Express: one AP also acts as the WLC for the others, for small branches.

AP modes

A lightweight AP can be put in a mode that sets its job:

  • Local: the default. Serves clients and tunnels their traffic to the WLC; briefly scans other channels when it can.
  • FlexConnect: for branch offices over a WAN. It can switch client traffic onto the local network itself, and keep serving clients if the link to the WLC fails.
  • Monitor: serves no clients; listens to find rogue APs, detect attacks and help locate devices.
  • Rogue detector: radio off; watches the wired network for traffic from rogue devices.
  • Sniffer: captures 802.11 frames and sends them to a computer running a tool such as Wireshark.
  • SE-Connect: spectrum analysis, to find non-Wi-Fi interference.
  • Bridge / mesh: links APs to each other over the air, where cabling is not possible.

Cabling it up

APs are usually powered over the network cable by PoE from the switch.

  • A lightweight AP in local mode goes on an access port. It only needs one VLAN for its own address, because client traffic for every SSID rides inside CAPWAP.
  • An autonomous AP, or a FlexConnect AP switching several VLANs locally, goes on a trunk port.
  • A WLC connects to the switch with trunk ports, its distribution system ports, so it can put each WLAN on its VLAN. It also has a service port for out-of-band management, a console port and a redundancy port for a standby WLC.

Several distribution ports can be bundled into one logical link with LAG (link aggregation). A Cisco WLC does not negotiate with LACP or PAgP, so the switch side must be a static EtherChannel: channel-group 1 mode on.

Key terms

Autonomous AP
An AP configured and run on its own, bridging wireless traffic straight onto the wired network.
Lightweight AP
An AP that handles only real-time radio work and is managed by a WLC.
WLC
Wireless LAN controller: centrally manages lightweight APs, security, roaming and RF settings.
Split-MAC
The division of 802.11 work between a lightweight AP and a WLC.
CAPWAP
The tunnel protocol between AP and WLC: control on UDP 5246, data on UDP 5247.
FlexConnect
An AP mode that can switch traffic locally and survive loss of the WAN link to the WLC.
LAG
Bundling WLC distribution ports into one logical link; the switch uses a static EtherChannel.

For the exam

  • 2.6: describe Cisco wireless architectures and AP modes. 2.7: describe physical infrastructure connections of WLAN components (AP, WLC, access/trunk ports, LAG).
  • CAPWAP uses UDP 5246 for control (DTLS encrypted) and UDP 5247 for data.
  • Local mode is the default; know what monitor, rogue detector, sniffer, SE-Connect, FlexConnect and bridge modes do.
  • Local-mode AP: access port. Autonomous AP or locally switching FlexConnect AP: trunk port. WLC: trunk.
  • WLC LAG supports only static EtherChannel (mode on), not LACP or PAgP.

Common mistakes

  • Setting the switch side of a WLC LAG to LACP mode active: the WLC never negotiates, so the bundle does not come up.
  • Putting a local-mode AP on a trunk and expecting each SSID on its own VLAN at the switch: client traffic is inside CAPWAP and is placed on VLANs at the WLC.
  • Putting an autonomous AP with several SSIDs on an access port: only one VLAN reaches it, so clients on the other SSIDs get no addresses.
  • Expecting a monitor-mode AP to serve clients: it only listens.

Quick check

1. Which UDP port carries CAPWAP control traffic?

  1. 5247
  2. 5246
  3. 1812
  4. 161
Show the answer

B. 5246

CAPWAP control is UDP 5246 and is always DTLS encrypted. 5247 is the data tunnel. 1812 is RADIUS and 161 is SNMP.

2. A branch AP must keep serving clients if the WAN link to the central WLC fails. Which mode fits?

  1. Local
  2. Monitor
  3. Sniffer
  4. FlexConnect
Show the answer

D. FlexConnect

FlexConnect can switch traffic locally and keep working without the WLC. A local-mode AP depends on its CAPWAP tunnel to the WLC.

3. What kind of switch port does a lightweight AP in local mode normally connect to?

  1. An access port
  2. A trunk port carrying every WLAN VLAN
  3. A routed port
  4. An EtherChannel with LACP
Show the answer

A. An access port

All client traffic rides inside CAPWAP to the WLC, so the AP needs only one VLAN for itself. The WLC connects on trunks.

4. Four WLC ports are bundled with LAG. How is the switch side configured?

  1. channel-group 1 mode active
  2. channel-group 1 mode desirable
  3. channel-group 1 mode on
  4. channel-group 1 mode passive
Show the answer

C. channel-group 1 mode on

A Cisco WLC does not run LACP or PAgP, so only a static EtherChannel (mode on) matches it. Active and passive are LACP; desirable is PAgP.

5. In split-MAC, which job stays on the lightweight AP rather than the WLC?

  1. Sending beacons and acknowledging frames
  2. Client authentication
  3. Choosing channels for every AP
  4. Applying security policy
Show the answer

A. Sending beacons and acknowledging frames

Real-time radio work such as beacons, probe responses and acknowledgements must happen at the AP. Management decisions are made centrally on the WLC.

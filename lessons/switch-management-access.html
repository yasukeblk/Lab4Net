Switch management access

How to reach and manage a switch remotely

  • 1.6IPv4 addressing and subnetting
  • 5.3Local device access control

Switching needs no IP address

A Layer 2 switch forwards frames using MAC addresses. It can do that all day with no IP address at all, which is why SW1 already passes PC1's traffic.

Managing it is different. The console port works with no address, but only for someone standing next to the switch with a cable. To log in from ADMIN, SSH needs an IP address on the switch, a way for replies to get back to another subnet, and a secure login. This lab adds all three.

The SVI: the switch's own address

A switch's physical ports have no IP addresses. Instead you give it a switch virtual interface (SVI): interface vlan 99. The SVI is the switch itself, as a host, inside VLAN 99.

Using a dedicated management VLAN keeps the login prompt away from user VLANs. PC1 in VLAN 10 cannot reach 192.168.99.2 unless the router lets it.

An SVI is only up/up when the VLAN exists on the switch and at least one port carrying that VLAN is up and forwarding. Here that port is Gi0/1, the trunk to R1, where R1 subinterface G0/0.99 is 192.168.99.1.

Why the switch needs a default gateway

Once the SVI is up, ADMIN's ping still fails. The request reaches the switch, but the reply is for 192.168.50.10, which is not in 192.168.99.0/24. A Layer 2 switch does not route, so it does not know where to send it.

The fix is the same as on a PC: ip default-gateway 192.168.99.1. Traffic for any other subnet now goes to R1, which routes it to the admin LAN. This command is for switches that are not routing. A Layer 3 switch with ip routing enabled uses a default route instead.

SSH instead of Telnet

The VTY lines are the switch's virtual terminals for remote logins. Telnet (TCP port 23) sends everything, including the password, in clear text. SSH (TCP port 22) encrypts the session. Enabling SSH takes a few pieces:

  1. A hostname other than the default, and a domain name (lab.local). The key is named hostname.domain.
  2. An RSA key pair: crypto key generate rsa with a 2048-bit modulus. SSH version 2 needs at least 768 bits.
  3. A local user, netadmin, stored with secret so it is hashed.
  4. On line vty 0 4: login local to ask for that username and password, and transport input ssh to refuse Telnet.

Check it worked

show ip interface brief should show Vlan99 up/up with 192.168.99.2. show ip ssh shows whether SSH is enabled and which version. The real test is from ADMIN: ssh -l netadmin 192.168.99.2 works, which proves the address, the gateway and the login, and Telnet to the same address is refused.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Nothing to answer ADMIN pings 192.168.99.2. R1 routes the ping into VLAN 99, but SW1 has no address there yet, so nothing answers.
  2. The SVI receives the ping With interface vlan 99 up at 192.168.99.2, the ping arrives at the switch itself. R1 G0/0.99 tagged it for VLAN 99 on the trunk.
  3. The reply has nowhere to go The reply is for 192.168.50.10, outside 192.168.99.0/24. The switch does not route, and with no default gateway it cannot send the reply.
  4. Default gateway set With ip default-gateway 192.168.99.1, SW1 sends the reply to R1, which routes it to the admin LAN. The ping works.
  5. Telnet is closed ADMIN tries Telnet on TCP 23. transport input ssh on the VTY lines refuses it, so no password crosses the network in clear text.
  6. SSH works ADMIN connects with ssh -l netadmin. The session is encrypted with SW1's RSA key, and login local checks the netadmin account.

Key terms

SVI
Switch virtual interface: a Layer 3 interface for a VLAN, such as interface vlan 99. Gives the switch an IP address.
Management VLAN
A VLAN set aside for reaching network devices, kept separate from user traffic.
Default gateway (on a switch)
ip default-gateway: where a non-routing switch sends traffic for other subnets.
VTY lines
Virtual terminal lines that accept remote Telnet or SSH sessions. Lines 0 to 4 are the usual first five.
SSH
Secure Shell: encrypted remote login on TCP port 22.
Telnet
Unencrypted remote login on TCP port 23. Sends passwords in clear text.
RSA key pair
The public and private keys SSH uses to set up encryption. Generated with crypto key generate rsa.
login local
Makes a line ask for a username and password from the device's own user list.

For the exam

  • 2.8: describe network device management access (Telnet, SSH, console). 4.8: configure network devices for remote access using SSH. 1.6: IPv4 addressing.
  • A switch is managed through an SVI, and it needs ip default-gateway to answer other subnets.
  • SSH prerequisites: hostname, domain name, RSA key, local user, VTY login local, transport input ssh.
  • SSH uses TCP 22, Telnet TCP 23. Use ip ssh version 2 to force version 2.
  • An SVI needs its VLAN to exist and an active port in that VLAN to be up/up.

Common mistakes

  • No default gateway: the switch can be pinged from its own subnet but not from anywhere else.
  • SVI left shut down, or the VLAN never created: the interface shows down and nothing answers.
  • login instead of login local: the line asks for a line password, not the user accounts, and SSH logins fail.
  • Generating the RSA key before setting the domain name: IOS refuses, because the key is named after hostname and domain.

Quick check

1. ADMIN on 192.168.50.0/24 cannot ping SW1 at 192.168.99.2, but R1 can. The SVI is up/up. What is most likely missing on SW1?

  1. A trunk to R1
  2. transport input ssh
  3. ip domain-name
  4. ip default-gateway 192.168.99.1
Show the answer

D. ip default-gateway 192.168.99.1

R1 is on the switch's own subnet, so it works. ADMIN is on another subnet, and the switch needs a gateway to send the reply there.

2. Which command gives a Layer 2 switch an IP address for management?

  1. ip address on interface vlan 99
  2. ip address on interface FastEthernet0/1
  3. ip default-gateway 192.168.99.2
  4. switchport access vlan 99
Show the answer

A. ip address on interface vlan 99

Physical switch ports have no IP addresses. The SVI, interface vlan 99, is the switch's own Layer 3 interface.

3. Which is NOT required before SSH logins work on a switch?

  1. An RSA key pair
  2. A domain name
  3. An enable password
  4. A local username used with login local
Show the answer

C. An enable password

SSH needs the key, and the key needs hostname and domain. The VTY login uses the local user. An enable secret is good practice but not needed for the SSH session itself.

4. What does transport input ssh do on the VTY lines?

  1. Encrypts the console port
  2. Allows only SSH for remote sessions, refusing Telnet
  3. Generates the RSA key
  4. Forces SSH version 2
Show the answer

B. Allows only SSH for remote sessions, refusing Telnet

It limits which protocols may open a VTY session. Version 2 is forced with ip ssh version 2.

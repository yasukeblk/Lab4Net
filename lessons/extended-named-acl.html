Extended named ACL

How to filter by protocol and port

  • 5.6Access control lists

The problem: allow one service, not the whole host

Staff on 192.168.1.0/24 may use the web server on SRV1 (192.168.3.10) but nothing else on it: no ping, no file sharing, no remote login. Everything else staff do must keep working.

A standard ACL cannot do this, because it only sees the source. An extended ACL matches the protocol, the source, the destination and, for TCP and UDP, the port. That is enough to say "staff to SRV1 on TCP port 80 only".

Reading an extended line

Each line follows the same pattern: action, protocol, source, destination, then an optional port test.

permit tcp 192.168.1.0 0.0.0.255 host 192.168.3.10 eq 80 reads as: permit TCP from any staff address to exactly 192.168.3.10, destination port equal to 80 (HTTP). The port goes after the address it belongs to; placed after the destination it tests the destination port, which is the service being used.

The protocol ip means any IP packet, whatever is inside. tcp, udp and icmp narrow it. Other port tests include gt, lt, neq and range.

Order matters: specific first

The rules are the same as for any ACL: top down, first match wins, implicit deny at the end. So the order of WEB-ONLY is the design:

  1. Permit staff to SRV1 on TCP 80. Web traffic matches here and stops.
  2. Deny all other IP from staff to SRV1. Ping and anything else to the server stop here.
  3. Permit ip any any. Everything else passes, instead of hitting the implicit deny.

Swap lines 1 and 2 and web traffic would match the deny first, so nothing would reach the server.

Named ACLs

Instead of a number, ip access-list extended WEB-ONLY gives the list a name that says what it is for, and opens a sub-mode for its lines. IOS numbers the lines 10, 20, 30, so you can later add a line between them (for example sequence 15) or remove one with no 20, without rewriting the whole list.

Placement: close to the source

Because an extended ACL knows the destination, it can sit close to the source without blocking too much. Here it is applied inbound on R1 G0/0, the staff LAN interface. Unwanted packets are dropped at the first router instead of crossing R1, the transit link and R2 before being thrown away.

Applied inbound, it checks traffic from PC1 entering R1. The server's replies leave R1 on G0/0, so this ACL does not check them.

Check it worked

From PC1: telnet 192.168.3.10 80 should open (TCP 80 is allowed), ping 192.168.3.10 should fail (ICMP is not TCP 80), and ping 10.0.0.2 should work (permit ip any any). PC2 is on G0/1, so it is not affected at all. show access-lists WEB-ONLY shows the match count on each line.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Web traffic matches line 10 PC1 opens TCP port 80 to 192.168.3.10. ACL WEB-ONLY checks it as it enters R1 G0/0, and the first line permits it.
  2. It reaches the server R1 routes the packet across the transit link and R2 delivers it. The web connection opens.
  3. Replies are not filtered The server's reply leaves R1 on G0/0. The ACL is inbound on G0/0, so traffic going out toward PC1 is not checked.
  4. A ping to the server is dropped PC1 pings 192.168.3.10. ICMP is not TCP 80, so line 10 does not match. Line 20 denies all IP from staff to the server, and R1 drops it right at the edge.
  5. Other destinations still work PC1 pings 10.0.0.2. Lines 10 and 20 are about the server only, so the packet falls to line 30, permit ip any any, and reaches R2.
  6. Guests are not affected PC2 enters R1 on G0/1, where no ACL is applied, so its ping reaches the server. WEB-ONLY only checks traffic entering G0/0.

Key terms

Extended ACL
An ACL that matches protocol, source, destination and port. Numbered 100 to 199 or 2000 to 2699, or named.
Named ACL
An ACL identified by a name instead of a number, edited line by line in its own sub-mode.
Sequence number
The number of each line in an ACL, used to insert or delete individual lines.
eq
Port test meaning equal to, as in eq 80.
Destination port
The port of the service being reached, such as 80 for HTTP or 22 for SSH.
permit ip any any
A final line that allows everything not matched earlier, overriding the implicit deny.

For the exam

  • 5.6: configure and verify access control lists.
  • Extended ACLs: numbers 100 to 199 and 2000 to 2699, or a name. Place them close to the source.
  • Know common ports: HTTP 80, HTTPS 443, SSH 22, Telnet 23, DNS 53, DHCP 67/68.
  • A port test after the source address checks the source port; after the destination it checks the destination port.
  • Named ACLs let you insert and delete lines by sequence number.

Common mistakes

  • Putting the deny line before the permit: web traffic matches the deny first and the server becomes unreachable.
  • Forgetting permit ip any any: staff lose every destination, including R2 at 10.0.0.2.
  • Writing eq 80 after the source address: it tests the client's source port, which is a random high number, so the permit never matches.
  • Applying the ACL in the wrong direction: out on G0/0 checks traffic going to the staff LAN, so nothing staff send is filtered.

Quick check

1. Which line permits staff to reach the web server on SRV1?

  1. permit tcp host 192.168.3.10 eq 80 192.168.1.0 0.0.0.255
  2. permit tcp 192.168.1.0 0.0.0.255 eq 80 host 192.168.3.10
  3. permit ip 192.168.1.0 0.0.0.255 host 192.168.3.10 eq 80
  4. permit tcp 192.168.1.0 0.0.0.255 host 192.168.3.10 eq 80
Show the answer

D. permit tcp 192.168.1.0 0.0.0.255 host 192.168.3.10 eq 80

Source first, then destination, then the port after the destination to test the service port. The second option tests the client's source port, and ip cannot take a port.

2. WEB-ONLY has the deny line above the permit tcp line. What happens when PC1 opens port 80 on SRV1?

  1. It works, because the permit is more specific
  2. It is dropped, because the deny matches first
  3. It works, because named ACLs sort lines automatically
  4. It is dropped by the implicit deny
Show the answer

B. It is dropped, because the deny matches first

ACLs stop at the first match. The deny ip line matches web traffic too, so it is dropped before the permit is ever read.

3. Where is an extended ACL normally placed, and why?

  1. Close to the source, because it can see the destination and drops unwanted traffic early
  2. Close to the destination, because it only sees the source
  3. On the server itself
  4. Outbound on every interface
Show the answer

A. Close to the source, because it can see the destination and drops unwanted traffic early

An extended ACL is precise enough to sit near the source without blocking other destinations, so it saves carrying traffic that will be dropped anyway.

4. PC1's ping 192.168.3.10 fails but telnet 192.168.3.10 80 opens. Why?

  1. Ping uses UDP port 80
  2. The ACL only filters inbound replies
  3. Ping is ICMP, which does not match permit tcp ... eq 80, and the deny line catches it
  4. The server does not answer pings
Show the answer

C. Ping is ICMP, which does not match permit tcp ... eq 80, and the deny line catches it

Line 10 only allows TCP to port 80. ICMP falls to line 20, which denies everything else from staff to the server.

5. What does a named ACL let you do that an old numbered one typed in global config does not?

  1. Match on port numbers
  2. Insert or delete single lines by sequence number
  3. Apply the ACL to more than one direction at once
  4. Skip the implicit deny
Show the answer

B. Insert or delete single lines by sequence number

Named ACLs number their lines (10, 20, 30), so you can add line 15 or remove line 20 alone. Ports and direction work the same in both kinds.

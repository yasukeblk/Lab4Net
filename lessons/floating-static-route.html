Floating static route

How a backup route waits for a failure

  • 3.2Forwarding decisions
  • 3.3Static routing

The problem: one path, no plan B

HQ (R1, PC1) and the branch (R2, PC2) are joined by two links. G0/1 is the fast primary link (10.0.12.0/30). G0/2 is a slower backup link (10.0.21.0/30). Today each router has a static route, a route typed by hand, to the other LAN through the primary link only.

A static route does not look for alternatives. If the primary link fails, the route disappears and the branch is cut off, even though a working cable sits right next to it. You want a second route that is ready, but only used when the first one is gone.

Administrative distance decides between sources

A router can learn a route to the same network from several places: a connected interface, a static route, OSPF and so on. Administrative distance (AD) is a number that says how much to trust each source. Lower wins. The defaults to know:

  • Connected 0, static 1
  • eBGP 20, EIGRP 90, OSPF 110, RIP 120
  • iBGP 200; 255 means never use

Only the best route for each network goes into the routing table. The others are not mixed in or shared; they simply wait.

A floating route is a static route with a worse AD

A floating static route is a static route given a higher AD than the route it backs up. The number goes at the end of the command: ip route 192.168.2.0 255.255.255.0 10.0.21.2 5 on R1.

The primary static route has AD 1, so it wins. The floating route with AD 5 stays in the running configuration but does not appear in show ip route. It "floats" above the table, ready to drop in. To back up an OSPF route the floating AD must be higher than 110, or it would replace OSPF instead of backing it up.

How failover happens

  1. R1 G0/1 goes down. Its connected subnet 10.0.12.0/30 leaves the routing table.
  2. The primary route points to next hop 10.0.12.2. R1 can no longer reach that next hop, so it removes the route.
  3. The floating route is now the best route left to 192.168.2.0/24, so R1 installs it.
  4. When G0/1 comes back, the AD 1 route returns and pushes the floating route out again. Nobody has to touch anything.

Routing works in both directions, so R2 needs its own floating route to 192.168.1.0/24 via 10.0.21.1. Without it, PC1's packets reach PC2 but the replies still head for the dead link.

Check it worked

show ip route shows the primary as S 192.168.2.0/24 [1/0] via 10.0.12.2. The first number in the brackets is the AD, the second the metric. show ip route 192.168.2.10 shows exactly which entry that address uses. After shutting G0/1, the same command shows [5/0] via 10.0.21.2, and tracert from PC1 shows the hop through the backup link. show running-config | include ip route lists both routes, including the one that is hidden from the table.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Normal path PC1 pings PC2. R1 looks up 192.168.2.0/24 and finds the static route [1/0] via 10.0.12.2, so the packet crosses the fast primary link.
  2. The backup waits R1 now also has a route via 10.0.21.2 with AD 5. Only the best route per network enters the table, so AD 1 wins and the backup stays in the config.
  3. The primary link fails G0/1 shuts down. Subnet 10.0.12.0/30 disappears, the next hop 10.0.12.2 becomes unreachable, and R1 removes the primary route.
  4. The floating route drops in The AD 5 route is now the best one left, so R1 installs it. The packet crosses the backup link G0/2 to R2 and on to PC2.
  5. The reply needs R2's backup too R2 lost its primary route as well and has installed its own floating route via 10.0.21.1. Without it the reply would be lost.
  6. The primary returns G0/1 comes back up. The AD 1 route returns and pushes the floating route back out, so traffic moves back to the fast link on its own.

Key terms

Static route
A route typed in by hand. It does not change unless the router loses the way to its next hop.
Administrative distance
How trusted a route source is, from 0 to 255. Lower wins when two sources offer the same prefix.
Floating static route
A static route with a higher administrative distance than the main route, used only when the main route is gone.
Next hop
The address of the neighbouring router a packet is handed to.
Metric
The cost of a route within one source. Static routes have metric 0.
Failover
Traffic moving to a backup path automatically when the main path fails.

For the exam

  • 3.3: configure and verify IPv4 and IPv6 static routing, including floating static. 3.2: how a router decides, using administrative distance.
  • Default AD values: connected 0, static 1, eBGP 20, EIGRP 90, OSPF 110, RIP 120, iBGP 200.
  • A floating static route is not shown in show ip route until the main route is removed.
  • In [1/0] the first number is AD, the second the metric.
  • IPv6 works the same way: ipv6 route ::/0 2001:db8::2 5 floats with AD 5.

Common mistakes

  • Floating route on one router only: traffic fails over one way and replies are lost.
  • AD lower than or equal to the primary: the "backup" replaces or shares with the primary instead of waiting.
  • Backing up OSPF with AD 5: the static route beats OSPF (110) and becomes the main path.
  • Primary link fails somewhere beyond the interface (for example behind a switch) while the interface stays up: the router still thinks the next hop is reachable and never fails over.

Quick check

1. R1 has ip route 192.168.2.0 255.255.255.0 10.0.12.2 and ip route 192.168.2.0 255.255.255.0 10.0.21.2 5. What does show ip route show for 192.168.2.0/24?

  1. Only the route via 10.0.12.2
  2. Both routes, sharing the traffic
  3. Only the route via 10.0.21.2
  4. Neither, because the routes conflict
Show the answer

A. Only the route via 10.0.12.2

Only the best route per prefix is installed. AD 1 beats AD 5, so the second route waits outside the table. Equal-cost sharing needs equal AD and metric.

2. A company wants a static route to back up an OSPF-learned route. Which AD should the static route use?

  1. 1
  2. 90
  3. 120
  4. 100
Show the answer

C. 120

To wait behind OSPF the static route needs an AD higher than 110, so 120 works. Any of the others is lower than 110 and would replace the OSPF route.

3. Failover worked on R1, but pings from PC1 to PC2 still fail while the primary is down. What is the most likely cause?

  1. R1 needs a lower AD on its floating route
  2. R2 has no floating route back to 192.168.1.0/24
  3. PC2 has the wrong subnet mask
  4. The backup link needs OSPF
Show the answer

B. R2 has no floating route back to 192.168.1.0/24

Routing is needed both ways. The request reaches PC2, but R2 still tries to send the reply through the dead primary link.

4. In S 192.168.2.0/24 [5/0] via 10.0.21.2, what does the 5 mean?

  1. The metric
  2. The hop count
  3. The number of failovers
  4. The administrative distance
Show the answer

D. The administrative distance

The first number in the brackets is the administrative distance, the second is the metric. Static routes always have metric 0.

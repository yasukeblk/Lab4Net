OSPF router IDs and passive interfaces

How OSPF routers name themselves and pick peers

  • 3.4Single-area OSPFv2

The problem

OSPF lets routers share routes automatically. Here R1 and R2 run it, but two things were left to chance. The routers chose their own identities, and every interface sends hellos, the messages OSPF uses to find neighbors. A rogue router on R1's user LAN heard those hellos, became a neighbor, and is now injecting a route that R2 believes.

The router ID

Every OSPF router has a router ID: a 32-bit number written like an IPv4 address. Other routers use it to name this router in their neighbor tables and in the link-state database. When the process starts, IOS chooses it in this order:

  1. The router-id command, if configured.
  2. Otherwise, the highest IP address on an up loopback interface.
  3. Otherwise, the highest IP address on an up physical interface.

With no loopbacks, R1 would pick 192.168.1.1 over 10.0.12.1, which says little about which router it is. Two routers with the same router ID will not form an adjacency. Setting 1.1.1.1 and 2.2.2.2 makes the IDs fixed and readable.

Why a restart is needed

The router ID is chosen once, when the process starts. Typing router-id on a running router only prints a message telling you to reload or use clear ip ospf process. Clearing the process restarts OSPF: every adjacency drops and forms again, now with the new ID. On a live network that is a short outage, so it is done in a maintenance window.

Hellos and neighbors

OSPF sends hellos out of every interface it runs on, every 10 seconds on Ethernet by default. A dead interval of 40 seconds without hellos means the neighbor is gone. Two routers become neighbors only if key settings in the hellos match, including area, subnet, hello and dead timers, and they have different router IDs.

Any interface that sends hellos will accept a neighbor. On R1's G0/0 that means anything plugged into the user LAN, which is how ROGUE got in.

Passive interfaces

A passive interface does not send hellos and does not form neighbors, but OSPF still advertises its network. That is exactly what a user LAN needs: R2 must still learn 192.168.1.0/24, but nobody on that LAN should be a neighbor.

passive-interface default makes every interface passive. no passive-interface g0/1 then reopens only the link between the routers. Starting from passive is safer, because a new interface added later is passive until you decide otherwise.

Check it worked

show ip protocols shows the router ID and the passive interfaces. show ip ospf neighbor on R1 should list only 2.2.2.2. On R2, show ip route ospf should still have 192.168.1.0/24, marked O, but no rogue route. Finally PC1 pings PC2.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. A rogue neighbor ROGUE sends OSPF hellos on the user LAN. R1 G0/0 is not passive, so it accepts ROGUE as a neighbor.
  2. The bad route spreads R1 shares ROGUE's route with R2, as OSPF shares everything in the area. R2 installs it and will send traffic towards a device nobody approved.
  3. Fixed router IDs After router-id and clear ip ospf process, R1 restarts as 1.1.1.1 and R2 as 2.2.2.2. The adjacency forms again under the new names.
  4. Passive on the user LAN G0/0 is now passive. R1 sends no hellos there and forms no neighbor, so ROGUE's hellos get nowhere and its route ages out.
  5. The real link still talks no passive-interface g0/1 keeps hellos on the link between the routers, so R1 and R2 stay neighbors.
  6. Routes still flow R1 still advertises 192.168.1.0/24 from its passive LAN. R2 has the route, so PC1 reaches PC2.

Key terms

Router ID
A 32-bit identifier, written like an IPv4 address, that names an OSPF router.
Hello
The OSPF message that discovers neighbors and keeps adjacencies alive. Every 10 seconds on Ethernet by default.
Dead interval
How long without a hello before a neighbor is declared down. 40 seconds by default on Ethernet.
Adjacency
A full OSPF neighbor relationship over which routing information is exchanged.
Passive interface
An interface whose network is advertised but which sends no hellos and forms no neighbors.
Loopback interface
A virtual interface that is always up. A common source for the router ID.
Link-state database
Each router's copy of the network map built from the information its neighbors share.

For the exam

  • 3.4: configure and verify single-area OSPFv2: neighbor adjacencies, point-to-point, broadcast (DR/BDR selection), router ID.
  • Router ID order: manual router-id, highest up loopback, highest up physical interface.
  • A new router ID takes effect only after clear ip ospf process or a reload.
  • Passive interfaces still advertise their networks; they only stop hellos.
  • Duplicate router IDs prevent adjacency. OSPF's administrative distance is 110.

Common mistakes

  • Setting router-id and not clearing the process: show ip protocols still shows the old ID.
  • Making the router-to-router link passive as well: the adjacency drops and remote routes disappear.
  • Thinking passive removes the network from OSPF: the LAN is still advertised, which is the point.
  • Copying a config between routers including the same router-id: the two routers never become neighbors.

Quick check

1. A router has no router-id command, a loopback at 10.255.255.1, and physical interfaces at 192.168.1.1 and 172.16.0.1. Which router ID does OSPF choose?

  1. 192.168.1.1
  2. 172.16.0.1
  3. 10.255.255.1
  4. 0.0.0.0
Show the answer

C. 10.255.255.1

A loopback beats any physical interface, even one with a higher address. Physical interfaces are used only when no loopback is up.

2. You type router-id 1.1.1.1 on a router already running OSPF. What happens?

  1. The ID changes immediately
  2. Nothing until the OSPF process is restarted or the router reloads
  3. OSPF shuts down
  4. The command is rejected
Show the answer

B. Nothing until the OSPF process is restarted or the router reloads

The router ID is chosen when the process starts. IOS tells you to use clear ip ospf process.

3. What does a passive interface still do in OSPF?

  1. Send hellos every 10 seconds
  2. Form adjacencies with routers on its LAN
  3. Have its network advertised to other routers
  4. Nothing at all; it is removed from OSPF
Show the answer

C. Have its network advertised to other routers

Passive stops hellos and neighbors, but the network is still advertised. That is why R2 keeps its route to R1's user LAN.

4. After passive-interface default on R1 and R2, the routers lose their adjacency. What was missed?

  1. clear ip ospf process
  2. no passive-interface g0/1
  3. router-id
  4. network 10.0.12.0 0.0.0.3 area 0
Show the answer

B. no passive-interface g0/1

Default-passive also silences the link between the routers. That link needs hellos turned back on.

5. Two routers on a shared link are both configured with router ID 1.1.1.1. What is the result?

  1. They form an adjacency normally
  2. The one with the higher interface IP wins
  3. OSPF picks a new ID automatically
  4. They do not form an adjacency
Show the answer

D. They do not form an adjacency

A duplicate router ID stops the adjacency, and IOS logs the duplicate. OSPF never renames a router by itself; you fix it by setting a unique router-id.

DNS: names to addresses

How names become addresses

  • CCNA 4.3DHCP and DNS concepts

The problem DNS solves

Devices talk to IP addresses. People remember names. DNS (Domain Name System) is the service that turns a name such as www.example.com into an address such as 203.0.113.10.

It runs before almost everything else a user does. That is why a DNS fault looks like "the internet is down" even when every link and route is fine.

How a lookup works

  1. The application asks the operating system for the address of a name.
  2. The host checks its own cache and its local hosts file. If the answer is there, it stops.
  3. Otherwise it sends a query to its configured DNS server, also called a resolver. The host learned that server address from DHCP or from manual settings.
  4. If the resolver does not know the answer, it asks other servers on the host's behalf: a root server, then the server for .com, then the server for example.com.
  5. The resolver returns the answer and keeps a copy.

Each answer carries a TTL, the time it may be cached. Until it runs out, the same question is answered from memory.

Record types

A DNS server stores records. The ones to know:

  • A: a name to an IPv4 address.
  • AAAA: a name to an IPv6 address.
  • CNAME: an alias that points one name at another name.
  • MX: the mail server for a domain.
  • NS: the name servers that hold a domain's records.
  • PTR: the reverse, an address to a name.

Ports

DNS uses port 53. Ordinary queries use UDP, because one small question and one small answer do not need a connection. TCP port 53 is used when an answer is too large for one UDP message, and for copying whole zones between servers.

If an ACL has to let DNS through, it needs to permit UDP 53, and usually TCP 53 as well.

DNS on a Cisco device

A router or switch can be a DNS client, so that you can type names in commands such as ping:

  • ip name-server 8.8.8.8 tells it which server to ask.
  • ip domain-lookup turns name lookups on. It is on by default.
  • ip domain-name example.com sets the domain added to short names. SSH key generation also needs it.
  • ip host SRV1 192.168.10.10 adds a local name, like an entry in a hosts file.

With lookups on and no server set, a mistyped command is treated as a host name and the console waits while it tries to resolve it. Many people turn that off in a lab with no ip domain-lookup.

How DHCP and DNS fit together

The two services do different jobs. DHCP gives a host its address, mask, default gateway and the address of a DNS server. DNS then answers name questions. In a DHCP pool the command is dns-server.

A host with a correct address and gateway but a wrong DNS server can ping 8.8.8.8 but cannot open a website by name.

Checking it works

On a PC, nslookup www.example.com asks the configured server and shows the answer and which server gave it. ipconfig /all shows which DNS servers the PC is using.

The quick test for any "cannot reach it" report: ping by address, then ping by name. If the address works and the name does not, the network is fine and the fault is DNS. On a router, show hosts lists the name servers and cached names.

Key terms

DNS
Domain Name System: the service that maps names to IP addresses.
Resolver
The DNS server a host is configured to ask; it finds the answer on the host's behalf.
A record
A DNS record mapping a name to an IPv4 address.
AAAA record
A DNS record mapping a name to an IPv6 address.
CNAME
A DNS record that makes one name an alias of another.
TTL
In DNS, how long an answer may be kept in a cache.
Hosts file
A local list of names and addresses a host checks before asking a DNS server.

For the exam

  • 4.3: explain the role of DHCP and DNS within the network.
  • DNS uses port 53: UDP for normal queries, TCP for large answers and zone transfers.
  • A record is IPv4, AAAA is IPv6, CNAME is an alias, MX is mail, PTR is address to name.
  • ip name-server sets the server a Cisco device asks. ip domain-lookup is on by default.

Common mistakes

  • Blaming routing when only names fail. If a ping to an address works and a ping to a name does not, look at DNS.
  • Leaving the dns-server line out of a DHCP pool. Clients get an address and a gateway but cannot resolve any name.
  • Permitting only TCP 53 or only UDP 53 in an ACL. Most queries are UDP, but some answers need TCP.

Quick check

1. Which DNS record maps a name to an IPv6 address?

  1. A
  2. CNAME
  3. AAAA
  4. PTR
Show the answer

C. AAAA

AAAA holds an IPv6 address. A is the IPv4 version, CNAME is an alias and PTR maps an address back to a name.

2. A user can ping 8.8.8.8 but cannot open any website by name. What is the most likely cause?

  1. The default gateway is wrong
  2. The PC has no working DNS server
  3. The switch port is in the wrong VLAN
  4. NAT is not configured
Show the answer

B. The PC has no working DNS server

Reaching 8.8.8.8 proves the address, gateway, routing and NAT all work. Only name resolution is failing, so check the DNS server setting.

3. Which transport and port does a normal DNS query use?

  1. UDP 53
  2. TCP 23
  3. UDP 67
  4. TCP 443
Show the answer

A. UDP 53

DNS queries use UDP port 53. TCP 53 is also used, for large answers and zone transfers. UDP 67 is the DHCP server port.

4. Which command tells a Cisco router which DNS server to ask?

  1. ip domain-name
  2. ip host
  3. ip dns server
  4. ip name-server
Show the answer

D. ip name-server

ip name-server sets the server address. ip domain-name sets the default domain, ip host adds one local name, and ip dns server makes the router answer queries itself.

5. How does a PC usually learn the address of its DNS server?

  1. From an ARP reply
  2. From a DHCP option
  3. From the switch
  4. From the root DNS servers
Show the answer

B. From a DHCP option

The DHCP server hands out the DNS server address with the IP address, mask and gateway. It can also be typed in by hand.

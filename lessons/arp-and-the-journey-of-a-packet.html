ARP and the journey of a packet

How a packet crosses a routed network

  • CCNA 1.13Switching concepts
  • CCNA 3.2Forwarding decisions

Two addresses, two jobs

Every frame on an Ethernet network carries two kinds of address. The IP addresses say where the packet starts and where it must end up. The MAC addresses say which device on this link sent the frame and which device on this link should take it.

The key idea: across a routed network the IP addresses stay the same the whole way, and the MAC addresses change at every router.

Step 1: same subnet or not?

Before sending, a host compares the destination IP with its own address and mask.

  • Same subnet: send the frame straight to the destination's MAC address.
  • Different subnet: send the frame to the MAC address of the default gateway. The destination IP in the packet is still the far host.

A host never puts a remote host's MAC address in a frame. It cannot learn it, and does not need to.

Step 2: ARP finds the MAC

The host knows the IP address it wants to reach on its link but not the MAC. ARP (Address Resolution Protocol) finds it.

  1. The host sends an ARP request as a broadcast, to FFFF.FFFF.FFFF: "Who has 192.168.10.1? Tell 192.168.10.20."
  2. Every device in the VLAN receives it. Only the owner of that address answers.
  3. The ARP reply is a unicast straight back to the asker, carrying the MAC address.
  4. The host stores the pair in its ARP table and sends the waiting packet.

ARP broadcasts stay inside one subnet, because routers do not forward broadcasts.

Step 3: what the router does

The frame arrives at the router, addressed to the router's MAC. The router then:

  1. Checks the frame for errors and removes the Ethernet header and trailer. The old MAC addresses are gone.
  2. Looks up the destination IP in its routing table and picks the longest matching route.
  3. Lowers the packet's TTL by one. If it reaches zero the packet is dropped and an ICMP "time exceeded" message goes back to the sender.
  4. Uses ARP on the outgoing link, if it has to, to find the MAC of the next hop or of the final host.
  5. Builds a new frame: source MAC is its own outgoing interface, destination MAC is the next device.

This repeats at every router until the packet reaches the destination subnet.

The reply comes back the same way

A ping only succeeds if the reply gets home. The far host runs the same steps in reverse: same subnet or not, ARP for its own gateway, and so on. Each router on the way back needs a route to the original sender.

Many "ping fails" problems are a missing route or gateway on the return path. The request arrives, and the reply has nowhere to go.

Seeing it on devices

  • On a PC, arp -a shows the ARP table.
  • On a router, show ip arp shows it. The entry for the router's own interface has a dash for its age.
  • An entry marked Incomplete means a request was sent and nobody answered: the address is wrong, the host is off, or it is in another VLAN.

The first ping to a new destination from a Cisco router often shows .!!!!. The first packet was dropped while ARP was finding the MAC. That is normal.

Why this matters for troubleshooting

Because MAC addresses only matter on one link, a fault can be pinned down hop by hop. If a host has no ARP entry for its gateway, the problem is local: cable, VLAN, address or mask. If it does, and pings still fail, look at routing further along.

Key terms

ARP
Address Resolution Protocol: finds the MAC address that belongs to an IPv4 address on the local link.
ARP table
The list of IP-to-MAC pairs a device has learned, kept for a limited time.
Default gateway
The router address a host sends frames to when the destination is on another subnet.
TTL
Time to live: a counter in the IP header that each router lowers by one, so packets cannot loop for ever.
Encapsulation
Wrapping a packet in a frame header and trailer before sending it on a link.
Next hop
The next router a packet is handed to on the way to its destination.

For the exam

  • 1.13: describe switching concepts. 3.2: determine how a router makes a forwarding decision by default.
  • IP addresses do not change from source to destination (unless NAT is in the path). MAC addresses are rewritten at every router.
  • An ARP request is a broadcast; the ARP reply is a unicast.
  • For a remote destination the frame goes to the MAC of the default gateway, not the MAC of the destination host.

Common mistakes

  • Expecting to see a remote host's MAC address in the ARP table. You only ever see devices in your own subnet.
  • Setting a default gateway that is not in the host's own subnet. The host cannot ARP for it, so nothing leaves the LAN.
  • Checking only the outward path. Half of all reachability faults are on the way back.

Quick check

1. PC1 pings a server in another subnet. What is the destination MAC address of the frame PC1 sends?

  1. The server's MAC address
  2. The broadcast address
  3. The MAC address of PC1's default gateway
  4. The MAC address of the switch
Show the answer

C. The MAC address of PC1's default gateway

A host sends off-subnet traffic to its default gateway, so the frame is addressed to the router's MAC. The destination IP inside is still the server.

2. Which statement about ARP is true?

  1. The request is a broadcast and the reply is a unicast
  2. Both request and reply are broadcasts
  3. Routers forward ARP requests between subnets
  4. ARP maps a name to an IP address
Show the answer

A. The request is a broadcast and the reply is a unicast

The asker does not know the MAC, so it broadcasts. The owner answers directly. ARP stays inside one subnet, and name-to-address mapping is DNS.

3. As a packet crosses three routers with no NAT, what changes at each hop?

  1. The source and destination IP addresses
  2. Only the destination IP address
  3. Nothing changes
  4. The source and destination MAC addresses, and the TTL
Show the answer

D. The source and destination MAC addresses, and the TTL

Each router builds a new frame with new MAC addresses and lowers the TTL by one. The IP addresses stay the same end to end.

4. A router's ARP table shows an address as Incomplete. What does that mean?

  1. The entry is about to age out
  2. An ARP request was sent and no reply came back
  3. The address belongs to the router itself
  4. The MAC address was learned from a trunk
Show the answer

B. An ARP request was sent and no reply came back

Incomplete means the router asked and nobody answered. Check that the host is up, is in the right VLAN and has the right address.

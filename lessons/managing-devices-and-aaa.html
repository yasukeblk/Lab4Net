Managing devices and AAA

How you reach devices and who is let in

  • 2.8Device management access
  • 5.8

The problem: getting in, safely

Routers and switches need to be configured and checked, often from far away. Every way in is also a way in for an attacker, and a shared admin password tells you nothing about who used it. Good management access gives administrators a reliable path, keeps their passwords and commands private, and records who changed what.

The ways in

  • Console: a cable plugged straight into the device's console port, usually at 9600 baud. It works with no network and no IP address, so it is the way to recover a device. It needs physical access.
  • Telnet (TCP 23): remote CLI over the network. Everything, including the password, crosses the network in clear text. Avoid it.
  • SSH (TCP 22): remote CLI, encrypted. The standard way in. It needs a hostname, a domain name, an RSA key pair (at least 768 bits for SSH version 2), a username, and transport input ssh with login local on the VTY lines.
  • HTTP (TCP 80) and HTTPS (TCP 443): web management, enabled by ip http server and ip http secure-server. Only HTTPS is encrypted.
  • Cloud managed: devices such as Meraki connect out to a cloud dashboard, and administrators manage them through a browser.

In-band management uses the same network as user traffic. Out-of-band management uses a separate path, such as a console server or a dedicated management network, so the device can still be reached when the main network is broken.

AAA: three questions

AAA answers three separate questions:

  1. Authentication: who are you? A username and password, a certificate or a token.
  2. Authorization: what may you do? For example, read-only access, or only certain commands.
  3. Accounting: what did you do? A record of logins and commands, for audits and troubleshooting.

Local usernames on each device work for a few devices, but every device has its own list to keep up to date. A central AAA server, such as Cisco ISE, holds one set of accounts for all of them, so removing a leaver is one change. It can also give different people different rights: a help desk engineer might be allowed show commands only, while a senior engineer may change the configuration.

TACACS+ and RADIUS

Devices talk to the AAA server with one of two protocols:

  • TACACS+: Cisco-developed, uses TCP 49, encrypts the whole message body, and handles authentication, authorization and accounting separately. That allows per-command authorization, which makes it the usual choice for administrators logging in to network devices.
  • RADIUS: an open standard, uses UDP 1812 for authentication and UDP 1813 for accounting (older servers use 1645 and 1646), encrypts only the password, and combines authentication and authorization. It is the usual choice for network access: 802.1X on switch ports and Wi-Fi, and VPN users.

How it is configured

aaa new-model switches on AAA. From then on, logins follow method lists, ordered lists of where to check credentials. The server is defined by name, for example tacacs server ISE1 with its address ipv4 and shared key (or radius server for RADIUS). Then:

aaa authentication login default group tacacs+ local

This says: ask the TACACS+ servers first; use the local user list only if no server answers. If a server answers and rejects the password, the login fails; the local list is not tried. Keeping local at the end, with a local user configured, means administrators can still get in when the server is down.

Check it worked

Log in over SSH and confirm the server sees the attempt. show aaa servers shows whether each server is up and how many requests it has answered. show ip ssh shows the SSH version, and show ssh lists active sessions. show users lists who is connected on which line.

Key terms

Console port
A physical port for direct CLI access that works without any network.
SSH
Encrypted remote CLI access on TCP 22.
Out-of-band management
Managing devices over a separate path from user traffic.
AAA
Authentication, authorization and accounting.
TACACS+
Cisco AAA protocol on TCP 49; encrypts the whole body; separates the three As.
RADIUS
Open-standard AAA protocol on UDP 1812/1813; encrypts only the password; combines authentication and authorization.
Method list
An ordered list of where a device checks credentials, such as a server group then local users.

For the exam

  • 2.8: describe network device management access (Telnet, SSH, HTTP, HTTPS, console, TACACS+/RADIUS, cloud managed). 5.8: describe authentication, authorization and accounting concepts.
  • Ports: Telnet TCP 23, SSH TCP 22, HTTP TCP 80, HTTPS TCP 443, TACACS+ TCP 49, RADIUS UDP 1812/1813.
  • TACACS+ encrypts the whole payload and separates all three functions; RADIUS encrypts only the password and combines authentication with authorization.
  • TACACS+ suits device administration; RADIUS suits network access such as 802.1X.
  • A method list falls back to the next method only when the previous one gives no answer, not when it rejects the user.

Common mistakes

  • Typing aaa new-model with a server-only method list and no local fallback: if the server is unreachable, nobody can log in remotely.
  • Mismatched shared key between device and AAA server: every login fails, and the server logs show bad requests.
  • Generating RSA keys before setting the hostname and domain name: IOS refuses, because the key is named from them.
  • Leaving transport input telnet ssh on the VTY lines: Telnet still works and passwords cross the network in clear text.

Quick check

1. Which protocol encrypts the entire AAA message body?

  1. RADIUS
  2. TACACS+
  3. Telnet
  4. HTTP
Show the answer

B. TACACS+

TACACS+ encrypts the whole body. RADIUS encrypts only the password field. Telnet and HTTP are management protocols, not AAA protocols, and are unencrypted.

2. A switch port must authenticate users with 802.1X. Which protocol normally carries the request to the AAA server?

  1. TACACS+
  2. SNMP
  3. SSH
  4. RADIUS
Show the answer

D. RADIUS

RADIUS is the standard protocol for network access such as 802.1X and VPN users. TACACS+ is mainly used for administrators logging in to devices.

3. With aaa authentication login default group tacacs+ local, the server answers and rejects the password. What happens?

  1. The local user list is checked next
  2. The login is allowed read-only
  3. The login fails
  4. The device tries RADIUS
Show the answer

C. The login fails

The local method is used only when the server gives no answer. An answer of "rejected" ends the attempt.

4. Which access method still works when the device has no IP address configured?

  1. Console
  2. SSH
  3. HTTPS
  4. Telnet
Show the answer

A. Console

The console is a direct serial connection and needs no network settings. SSH, HTTPS and Telnet all need IP.

5. A company wants a log of every command an administrator ran. Which part of AAA provides it?

  1. Authentication
  2. Authorization
  3. Accounting
  4. Auditing by SNMP
Show the answer

C. Accounting

Accounting records what users did. Authorization decides what they are allowed to do; authentication checks who they are.

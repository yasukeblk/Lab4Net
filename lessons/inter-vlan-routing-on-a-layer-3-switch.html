Inter-VLAN routing on a Layer 3 switch

How a switch routes between VLANs

  • 2.1VLANs and inter-VLAN connectivity
  • 3.3Static routing

The problem: hosts in different VLANs

A VLAN is its own subnet, and a switch alone will not move traffic between VLANs. Something has to route. With router-on-a-stick, one router link carries every VLAN as a trunk, so a packet from VLAN 10 to VLAN 20 crosses that link twice. As traffic grows, that link fills up.

A Layer 3 switch such as DSW1, a Catalyst 3560, can route itself, in hardware, at the same speed it switches.

Turning the switch into a router

On a 3560, routing is off by default. Until ip routing is entered, DSW1 behaves like an ordinary switch, and show ip route only shows a default gateway for its own management traffic.

Once routing is on, DSW1 builds a routing table like any router: connected networks from its interfaces, plus any static routes you add.

SVIs: one gateway per VLAN

A switch virtual interface (SVI) is a Layer 3 interface for a whole VLAN, created with interface vlan 10. It has no physical port of its own. Its address, 192.168.10.1, is the default gateway for every host in VLAN 10, wherever it is plugged in.

PC1 is on DSW1 directly, and PC3 is on ASW1 across the trunk. Both use 192.168.10.1. An SVI comes up when its VLAN exists and at least one port carrying that VLAN is up and forwarding.

What happens to a packet inside DSW1

  1. PC1 sees that PC2, 192.168.20.12, is not in its own subnet, so it sends the frame to its gateway's MAC address: the VLAN 10 SVI.
  2. DSW1 receives the frame in VLAN 10, sees its own MAC as the destination, and looks up 192.168.20.12 in its routing table.
  3. The match is the connected route on the VLAN 20 SVI. DSW1 rewrites the frame with its own MAC as the source and PC2's MAC as the destination, lowers the TTL, and switches it out in VLAN 20.

This is exactly what a router does. The difference is that the switch does it in hardware, on every port at once.

Routed ports for links to routers

The link to R1 does not need a VLAN at all. no switchport on Gi0/2 turns it into a routed port: a plain Layer 3 interface, like a router's, with its own address, 10.0.0.1/30. It belongs to no VLAN and spanning tree does not run on it.

A default route, ip route 0.0.0.0 0.0.0.0 10.0.0.2, then sends everything that is not local to R1. R1 already has a route back to 192.168.0.0/16.

Check it worked

show ip route on DSW1 should list C (connected) routes for 192.168.10.0/24, 192.168.20.0/24 and 10.0.0.0/30, and an S* default route. A trace from PC1 to PC2 shows a single hop, 192.168.10.1: the packet turned around inside DSW1. PC3 reaching 203.0.113.1 proves the SVI works across the trunk and the default route works.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Before ip routing PC1 sends a packet for PC2 to its gateway. Without routing turned on, DSW1 has nowhere to route it, so it is lost.
  2. PC1 reaches its gateway With routing and SVIs in place, PC1 sends the packet to 192.168.10.1, the VLAN 10 SVI on DSW1.
  3. Routed out of VLAN 20 DSW1 finds 192.168.20.0/24 as a connected route on its VLAN 20 SVI and forwards the packet to PC2. The trace shows one hop, and no router was involved.
  4. A host on the access switch PC3 is on ASW1, but its gateway is the same SVI. The frame crosses the trunk tagged VLAN 10 and reaches 192.168.10.1 on DSW1.
  5. Out to the internet 203.0.113.1 is not a local network, so the default route sends it out the routed port Gi0/2 to R1, at 10.0.0.2.

Key terms

Layer 3 switch
A switch that can also route between subnets, in hardware.
SVI
Switch virtual interface. A Layer 3 interface for a VLAN, used as that VLAN's gateway.
Routed port
A switch port turned into a Layer 3 interface with no switchport. It has an address and no VLAN.
ip routing
The command that turns on IPv4 routing on a Layer 3 switch.
Router-on-a-stick
Routing between VLANs with one router link that carries all VLANs as a trunk, using subinterfaces.
Default route
0.0.0.0/0, the route used when nothing more specific matches.

For the exam

  • 2.1: configure and verify VLANs. 3.3: configure and verify IPv4 static routing, including default routes.
  • An SVI is up/up only if its VLAN exists and an active port carries that VLAN.
  • no switchport makes a routed port; interface vlan makes an SVI. Know which fits a link to a router.
  • Compare the three ways to route between VLANs: a router port per VLAN, router-on-a-stick, and a Layer 3 switch.

Common mistakes

  • Forgetting ip routing: the SVIs have addresses and answer pings, but nothing is routed between VLANs.
  • Creating interface vlan 30 for a VLAN that does not exist on the switch: the SVI stays down.
  • Putting the address on Gi0/2 without no switchport: a switch port cannot take an IP address.
  • Hosts with the wrong default gateway: they reach their own VLAN but nothing else.

Quick check

1. On a Layer 3 switch, PC1 and PC2 can each ping their own SVI but not each other. What is most likely missing?

  1. A trunk between the VLANs
  2. ip routing
  3. no switchport on the access ports
  4. A default route
Show the answer

B. ip routing

The SVIs answer, so the addresses and VLANs are fine. Without ip routing the switch will not forward between them. A default route only matters for non-local traffic.

2. Which command makes Gi0/2 a routed port?

  1. switchport mode routed
  2. ip routing
  3. no switchport
  4. interface vlan 2
Show the answer

C. no switchport

no switchport turns the port into a Layer 3 interface. There is no switchport mode routed command.

3. When is an SVI up/up?

  1. As soon as it has an IP address
  2. When ip routing is on
  3. When a trunk is configured on the switch
  4. When its VLAN exists and at least one port carrying it is up
Show the answer

D. When its VLAN exists and at least one port carrying it is up

An SVI depends on its VLAN: the VLAN must exist and an active, forwarding port must carry it. An address alone does not bring it up.

4. Why is a Layer 3 switch better than router-on-a-stick for heavy inter-VLAN traffic?

  1. It routes in hardware and avoids sending every packet across one router link twice
  2. It needs no IP addresses
  3. It removes the need for VLANs
  4. It uses spanning tree to balance load
Show the answer

A. It routes in hardware and avoids sending every packet across one router link twice

With router-on-a-stick, traffic between VLANs goes to the router and back on one link. The Layer 3 switch routes internally, at switching speed.

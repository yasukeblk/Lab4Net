Named ACLs and sequence numbers

How to edit an ACL without retyping it

  • 5.6Access control lists

The problem: changing a list in place

An access control list (ACL) is an ordered list of permit and deny lines that a router checks against packets. R1 applies a standard ACL called SRV-ACCESS outbound on G0/2, the interface toward the file server SRV1. It starts with three lines:

  1. 10 permit 192.168.10.0 0.0.0.255 (staff)
  2. 20 deny 192.168.20.0 0.0.0.255 (contractors)
  3. 30 permit 172.16.0.0 0.0.255.255 (an old VPN range)

Three changes have arrived. With old-style numbered ACLs you would delete the list and type it all again. Named ACLs with sequence numbers let you edit one line at a time.

How an ACL is checked

  1. Lines are checked from the lowest sequence number up.
  2. The first match wins and checking stops.
  3. If nothing matches, the hidden implicit deny at the end drops the packet.

So order is everything. A permit for one host after a deny for its whole subnet is never reached. A standard ACL matches only the source address, which is why it is placed close to the destination, here on G0/2 facing the server.

Named ACLs and sequence numbers

ip access-list standard SRV-ACCESS enters the list's own configuration mode. Each line you add gets a sequence number, 10, 20, 30 by default. Type a number first to choose where a line goes:

  • 15 permit host 192.168.20.50 lands between 10 and 20, so the contractor laptop matches before the contractor deny.
  • 5 deny host 192.168.10.66 lands before 10, so HR's PC is denied before the staff permit.
  • no 30 removes only the VPN line.

A name also says what the list is for, which a number cannot.

Named versus numbered

A numbered ACL is created with global commands such as access-list 10 permit .... Each new line is added at the end, and no access-list 10 removes the whole list, not one line. A named ACL is created with ip access-list standard or ip access-list extended and edited inside its own mode, line by line.

On current IOS a numbered ACL also has sequence numbers, and you can edit it the same way by entering ip access-list standard 10. Names are still preferred because they explain themselves in the configuration.

Resequencing

After a few insertions the numbers are 5, 10, 15, 20, with no room left between some lines. ip access-list resequence SRV-ACCESS 10 10 renumbers from 10 in steps of 10. The order does not change: the list becomes 10 deny HR, 20 permit staff, 30 permit laptop, 40 deny contractors.

Check it worked

show access-lists shows each line with its sequence number and a match counter, so you can see which line a test hit. Test every rule you changed and one you did not: PC1 and LAPTOP should reach 192.168.30.10, HR and CONTR should not. show ip interface g0/2 confirms the list is still applied outbound.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Staff are allowed PC1 (192.168.10.10) pings the server. As the packet leaves G0/2, R1 checks SRV-ACCESS: line 10 matches the staff subnet and permits it.
  2. The laptop is caught by the subnet deny Before the change, 192.168.20.50 matches line 20, the deny for the whole contractor subnet. The first match wins, so it is dropped.
  3. An exception inserted in place 15 permit host 192.168.20.50 sits between 10 and 20. The laptop now matches line 15 before reaching the deny.
  4. HR is blocked before the staff permit HR (192.168.10.66) used to match line 10. Line 5 denies that one host, and it is checked first.
  5. The rest of the subnet is unchanged CONTR (192.168.20.20) does not match line 15, so it still hits the contractor deny. One exception did not open the whole subnet.
  6. Replies are not filtered The ACL is outbound on G0/2. The server's reply enters G0/2 and leaves another interface, so SRV-ACCESS does not check it.

Key terms

ACL
Access control list: an ordered list of permit and deny lines used to filter or select traffic.
Standard ACL
Matches the source address only. Numbers 1 to 99 and 1300 to 1999, or a name.
Extended ACL
Matches source, destination, protocol and ports. Numbers 100 to 199 and 2000 to 2699, or a name.
Sequence number
The number in front of each ACL line that sets its order and lets you insert or delete it.
Implicit deny
The hidden last line of every ACL that drops anything not matched.
Wildcard mask
The inverse of a mask in an ACL: 0 bits must match, 1 bits are ignored. 0.0.0.255 matches a /24.
Resequence
Renumbering an ACL's lines with even gaps, without changing their order.

For the exam

  • 5.6: configure and verify access control lists.
  • Lines are processed top-down by sequence number, first match wins, implicit deny at the end.
  • Standard ACLs match source only and go near the destination; extended ACLs go near the source.
  • host 192.168.20.50 is the same as 192.168.20.50 0.0.0.0.
  • Only one ACL per interface, per direction, per protocol.

Common mistakes

  • Adding the laptop permit at the end: it sits after the contractor deny and is never reached.
  • Typing no access-list 10 to remove one line of a numbered ACL: it deletes the whole list.
  • An ACL with only deny lines: the implicit deny blocks everything else too.
  • Applying the list in the wrong direction: outbound on G0/2 filters traffic toward the server; inbound would check the server's replies instead.
  • Testing only the changed hosts and missing that a new line also caught others.

Quick check

1. SRV-ACCESS has 10 permit 192.168.10.0/24 and 20 deny 192.168.20.0/24. Where must permit host 192.168.20.50 go to work?

  1. After line 20, for example 25
  2. Anywhere, because host entries are always checked first
  3. Between 10 and 20, for example 15
  4. At the end, after the implicit deny
Show the answer

C. Between 10 and 20, for example 15

First match wins. The host permit must come before the subnet deny, or the deny catches the laptop first.

2. In a named ACL, what does no 30 do?

  1. Removes only the line with sequence number 30
  2. Removes the whole ACL
  3. Removes the first 30 lines
  4. Disables the ACL on its interface
Show the answer

A. Removes only the line with sequence number 30

In named ACL mode, no plus a sequence number deletes exactly one line.

3. What does ip access-list resequence SRV-ACCESS 10 10 change?

  1. The order of the lines
  2. The sequence numbers only, keeping the order
  3. The direction the ACL is applied
  4. The match counters
Show the answer

B. The sequence numbers only, keeping the order

Resequencing gives the lines new numbers starting at 10 in steps of 10. The order stays exactly the same.

4. A standard ACL contains only deny host 192.168.10.66. What happens to traffic from 192.168.10.10?

  1. It is permitted, because it does not match
  2. It is permitted only outbound
  3. It is logged and permitted
  4. It is denied by the implicit deny at the end
Show the answer

D. It is denied by the implicit deny at the end

Every ACL ends with an implicit deny. A list with only deny lines blocks everything; add a permit for the rest.

5. Where should a standard ACL usually be placed?

  1. Close to the source
  2. Close to the destination
  3. On every interface
  4. On the switch, not the router
Show the answer

B. Close to the destination

A standard ACL matches only the source, so placing it near the source would block that host from everywhere. Near the destination it blocks only what you intend.

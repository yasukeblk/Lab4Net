SSH remote access

How to log in to a router securely

  • 4.8SSH management
  • 5.3Local device access control

The problem: Telnet sends everything in clear text

R1 accepts Telnet on TCP port 23 with one shared password. Telnet sends everything as plain text, including the password, so anyone who captures traffic on the path can read it. A shared password also means you cannot tell who logged in, and you cannot remove one person without changing it for everyone.

SSH (Secure Shell), on TCP port 22, gives the same command line but encrypts the whole session. Combined with individual usernames, it fixes both problems.

How SSH protects the session

  1. PC1 opens a TCP connection to R1 on port 22.
  2. The two agree on encryption. R1 proves its identity with its RSA key pair: a public key it can share and a private key it keeps.
  3. They build a shared session key, and from then on every byte is encrypted.
  4. Only then does R1 ask for a username and password, so the password crosses the network encrypted.

SSH version 2 is the one to use. Version 1 has known weaknesses.

What the router needs first

  • A hostname other than the default Router, and a domain name (ip domain-name lab.local). The key pair is named after both, as R1.lab.local, so IOS will not generate keys without them.
  • An RSA key pair: crypto key generate rsa modulus 2048. Generating keys is what switches the SSH server on. SSH version 2 needs a modulus of at least 768 bits; 2048 is the sensible size today.
  • A local user: username admin privilege 15 secret S3cure-Pass. secret stores the password as a hash, and privilege 15 puts the user straight into privileged EXEC mode.

Locking the VTY lines

Remote logins arrive on VTY lines (virtual terminal lines), here 0 to 4. Two commands there finish the job:

  • login local makes the lines ask for a username and check it against the local user database.
  • transport input ssh allows only SSH. This is the line that actually closes Telnet; without it, Telnet keeps working.

ip ssh version 2 stops the router accepting version 1.

Other ways in

SSH is not the only way to manage a device. The console port needs a cable plugged into the device itself, so it works even when the network is down; it is the way back in if a remote setting locks you out. Some devices also offer a web page: HTTP is clear text like Telnet, while HTTPS is encrypted like SSH. In larger networks, usernames are kept on a central TACACS+ or RADIUS server instead of on every device, so one account works everywhere and can be removed in one place.

Check it worked

Test both halves. From PC1, ssh -l admin 192.168.1.1 should ask for the password and log in, and telnet 192.168.1.1 should be refused. On R1, show ip ssh shows whether SSH is enabled and which version, and show ssh lists the current SSH sessions.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Before: Telnet in clear text PC1 runs telnet 192.168.1.1. The connection works, and the shared password crosses the link as readable text that anyone capturing traffic could see.
  2. PC1 opens SSH After the change, PC1 runs ssh -l admin 192.168.1.1. It opens a TCP connection to R1 on port 22.
  3. R1 proves who it is R1 sends its public key, from the 2048-bit pair generated as R1.lab.local. The two sides agree on SSH version 2 and build a shared session key.
  4. The login is encrypted Only now does PC1 send the username admin and its password, inside the encrypted session. login local makes R1 check them against its user database.
  5. Logged in The credentials match, and privilege 15 puts admin straight into privileged EXEC mode. Every command and reply is encrypted.
  6. Telnet is now closed PC1 tries telnet 192.168.1.1 again. transport input ssh allows only SSH on the VTY lines, so R1 refuses the connection.

Key terms

Telnet
A remote login protocol on TCP port 23 that sends everything, including passwords, in clear text.
SSH
Secure Shell, an encrypted remote login protocol on TCP port 22.
RSA key pair
A public and private key the router uses to prove its identity and set up encryption.
Modulus
The size of the RSA key in bits. Larger is stronger.
VTY lines
The virtual lines that remote Telnet and SSH sessions connect to.
login local
Line setting that asks for a username and checks it against the local user database.
transport input
Line setting that lists which protocols may connect, such as ssh or telnet.

For the exam

  • 4.8: configure network devices for remote access using SSH. 5.3: configure and verify device access control using local passwords.
  • Ports: SSH is TCP 22, Telnet is TCP 23.
  • The steps in order: hostname, domain name, local user, RSA keys, ip ssh version 2, then login local and transport input ssh on the VTY lines.
  • secret stores a hash; password stores clear text unless service password-encryption is on, which is weak.
  • 2.8 also lists console, HTTP and HTTPS access: console is local, and HTTPS, like SSH, is encrypted.

Common mistakes

  • No domain name: crypto key generate rsa fails, and SSH never starts.
  • login instead of login local: the line asks for the line password, not a username, and the admin account is never used.
  • Forgetting transport input ssh: SSH works, but Telnet still works too.
  • Setting transport input ssh before creating a user: nobody can log in remotely, and you need the console to recover.

Quick check

1. crypto key generate rsa fails with a message about a domain name. What is missing?

  1. ip ssh version 2
  2. ip domain-name
  3. username admin
  4. transport input ssh
Show the answer

B. ip domain-name

The key pair is named hostname.domain, so IOS needs a domain name (and a hostname other than Router) before it will generate keys.

2. SSH works on R1, but Telnet still works too. Which command is missing?

  1. login local
  2. ip ssh version 2
  3. transport input ssh
  4. crypto key generate rsa
Show the answer

C. transport input ssh

transport input ssh limits the VTY lines to SSH. Without it they still accept Telnet.

3. Which TCP ports do SSH and Telnet use?

  1. SSH 22, Telnet 23
  2. SSH 23, Telnet 22
  3. SSH 443, Telnet 23
  4. SSH 22, Telnet 21
Show the answer

A. SSH 22, Telnet 23

SSH is 22 and Telnet is 23. 21 is FTP control and 443 is HTTPS.

4. What does login local on the VTY lines do?

  1. Allows logins only from the local subnet
  2. Uses the enable secret as the login password
  3. Turns on SSH
  4. Asks for a username and checks it against the local user database
Show the answer

D. Asks for a username and checks it against the local user database

login local uses accounts created with username. Plain login would ask for a line password instead, with no username.

5. Why is username admin secret S3cure-Pass better than using password?

  1. secret stores the password as a hash, not as readable text
  2. secret enables SSH automatically
  3. secret gives privilege 15
  4. secret is required for Telnet
Show the answer

A. secret stores the password as a hash, not as readable text

secret stores a hash. password stores clear text unless service password-encryption is on, and that encryption is easily reversed.

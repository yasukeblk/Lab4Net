Dynamic NAT with a pool

How dynamic NAT lends public addresses

  • 4.1Inside-source NAT

The problem: private inside, public outside

PC1 to PC3 use private addresses (192.168.1.11 to .13). Private addresses are not routed on the internet, so before a packet leaves, R1 must replace the source with a public address. That is NAT (Network Address Translation). The ISP has routed a small public block to R1, and the plan is to lend each inside host its own public address from it.

The four NAT address names

NAT names addresses by which side of the router they belong to and from which side you look at them:

  • Inside local: the inside host's real address, 192.168.1.11.
  • Inside global: the public address it appears as, 203.0.113.33.
  • Outside global: the outside host's real address, 198.51.100.10.
  • Outside local: how the outside host appears from inside. Without outside NAT it is the same as outside global.

The parts of dynamic NAT

  1. Inside and outside: ip nat inside on G0/0 and ip nat outside on G0/1 set the direction of translation.
  2. Who is translated: standard ACL 1 permits 192.168.1.0 0.0.0.255. Here the ACL only selects traffic; it does not block anything.
  3. The pool: ip nat pool PUBLIC 203.0.113.33 203.0.113.34 netmask 255.255.255.248. The netmask need not match an interface; it must contain the whole range.
  4. The rule: ip nat inside source list 1 pool PUBLIC ties them together.

How a packet is translated

  1. PC1 sends a packet to 198.51.100.10. It enters R1 on G0/0, a NAT inside interface.
  2. R1 routes it toward G0/1, a NAT outside interface. Because the packet crosses from inside to outside and its source matches ACL 1, R1 looks for an existing translation for 192.168.1.11.
  3. There is none, so R1 takes a free address from the pool, rewrites the source, and records the pair in its translation table.
  4. The reply arrives addressed to 203.0.113.33. The ISP routes the whole public block to R1, so it gets there. R1 finds the entry and rewrites the destination back to 192.168.1.11.

Only one side of the pair is ever seen outside: the web server talks to 203.0.113.33 and nothing else.

One-to-one, and the pool runs dry

Without the word overload, dynamic NAT is one-to-one. The first packet from PC1 borrows 203.0.113.33, PC2 borrows .34, and each keeps its address while its translation lasts (24 hours after last use by default for this kind of entry). PC3 matches the ACL but the pool is empty, so its packets are dropped. Nothing is wrong with PC3; there are simply more hosts than addresses.

The fix: overload the pool

Adding overload turns the rule into PAT (Port Address Translation). Many hosts share one public address, and R1 keeps them apart by the source port number of each connection. All three PCs now share 203.0.113.33.

IOS will not change a NAT rule while translations made by it exist. Clear them with clear ip nat translation *, then replace the rule.

Check it worked

show ip nat translations lists each entry: inside global, inside local, outside local, outside global. With PAT the addresses carry port or ICMP id numbers. show ip nat statistics shows the inside and outside interfaces, hit counts, and the pool line: total addresses, how many are allocated, and misses when a host found the pool empty.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. PC1 borrows an address PC1 pings the web server. Its source 192.168.1.11 matches ACL 1, so R1 takes the first free pool address, 203.0.113.33, and rewrites the source.
  2. Only the public address leaves The web server sees a packet from 203.0.113.33. It never learns the private address.
  3. The reply is translated back The ISP routes the reply to R1. R1 finds 203.0.113.33 in its translation table and rewrites the destination back to 192.168.1.11.
  4. PC2 takes the last address PC2 borrows 203.0.113.34. The pool now has no free addresses.
  5. PC3 is dropped PC3 matches the ACL, but without overload each host needs a whole address and none are left. R1 drops the packet.
  6. Overload shares the address With overload, PC3 shares 203.0.113.33 with the others. R1 tells their traffic apart by port number.

Key terms

NAT
Network Address Translation: rewriting addresses in a packet as it crosses a router.
Inside local
The real address of an inside host, usually private.
Inside global
The public address an inside host appears as on the outside.
NAT pool
A range of public addresses that dynamic NAT may lend.
Dynamic NAT
One-to-one translation using a pool: each host borrows a whole address.
PAT (overload)
Many-to-one translation that tells hosts apart by port number.
Static NAT
A fixed one-to-one mapping, typed in, used for servers reached from outside.

For the exam

  • 4.1: configure and verify inside source NAT using static and pools.
  • Know the four names: inside local, inside global, outside local, outside global.
  • Dynamic NAT without overload is one-to-one; when the pool is used up, new hosts are dropped.
  • overload on a pool or an interface makes it PAT.
  • The ACL in a NAT rule selects traffic for translation; a host the ACL does not match is not translated.

Common mistakes

  • Inside and outside swapped on the interfaces: nothing is translated, or translation runs backwards.
  • Wildcard written as a subnet mask in the ACL (255.255.255.0): it matches the wrong hosts.
  • Pool netmask too small to contain the range: IOS rejects the pool.
  • Trying to change the NAT rule while translations exist: IOS refuses until they are cleared.
  • Blaming PC3 when the pool is simply exhausted: check the allocated count in the statistics.

Quick check

1. A pool has two addresses and the NAT rule has no overload. A third inside host sends traffic. What happens?

  1. It shares the first address
  2. Its packets are dropped until an address is free
  3. It is sent untranslated
  4. R1 asks the ISP for another address
Show the answer

B. Its packets are dropped until an address is free

Dynamic NAT without overload is one-to-one. With the pool used up, new hosts cannot be translated and their packets are dropped.

2. In NAT terms, what is 192.168.1.11 for PC1?

  1. Inside global
  2. Outside local
  3. Inside local
  4. Outside global
Show the answer

C. Inside local

The real address of an inside host is inside local. Its public face, 203.0.113.33, is inside global.

3. What does the ACL in ip nat inside source list 1 pool PUBLIC do?

  1. Selects which inside addresses are translated
  2. Blocks traffic from the outside
  3. Lists the public addresses in the pool
  4. Filters which servers can be reached
Show the answer

A. Selects which inside addresses are translated

In a NAT rule the ACL only chooses traffic to translate. Traffic it does not permit is simply not translated.

4. You try to add overload to the NAT rule and IOS refuses. What do you do first?

  1. Delete the pool
  2. Shut G0/1
  3. Remove ip nat inside
  4. Clear the translations with clear ip nat translation *
Show the answer

D. Clear the translations with clear ip nat translation *

IOS will not change a rule that has active translations. Clear them, then replace the rule.

Passwords, MFA and VPNs

How logins and VPNs keep access private

  • 5.4
  • 5.5

The problem: passwords alone are weak

A password is only something you know, and anything known can be guessed, phished, reused from another breached site or read off a sticky note. A security policy sets rules that make passwords harder to break, and adds other proofs of identity where passwords are not enough. Separately, data crossing the internet needs protecting, which is what VPNs do.

Password policy

A password policy usually covers:

  • Length and complexity: a minimum length, and a mix of character types. Length adds more strength than complexity; a long passphrase beats a short jumble.
  • Management: no sharing, no reuse across systems, changes when a password may be exposed, and history so old passwords cannot be reused.
  • Lockout: blocking logins after several failures, which defeats online guessing.

On Cisco IOS, security passwords min-length enforces a minimum length, and login block-for stops logins for a time after repeated failures. enable secret stores a hash rather than the password. service password-encryption only applies weak, reversible type 7 encoding, which stops shoulder surfing, not attackers.

Rules that are too strict backfire. Forcing a new complex password every month leads people to write passwords down or add a number to the old one. That is why many policies now favour long passphrases, changed when there is reason to think they leaked, together with MFA.

MFA, certificates and biometrics

Multifactor authentication (MFA) requires proofs from two or more different factors:

  1. Something you know: a password or PIN.
  2. Something you have: a phone with an authenticator app, a hardware token or a smart card.
  3. Something you are: a fingerprint or face, called biometrics.

Two passwords are still one factor. A stolen password alone is no longer enough when MFA is used.

Digital certificates prove identity with public key cryptography. A trusted certificate authority (CA) signs a certificate that binds a name to a public key. The owner keeps the matching private key secret and proves identity by using it. Certificates identify websites in HTTPS, devices in 802.1X and peers in VPNs. Because the private key never leaves its owner, there is nothing for a user to type and nothing to phish.

Biometrics are convenient, but a fingerprint cannot be changed if it is ever copied, so they are usually one factor among several rather than the only one.

VPNs: a private tunnel over a public network

A VPN (virtual private network) carries private traffic across the internet inside an encrypted tunnel. It gives confidentiality (encryption, such as AES), integrity (a hash such as SHA shows nothing changed), authentication (each end proves who it is with a pre-shared key or certificate) and anti-replay (old packets cannot be resent).

IPsec is the standard framework for this. IKE (on UDP 500, or UDP 4500 when NAT is in the path) negotiates the keys. ESP (IP protocol 50) then encrypts and authenticates the traffic; AH (IP protocol 51) authenticates but does not encrypt, so ESP is what is normally used. In tunnel mode the whole original packet is encrypted and a new IP header is added; transport mode protects only the payload.

Site-to-site and remote access

  • Site-to-site VPN: two routers or firewalls, one at each office, build a permanent tunnel. Hosts send ordinary traffic; the devices at the edge encrypt it. Users need no VPN software and do not know it is there. Plain IPsec does not carry multicast, so routing protocols are often run through GRE over IPsec, and DMVPN builds tunnels between many branches on demand.
  • Remote access VPN: one user's device builds a tunnel to the company firewall when needed, using client software such as Cisco Secure Client (formerly AnyConnect). These usually use TLS, the protocol behind HTTPS, though IPsec is also used. A clientless VPN runs inside a web browser for limited access.

Key terms

MFA
Multifactor authentication: proofs from at least two of know, have and are.
Biometrics
Authentication by a physical trait, such as a fingerprint or face.
Digital certificate
A CA-signed document that binds an identity to a public key.
IPsec
A framework of protocols that secure IP traffic with encryption, integrity and authentication.
ESP
IPsec protocol (IP protocol 50) that encrypts and authenticates packets.
IKE
The protocol that negotiates IPsec keys, on UDP 500 (UDP 4500 through NAT).
Site-to-site VPN
A permanent tunnel between two networks, built by edge devices.
Remote access VPN
An on-demand tunnel from one user's device to the company network, usually with TLS.

For the exam

  • 5.4: describe security password policy elements, such as management, complexity and password alternatives (multifactor authentication, certificates and biometrics). 5.5: describe IPsec remote access and site-to-site VPNs.
  • The three factors: know, have, are. Two passwords are not MFA.
  • Site-to-site: always on, built by routers or firewalls, invisible to users. Remote access: on demand, built by client software, usually TLS.
  • ESP encrypts (protocol 50); AH does not encrypt (protocol 51); IKE uses UDP 500.
  • GRE over IPsec carries multicast and routing protocols that plain IPsec cannot.

Common mistakes

  • Relying on service password-encryption: type 7 passwords can be reversed in seconds. Use enable secret and username ... secret.
  • Counting a password plus a security question as MFA: both are things you know.
  • Expecting OSPF to run across a plain IPsec site-to-site tunnel: plain IPsec does not carry multicast, so neighbours never form; GRE over IPsec fixes it.
  • Choosing AH for confidentiality: it authenticates but sends the data unencrypted.

Quick check

1. A user logs in with a password and then a code from a phone app. Which factors are used?

  1. Something you know and something you have
  2. Something you know and something you are
  3. Two things you know
  4. Something you have and something you are
Show the answer

A. Something you know and something you have

The password is something you know; the phone that generates the code is something you have. Two different factors make it MFA.

2. Which VPN type needs no software on users' computers?

  1. Remote access with a VPN client
  2. Site-to-site
  3. Remote access with TLS
  4. Clientless browser VPN
Show the answer

B. Site-to-site

In a site-to-site VPN the edge routers or firewalls encrypt traffic, so hosts just send normal packets. A clientless VPN still needs the user to open it in a browser.

3. Which IPsec protocol provides encryption?

  1. AH
  2. IKE
  3. GRE
  4. ESP
Show the answer

D. ESP

ESP encrypts and authenticates. AH only authenticates. IKE negotiates keys, and GRE is a tunnel with no encryption at all.

4. Two offices need OSPF to run between them over the internet, encrypted. What fits?

  1. Plain IPsec tunnel mode
  2. AH in transport mode
  3. GRE over IPsec
  4. A clientless TLS VPN
Show the answer

C. GRE over IPsec

Plain IPsec does not carry multicast, so OSPF hellos would not cross it. GRE carries them, and IPsec encrypts the GRE tunnel.

5. What does service password-encryption do?

  1. Hashes passwords with a strong algorithm
  2. Applies weak, reversible type 7 encoding to plain-text passwords
  3. Encrypts SSH sessions
  4. Enforces a minimum password length
Show the answer

B. Applies weak, reversible type 7 encoding to plain-text passwords

Type 7 encoding only hides passwords from casual view; tools reverse it instantly. enable secret stores a real hash.

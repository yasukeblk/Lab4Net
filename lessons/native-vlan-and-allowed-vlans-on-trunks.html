Native VLAN and allowed VLANs on trunks

How trunks carry VLANs, tagged and untagged

  • 2.2Trunks and 802.1Q

The problem: a default trunk

A VLAN splits one switch into separate Layer 2 networks. A trunk is a link that carries several VLANs at once, usually between switches. Here SW1 Gi0/1 to SW2 Gi0/1 is the trunk, and it carries STAFF (VLAN 10) and BENCH (VLAN 30).

Out of the box a trunk works, but two defaults are weak. It carries every VLAN, and its native VLAN is VLAN 1. This lab changes both: native VLAN 99, and only VLANs 10 and 99 allowed.

How 802.1Q tags frames

When a frame crosses a trunk, the receiving switch must know which VLAN it belongs to. IEEE 802.1Q solves this by inserting a 4-byte tag into the Ethernet frame. The tag holds a 12-bit VLAN ID, so VLANs 1 to 4094 are usable.

  1. PC1 sends a normal, untagged frame into SW1 Fa0/1, an access port in VLAN 10.
  2. SW1 adds a tag saying VLAN 10 and sends it over Gi0/1.
  3. SW2 reads the tag, removes it and delivers the frame only to VLAN 10 ports, such as PC2's.

The PCs never see a tag. Only trunks carry them.

The native VLAN: the one sent untagged

One VLAN on each trunk is sent without a tag. That is the native VLAN. A frame that arrives on a trunk with no tag is placed into the receiving switch's own native VLAN.

That has two consequences:

  • Both ends must agree. Each switch only knows its own setting. If SW1 uses 99 and SW2 still uses 1, untagged frames leave SW1 in VLAN 99 and arrive in VLAN 1 on SW2: two VLANs are silently joined. CDP notices and logs a native VLAN mismatch. You will see that message between configuring SW1 and SW2.
  • Use an unused VLAN. In a VLAN hopping attack by double tagging, an attacker in the native VLAN sends a frame with two tags. The first switch strips the outer tag (it matches the native VLAN) and forwards the frame with the inner tag into another VLAN. If no host is in the native VLAN, nobody can start this attack. That is why VLAN 99 is named NATIVE and has no ports.

The allowed VLAN list

By default a trunk carries all VLANs. switchport trunk allowed vlan 10,99 replaces that list. VLAN 30 frames are then never sent across Gi0/1, so the two BENCH ports become two isolated islands: PC3 can no longer reach PC4.

Pruning the list also keeps broadcasts for unneeded VLANs off the link. Keep the native VLAN in the list. Be careful with the keyword: allowed vlan 30 on its own replaces the list, while allowed vlan add 30 adds to it.

Check it worked

show interfaces trunk has the answers in separate blocks: the trunk's mode and native VLAN, the VLANs allowed on the trunk, and the VLANs allowed and active. Check both switches, because each shows only its own side. Then test what must still work (PC1 to PC2) and what must now fail (PC3 to PC4).

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. An access port receives a frame PC1 sends a normal Ethernet frame to PC2. SW1 Fa0/1 is an access port in VLAN 10, so SW1 knows the frame belongs to STAFF.
  2. Tagged across the trunk SW1 inserts an 802.1Q tag with VLAN ID 10 and sends the frame over Gi0/1. SW2 reads the tag to learn which VLAN it belongs to.
  3. Tag removed at the far side SW2 removes the tag and delivers the frame out of Fa0/1, a VLAN 10 access port. PC2 never sees the tag.
  4. Only one end changed SW1 now sends VLAN 99 traffic untagged, but SW2 still puts untagged frames into VLAN 1. CDP sees the two ends disagree and logs a native VLAN mismatch.
  5. Both ends agree With native VLAN 99 on SW2 too, untagged frames stay in VLAN 99 at both ends and the mismatch message stops.
  6. BENCH stays on its own switch PC3 pings PC4. VLAN 30 is not in the trunk's allowed list, so SW1 never sends the frame across Gi0/1. The bench VLAN on each floor is now isolated.

Key terms

Trunk
A switch link that carries frames for several VLANs, telling them apart with tags.
802.1Q
The IEEE standard for VLAN tagging. It inserts a 4-byte tag with a 12-bit VLAN ID.
Native VLAN
The one VLAN on a trunk whose frames are sent untagged. VLAN 1 by default.
Native VLAN mismatch
The two ends of a trunk use different native VLANs, so untagged traffic leaks between VLANs. CDP reports it.
Allowed VLAN list
The VLANs a trunk will carry. All VLANs by default.
Double tagging
A VLAN hopping attack that uses two 802.1Q tags to push a frame from the native VLAN into another VLAN.
Access port
A port in one VLAN that sends and receives untagged frames, used for end devices.

For the exam

  • 2.2: configure and verify interswitch connectivity: trunk ports, 802.1Q, native VLAN.
  • The native VLAN is untagged; every other VLAN on the trunk is tagged.
  • The default native VLAN is 1, and by default a trunk allows all VLANs.
  • allowed vlan replaces the list; allowed vlan add and remove change it.
  • Best practice: native VLAN set to an unused VLAN, the same on both ends.

Common mistakes

  • Changing the native VLAN on one end only: CDP logs a native VLAN mismatch and untagged traffic lands in the wrong VLAN.
  • Typing switchport trunk allowed vlan 30 to add one VLAN: it replaces the list and every other VLAN stops crossing the trunk.
  • Putting hosts in the native VLAN: they become a starting point for double-tagging attacks.
  • Forgetting to create the VLAN on both switches, so traffic for it has nowhere to go on the far side.

Quick check

1. On an 802.1Q trunk, which frames cross without a tag?

  1. Frames in the native VLAN
  2. Frames in VLAN 1, whatever the native VLAN is
  3. Frames in every VLAN except the native VLAN
  4. Only CDP and STP frames
Show the answer

A. Frames in the native VLAN

Only the native VLAN is sent untagged. It is VLAN 1 by default, but once you change it to 99, VLAN 99 is the untagged one.

2. SW1 uses native VLAN 99 and SW2 still uses VLAN 1. What happens?

  1. The trunk shuts down until they match
  2. Untagged frames from SW1 land in VLAN 1 on SW2, and CDP logs a mismatch
  3. SW2 automatically changes to VLAN 99
  4. Nothing, because the native VLAN only matters locally
Show the answer

B. Untagged frames from SW1 land in VLAN 1 on SW2, and CDP logs a mismatch

Each switch puts untagged frames into its own native VLAN, so the two VLANs are joined. CDP spots the disagreement and logs it; the trunk itself stays up.

3. A trunk allows VLANs 10 and 99. An engineer types switchport trunk allowed vlan 30. What is allowed now?

  1. 10, 30 and 99
  2. 10 and 99, because 30 was rejected
  3. All VLANs
  4. Only 30
Show the answer

D. Only 30

Without add, the command replaces the whole list. switchport trunk allowed vlan add 30 would have kept 10 and 99.

4. Why should the native VLAN be one that no host uses?

  1. It makes the trunk faster
  2. Cisco switches refuse a native VLAN that has hosts
  3. It limits double-tagging attacks, which start from the native VLAN
  4. It stops CDP running on the trunk
Show the answer

C. It limits double-tagging attacks, which start from the native VLAN

A double-tagged frame only works if the attacker is in the native VLAN. With no hosts there, nobody can start the attack.

5. Which command shows a trunk's native VLAN and its allowed VLANs together?

  1. show vlan brief
  2. show interfaces trunk
  3. show mac address-table
  4. show cdp neighbors
Show the answer

B. show interfaces trunk

show interfaces trunk lists mode, native VLAN, allowed VLANs and active VLANs per trunk. show vlan brief lists access ports, not trunks.

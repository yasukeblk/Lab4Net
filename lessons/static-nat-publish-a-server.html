Static NAT: publish a server

How an outside client reaches an inside server

  • 4.1Inside-source NAT

The problem: an inside server nobody outside can reach

WEB has the private address 192.168.1.10. Internet routers do not route private addresses, so CLIENT (198.51.100.10) has no way to send anything to it.

With PAT, inside hosts can start connections out, but an outside host cannot start one in: there is no translation until an inside host creates it. A server must be reachable at any time, at an address that never changes. Static NAT gives it one: a permanent one-to-one mapping between the private address and a public address.

The addresses in this lab

  • Inside local 192.168.1.10: WEB's real address.
  • Inside global 203.0.113.10: the public address that represents WEB. This is what CLIENT connects to.
  • Outside global 198.51.100.10: CLIENT's real address.

The ISP already routes the public block that includes 203.0.113.10 to R1, so packets for the published address arrive at R1 G0/1.

How a static mapping works

  1. A packet for 203.0.113.10 arrives on G0/1, marked ip nat outside.
  2. R1 finds the static entry and rewrites the destination to 192.168.1.10, then routes it out G0/0 to WEB.
  3. WEB replies from 192.168.1.10. As the reply crosses from inside to outside, R1 rewrites the source back to 203.0.113.10.

CLIENT only ever sees 203.0.113.10. The mapping also works the other way: if WEB starts a connection out, it leaves as 203.0.113.10.

Static NAT compared with PAT

PAT creates entries only when inside hosts send traffic, and shares one address among many hosts by port. Static NAT is one address for one host, every port, all the time. Its entry is in the NAT table as soon as you type the command, before any traffic flows. That is the main thing to notice in this lab.

NAT is not a firewall. Static NAT publishes every port of WEB, not just port 80. Limiting what outsiders may reach is a job for an ACL.

The cost is addresses. Each published server uses up one public address for itself, and public addresses are scarce and paid for. That is why offices publish only the few servers that must be reached from outside, and let every other host share an address with PAT.

How it is configured here

R1 needs ip route 0.0.0.0 0.0.0.0 203.0.113.1 so replies can reach CLIENT, because translating an address does not create a route. Then G0/0 gets ip nat inside and G0/1 gets ip nat outside. One line creates the mapping: ip nat inside source static 192.168.1.10 203.0.113.10, inside local first, inside global second.

Check it worked

Run show ip nat translations before sending anything. The static entry is already there, with inside global 203.0.113.10 and inside local 192.168.1.10, and dashes for the outside columns. Then from CLIENT ping 203.0.113.10 and try telnet 203.0.113.10 80. Look at the table again: entries for the live connections appear next to the static one, with ports and CLIENT's address filled in.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. The mapping exists first As soon as the static command is entered, show ip nat translations lists 203.0.113.10 to 192.168.1.10. No traffic has been sent yet, unlike PAT.
  2. CLIENT connects to the public address CLIENT opens a connection to 203.0.113.10 port 80. The ISP routes the published block to R1, so the packet arrives on G0/1, the outside interface.
  3. R1 translates the destination R1 matches the static entry and rewrites the destination to 192.168.1.10, then forwards out G0/0. WEB sees a request from 198.51.100.10.
  4. R1 translates the reply WEB replies from 192.168.1.10. Crossing from inside to outside, R1 rewrites the source to 203.0.113.10 and uses its default route toward the ISP.
  5. CLIENT gets its answer The reply arrives from 203.0.113.10, the address CLIENT connected to. CLIENT never learns the private address behind it.

Key terms

Static NAT
A permanent one-to-one mapping between an inside local and an inside global address.
Inside local
The real private address of the inside host, here 192.168.1.10.
Inside global
The public address that represents the inside host, here 203.0.113.10.
Outside global
The real address of the outside host, here 198.51.100.10.
Publishing a server
Making an inside server reachable from outside at a fixed public address.
NAT inside / outside
Interface labels that tell the router which side of the translation each interface is on.

For the exam

  • 4.1: configure and verify inside source NAT using static and pools.
  • ip nat inside source static takes the inside local address first and the inside global second.
  • A static entry shows in show ip nat translations before any traffic; dynamic and PAT entries only appear when traffic flows.
  • Static NAT is one to one and lets outside hosts start connections in; PAT is many to one and does not.
  • For traffic coming in, static NAT translates the destination; for replies going out, it translates the source.

Common mistakes

  • Addresses in the wrong order in the static command: R1 maps the public address as if it were the inside host, and nothing works.
  • Inside and outside labels swapped: the packet arrives but is never translated, so WEB never sees it.
  • No default route on R1: CLIENT's request reaches WEB but the reply has no route back out.
  • Assuming static NAT protects the server: every port on WEB is reachable from outside unless an ACL restricts it.

Quick check

1. Which command publishes WEB at 203.0.113.10?

  1. ip nat inside source static 203.0.113.10 192.168.1.10
  2. ip nat outside source static 192.168.1.10 203.0.113.10
  3. ip nat inside source list 1 interface g0/1 overload
  4. ip nat inside source static 192.168.1.10 203.0.113.10
Show the answer

D. ip nat inside source static 192.168.1.10 203.0.113.10

Inside local comes first and inside global second. The overload line is PAT, which does not let outside hosts start connections to a fixed address.

2. Before any traffic, what does show ip nat translations show in this lab?

  1. Nothing, because entries appear only when traffic flows
  2. The static entry for 203.0.113.10 and 192.168.1.10
  3. An entry for CLIENT
  4. An error, because no traffic has been translated
Show the answer

B. The static entry for 203.0.113.10 and 192.168.1.10

Static entries exist from the moment they are configured. It is PAT and dynamic NAT entries that appear only with traffic.

3. When CLIENT's request crosses R1 toward WEB, which address does R1 change?

  1. The destination, from 203.0.113.10 to 192.168.1.10
  2. The source, from 198.51.100.10 to 203.0.113.10
  3. Both source and destination
  4. Neither; static NAT only changes replies
Show the answer

A. The destination, from 203.0.113.10 to 192.168.1.10

Traffic coming in is addressed to the public address, so R1 rewrites the destination. On the reply it rewrites the source back.

4. Why does R1 still need a default route after the static mapping is added?

  1. The static mapping needs a route to be activated
  2. The ISP uses it to reach 203.0.113.10
  3. Translation does not create routes, so replies to 198.51.100.10 need a path out
  4. It is needed for the inside label to work
Show the answer

C. Translation does not create routes, so replies to 198.51.100.10 need a path out

NAT changes addresses; routing still decides where packets go. Without a route to CLIENT's network, R1 cannot send the reply.

5. Which statement about static NAT is true?

  1. It shares one public address among many hosts by port
  2. It only allows port 80
  3. It filters traffic, so an ACL is not needed
  4. It lets outside hosts start connections to the inside host
Show the answer

D. It lets outside hosts start connections to the inside host

A permanent one-to-one mapping means outsiders can reach the server at any time. It does not filter: every port is published unless an ACL limits it.

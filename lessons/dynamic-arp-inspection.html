Dynamic ARP Inspection

How a switch stops ARP lies

  • 5.7Layer 2 security

The problem: ARP believes anyone

ARP (Address Resolution Protocol) finds the MAC address for an IPv4 address on the local subnet. A host broadcasts "who has 192.168.10.1?" and the owner replies with its MAC.

ARP has no checks. Any host can send a reply, even unasked, saying "192.168.10.1 is at my MAC". Other hosts update their ARP cache and send their gateway traffic to the liar. This is ARP spoofing (or ARP poisoning), and it is how a man-in-the-middle attack starts.

What an attack looks like

  1. The attacker sends PC1 an ARP reply: "192.168.10.1 is at my MAC".
  2. PC1 overwrites its ARP cache entry for the gateway.
  3. The attacker sends R1 a matching lie: "PC1's address is at my MAC".
  4. Traffic between PC1 and the gateway now passes through the attacker, who can read or change it and pass it on. Neither side notices.

The switch forwards these frames normally, because each one is a valid frame to a valid MAC. Port security does not stop it either. Only a check of what the ARP says catches the lie.

How DAI checks ARP

Dynamic ARP Inspection (DAI) makes the switch read every ARP message that enters an untrusted port in the chosen VLANs. It compares the sender's IP and MAC with the DHCP snooping binding table. If the pair is listed for that port, the ARP passes. If not, it is dropped and logged.

PC1 and PC2 got their addresses by DHCP, so they are in the table and pass. ATTACKER set 192.168.10.99 by hand and never got a lease, so its ARPs are dropped. It cannot reach the gateway, and it cannot claim anyone else's address.

Trusted ports

As with snooping, every port is untrusted by default. R1's address is set by hand, so R1 is not in the binding table either. Once DAI is on, R1's ARP replies arriving on Gi0/1 are dropped and nobody can reach the gateway.

The fix is ip arp inspection trust on Gi0/1. Trust ports toward routers and other switches. Check only edge ports, where users plug in.

Devices with fixed addresses

The printer is legitimate, but with a fixed address it has no lease, so DAI drops it too. A static binding adds it to the table by hand: ip source binding, with its MAC, VLAN 10, 192.168.10.5 and port Fa0/3. IOS writes MAC addresses as three dotted groups, such as 00e0.b08e.1310. An ARP ACL is another way to allow fixed hosts.

Turning it on and checking it

DAI depends on DHCP snooping, which is already running in this lab. Turn DAI on with ip arp inspection vlan 10. show ip arp inspection shows counters of ARPs forwarded and dropped per VLAN. DAI also limits untrusted ports to 15 ARP packets per second by default; a port that goes over is error-disabled. After testing from ATTACKER, its ARPs should show in the drop counter.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. The attacker is checked ATTACKER sends an ARP from 192.168.10.99. DAI finds no binding for that address on Fa0/6, so SW1 drops it. Spoofed replies claiming .1 are dropped the same way.
  2. PC1 asks for the gateway PC1's ARP request matches its lease in the binding table, so it passes and reaches R1.
  3. The gateway is dropped R1's reply enters on Gi0/1, which is untrusted. R1 has no lease, so DAI drops its reply and PC1 cannot reach the gateway.
  4. Uplink trusted With Gi0/1 trusted, R1's ARP replies are not checked. PC1 learns the gateway MAC and its pings work.
  5. The printer is back The static binding lists 192.168.10.5 with the printer's MAC on Fa0/3. Its ARP now matches and passes.

Key terms

ARP
Address Resolution Protocol. Maps an IPv4 address to a MAC address on the local subnet.
ARP spoofing
Sending false ARP replies so other hosts send traffic to the attacker's MAC.
Dynamic ARP Inspection
A switch feature that drops ARP messages whose IP and MAC do not match a known binding.
Trusted port (DAI)
A port whose ARP messages are not checked. Used toward routers and switches.
Static source binding
A hand-made entry in the binding table for a host with a fixed address.
Error-disabled
A port the switch has shut down because of a violation, such as too many ARPs.

For the exam

  • 5.7: configure and verify Layer 2 security features: DHCP snooping, dynamic ARP inspection, and port security.
  • DAI checks ARP against the DHCP snooping binding table, so it relies on snooping.
  • Only untrusted ports are checked. All ports start untrusted.
  • Default rate limit on untrusted ports: 15 ARP packets per second, then err-disable.
  • Hosts with static addresses need a static binding or an ARP ACL.

Common mistakes

  • Not trusting the uplink: the router's ARP replies are dropped and the whole VLAN loses its gateway.
  • Forgetting fixed-address devices: printers and servers stop working the moment DAI is on.
  • Turning on DAI in a VLAN without DHCP snooping bindings: every untrusted host is dropped.
  • Typing the MAC with dashes, as Windows shows it: IOS wants dotted groups.

Quick check

1. What does DAI compare an ARP message against?

  1. The MAC address table
  2. The DHCP snooping binding table
  3. The routing table
  4. The ARP cache of the gateway
Show the answer

B. The DHCP snooping binding table

DAI checks the sender IP and MAC against the snooping bindings for that port. The MAC address table has no IP addresses.

2. After DAI is turned on, no PC can reach the gateway. What is the most likely cause?

  1. DHCP snooping is off on Fa0/1
  2. The PCs have no static bindings
  3. The uplink to the router is not trusted for DAI
  4. The rate limit is too high
Show the answer

C. The uplink to the router is not trusted for DAI

The router's address is not leased, so its ARP replies are dropped on an untrusted uplink. Trusting the uplink fixes it.

3. A printer with a fixed address stops working once DAI is on. Which fix keeps the protection on?

  1. Trust the printer's port
  2. Turn off DAI for VLAN 10
  3. Give the printer a DHCP reservation on another VLAN
  4. Add a static source binding for the printer
Show the answer

D. Add a static source binding for the printer

A static binding allows only the printer's own IP and MAC on that port. Trusting the port would let anything through it.

4. What happens by default when an untrusted port sends more than 15 ARP packets per second?

  1. The port is error-disabled
  2. The extra ARPs are queued
  3. The port becomes trusted
  4. Nothing; there is no default limit
Show the answer

A. The port is error-disabled

DAI rate-limits untrusted ports to 15 packets per second by default, and a port over the limit is error-disabled.

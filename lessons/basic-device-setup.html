Basic device setup

How to give a device a safe starting point

  • 1.6IPv4 addressing and subnetting
  • 5.3Local device access control

Why a baseline matters

A router or switch out of the box is called Router or Switch, has no passwords, and (on a router) every interface is shut down. Anyone who plugs a cable into the console port gets full control.

A baseline is the small set of settings every device gets before it does real work: a name, passwords, a warning banner, an address for management, and a saved configuration. In this lab R1 becomes HQ-R1 and SW1 becomes ACCESS-SW1.

Modes, and where the configuration lives

The Cisco command line has levels. User EXEC (prompt >) can only look at a few things. enable moves to privileged EXEC (#), which can see everything and reload the device. configure terminal enters global configuration, and from there you enter sub-modes for an interface or a line.

Every change goes into the running-config, held in RAM. The device boots from the startup-config, held in NVRAM (memory that survives power loss). Until you run copy running-config startup-config, a reload throws your work away.

Locking the doors

  • enable secret protects privileged mode and stores the password as a hash. The older enable password is stored in clear text. If both exist, the secret is used.
  • The console line is the physical port. The VTY lines (virtual terminal, 0 to 4 here, so five sessions at once) are where Telnet and SSH sessions arrive. Each line needs a password, and login tells the line to actually ask for it.
  • banner motd shows a message before the login prompt: the legal notice that access is restricted.
  • no ip domain-lookup stops the router treating a typo as a hostname and stalling while it tries to resolve it.

Addresses: router port versus switch

A router interface is a Layer 3 port: it gets its own IP address. R1 G0/0 gets 192.168.1.1/24, which makes it the default gateway for PC1. Router interfaces start shut down, so no shutdown is required.

Switch ports are Layer 2: they forward frames and have no addresses. To manage SW1 over the network, you give an address to a virtual interface, the SVI (switch virtual interface) interface vlan 1, here 192.168.1.2/24, and bring it up. The switch does not route, so it also needs ip default-gateway 192.168.1.1 to reply to anyone outside its own subnet.

Check it worked

show ip interface brief lists every interface with its address and two columns: Status (Layer 1) and Protocol (Layer 2). You want up up. administratively down means the interface is still shut down. show running-config shows what is active, and show startup-config shows what will survive a reload. Finally, a ping from PC1 to 192.168.1.1 and 192.168.1.2 proves the cabling, addressing and interfaces work end to end.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Finding the router PC1 wants to ping 192.168.1.1, which is in its own subnet. It first broadcasts an ARP request asking which MAC address owns that IP. SW1 floods it and it reaches R1 G0/0.
  2. R1 answers R1 answers only because G0/0 has an address and is no longer shut down. PC1 now knows the MAC address to put on its frames.
  3. Echo request PC1 sends an ICMP echo request to 192.168.1.1. SW1 forwards it straight to the port where it learned R1.
  4. Echo reply R1 replies. The ping proves Layers 1 to 3 work between PC1 and its default gateway.
  5. Pinging the switch A ping to 192.168.1.2 is answered by the switch itself, through its VLAN 1 SVI. Without that address the switch forwards frames but cannot be reached for management.
  6. Remote login A remote session to R1 lands on a VTY line. R1 shows the MOTD banner and asks for the VTY password, because the line has login.

Key terms

Running-config
The active configuration, held in RAM. Lost on reload unless saved.
Startup-config
The saved configuration in NVRAM that the device loads when it boots.
Privileged EXEC
The # mode, reached with enable, where everything can be viewed and changed.
enable secret
The password for privileged mode, stored as a hash.
Console line
The physical management port, used with a console cable.
VTY lines
Virtual terminal lines that accept remote Telnet or SSH sessions.
SVI
Switch virtual interface: a logical interface for a VLAN, used here to give the switch a management address.
MOTD banner
A message of the day shown before login, usually a legal warning.

For the exam

  • 5.3: configure and verify device access control using local passwords. 1.6: configure and verify IPv4 addressing and subnetting.
  • enable secret is hashed and overrides enable password. service password-encryption only applies weak, reversible encryption to the other passwords.
  • A line password has no effect without login (or login local for usernames).
  • A Layer 2 switch takes its management address on an SVI and needs ip default-gateway, not a routing table.
  • Know the prompts: >, #, (config)#, (config-if)#, (config-line)#.

Common mistakes

  • Forgetting no shutdown on the router interface: show ip interface brief shows administratively down and nothing can ping it.
  • Setting a line password without login: the console still opens with no prompt.
  • No default gateway on the switch: it answers pings from its own subnet but not from anywhere else.
  • Not saving: everything works until the next reload, then the device is back to factory settings.

Quick check

1. A router has both enable password and enable secret configured. Which one unlocks privileged mode?

  1. Either one works
  2. enable password, because it was configured first
  3. enable secret
  4. Neither, until one is removed
Show the answer

C. enable secret

When both exist, IOS uses enable secret. It is also the one to use, because it is stored as a hash rather than clear text.

2. You set password conpass under line console 0 but forget login. What happens at the console?

  1. It asks for conpass
  2. It opens with no password prompt
  3. It asks for the enable secret instead
  4. It refuses all access
Show the answer

B. It opens with no password prompt

The password is stored but the line is never told to ask for it. login turns the check on.

3. PC1 can ping SW1 at 192.168.1.2, but a PC in another subnet cannot. Routing on R1 is fine. What is SW1 most likely missing?

  1. A hostname
  2. An enable secret
  3. no shutdown on Fa0/1
  4. ip default-gateway
Show the answer

D. ip default-gateway

The switch receives the ping but has no gateway to send its reply through, so it can only answer hosts in its own subnet.

4. After a power cut R1 is back to its factory settings. What was skipped?

  1. copy running-config startup-config
  2. no ip domain-lookup
  3. banner motd
  4. line vty 0 4
Show the answer

A. copy running-config startup-config

Changes live in RAM until saved to NVRAM. The startup-config is what the router loads at boot.

5. show ip interface brief shows G0/0 as administratively down. What fixes it?

  1. Add an IP address
  2. Replace the cable
  3. no shutdown on the interface
  4. Save the configuration
Show the answer

C. no shutdown on the interface

Administratively down means someone (or the factory default) shut the interface. A cable fault would show down, not administratively down.

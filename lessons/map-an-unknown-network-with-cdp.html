Map an unknown network with CDP

How to discover what is plugged in where

  • 2.3CDP and LLDP

The problem: no documentation

You have inherited five devices with no notes. You know their names, EDGE, CORE, ACC-A, ACC-B and the provider's ISP-PE, but not which port connects to which. Tracing cables by hand is slow. The devices can tell you themselves.

How CDP works

CDP (Cisco Discovery Protocol) is a Cisco protocol that runs at Layer 2. Each device sends a short advertisement out of every CDP-enabled port, every 60 seconds by default, to a multicast address that only the directly connected neighbor reads. Neighbors keep the information for a holdtime of 180 seconds.

Because it is Layer 2, CDP works before any IP is configured and between devices in different subnets. It only ever sees directly connected neighbors: CORE learns about EDGE, ACC-A and ACC-B, but not about ISP-PE, which is two hops away.

Reading show cdp neighbors

Each line of show cdp neighbors describes one cable:

  • Device ID: the neighbor's hostname.
  • Local Intrfce: your port.
  • Holdtme: seconds left before the entry expires.
  • Capability: R for router, S for switch, and so on.
  • Platform: the model.
  • Port ID: the neighbor's port at the far end.

Local Intrfce and Port ID together describe both ends of the cable. On CORE, one line shows ACC-B on local Fa0/8: an uplink on a FastEthernet port, which nobody would have guessed. CDP reports what is really plugged in.

show cdp neighbors detail adds each neighbor's IP address and software version. That is how you find ACC-B's management address to ping it.

Labelling links with descriptions

description attaches a note to an interface. It changes nothing about forwarding, but it appears in show interfaces and show interfaces description. The format here, TO-<neighbor>-<neighbor port>, names the far device and its port, so the next engineer can follow the cable from either end.

Where CDP should be off

CDP tells the neighbor your hostname, model, software version and addresses. Inside your network that helps you. Towards a provider, or on a port anyone can plug into, it hands an attacker a list of which software to target.

no cdp enable on an interface stops CDP on that port only. no cdp run stops it on the whole device. Here only EDGE G0/1, facing ISP-PE, is turned off. After the holdtime runs out, EDGE disappears from ISP-PE's table.

LLDP (IEEE 802.1AB) is the open-standard equivalent, for mixed-vendor networks. On Cisco devices it is off by default and turned on with lldp run.

Check it worked

show interfaces description lists every port with its status and label, so a wrong description stands out next to the CDP output. On ISP-PE, show cdp neighbors should no longer list EDGE once the holdtime has run out. Finally, ping ACC-B's management address from EDGE to prove the address you found is real.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. CORE introduces itself CORE sends a CDP advertisement out of Gi0/2. EDGE records Device ID CORE, its own port Gi0/0 as Local Intrfce, and Gi0/2 as Port ID.
  2. An unexpected uplink ACC-B advertises from its Gi0/1, and CORE hears it on Fa0/8. Without CDP, nobody would have looked for an uplink on a FastEthernet port.
  3. The cross-link between access switches ACC-A and ACC-B also hear each other, on their Gi0/1 and Gi0/2. Cross-links like this are easy to miss without discovery.
  4. Leaking to the provider EDGE also advertises out of G0/1, so ISP-PE learns EDGE's hostname, platform, software version and address. That is information an attacker could use.
  5. No CDP on the edge port With no cdp enable on G0/1, EDGE stops advertising there. After the 180-second holdtime, EDGE disappears from ISP-PE's neighbor table.
  6. From discovery to reachability show cdp neighbors detail on CORE gives ACC-B's management address. EDGE pings it through CORE.

Key terms

CDP
Cisco Discovery Protocol: a Layer 2 protocol where Cisco devices advertise themselves to directly connected neighbors.
LLDP
Link Layer Discovery Protocol, IEEE 802.1AB: the vendor-neutral equivalent of CDP.
Device ID
The neighbor's hostname in the CDP table.
Local interface
Your own port, on which the neighbor was heard.
Port ID
The neighbor's port at the far end of the cable.
Holdtime
How long a device keeps a neighbor's information without a fresh advertisement. 180 seconds by default for CDP.
Interface description
A free-text label on an interface, shown in show commands. Does not affect traffic.

For the exam

  • 2.3: configure and verify Layer 2 discovery protocols (Cisco Discovery Protocol and LLDP).
  • CDP is Cisco proprietary and on by default; LLDP is an open standard and off by default on Cisco devices.
  • CDP defaults: advertisements every 60 seconds, holdtime 180 seconds. LLDP: 30 and 120 seconds.
  • no cdp enable is per interface; no cdp run is global. For LLDP: lldp run, and per interface lldp transmit and lldp receive.
  • CDP sees only directly connected neighbors, and detail shows their IP addresses.

Common mistakes

  • Swapping Local Intrfce and Port ID, so every description names the wrong end of the cable.
  • Using no cdp run to hide the edge: it also blinds you on every internal link.
  • Expecting a neighbor to vanish the moment CDP is disabled: the old entry stays until its holdtime expires.
  • Expecting CDP to show devices two hops away. It shows only the next device on each cable.

Quick check

1. On EDGE, a CDP line reads: Device ID CORE, Local Intrfce Gig 0/0, Port ID Gig 0/2. What does it mean?

  1. EDGE Gi0/0 connects to CORE Gi0/2
  2. EDGE Gi0/2 connects to CORE Gi0/0
  3. CORE is two hops away through Gi0/0
  4. CORE has IP address 0.0.0.2
Show the answer

A. EDGE Gi0/0 connects to CORE Gi0/2

Local Intrfce is your own port and Port ID is the neighbor's. The description on EDGE G0/0 is therefore TO-CORE-Gi0/2.

2. How do you stop EDGE advertising CDP to the ISP but keep it on the LAN?

  1. no cdp run
  2. no cdp enable on the ISP-facing interface
  3. lldp run
  4. shutdown on the ISP-facing interface
Show the answer

B. no cdp enable on the ISP-facing interface

no cdp enable works per interface. no cdp run would turn CDP off everywhere, and shutdown would cut the internet link.

3. Which statement about CDP is true?

  1. It needs IP addresses on both ends
  2. It shows every Cisco device in the network
  3. It runs at Layer 2 and shows only directly connected neighbors
  4. It is an IEEE standard
Show the answer

C. It runs at Layer 2 and shows only directly connected neighbors

CDP is a Cisco Layer 2 protocol, so it needs no IP and only sees the next device. LLDP is the IEEE standard.

4. Which command shows a neighbor's IP address?

  1. show cdp
  2. show cdp neighbors
  3. show interfaces description
  4. show cdp neighbors detail
Show the answer

D. show cdp neighbors detail

The plain neighbors view has no addresses. The detail view adds IP address, platform and software version.

5. An engineer needs neighbor discovery between a Cisco switch and another vendor's switch. What should they use?

  1. CDP, which every vendor supports
  2. LLDP, enabled with lldp run
  3. STP BPDUs
  4. ARP
Show the answer

B. LLDP, enabled with lldp run

LLDP is the vendor-neutral standard. On Cisco devices it is off by default and turned on with lldp run.

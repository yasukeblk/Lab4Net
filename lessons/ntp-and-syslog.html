NTP and syslog

Why every device needs the same clock

  • 4.2NTP client and server
  • 4.5Syslog facilities and levels

The problem: logs nobody can line up

When a link fails, you want to read what each device saw, in order. That only works if every device agrees on the time. A Cisco router keeps its own clock, and after a reload it may start from a default date in 1993. In show clock, a * in front of the time means the router does not trust its own clock.

Two services fix this together. NTP (Network Time Protocol) sets every clock from one source. Syslog sends each device's log messages to one server, so they can be read side by side.

How NTP works

NTP runs over UDP port 123. A client asks a server for the time, measures how long the answer took to arrive, and corrects its clock gradually.

Distance from a real reference clock is called the stratum. NTP1 takes its time from GPS, so it is stratum 1. R1 learns from NTP1 and becomes stratum 2. R2 also points at NTP1 (its packets are routed through R1), so it is stratum 2 as well. A device that is not synchronised reports stratum 16. A router can also be a server for others: in client mode it only takes time, and with ntp master it gives out its own.

Syslog messages and severity levels

A Cisco log message looks like %LINK-3-UPDOWN: the facility (the part of the system that raised it), the severity, and a short name. There are eight severities, and lower is worse:

  1. 0 emergencies, 1 alerts, 2 critical
  2. 3 errors, 4 warnings
  3. 5 notifications, 6 informational, 7 debugging

Syslog travels over UDP port 514. It is fire and forget: if the path to the server is down, the message is simply lost.

Choosing what gets sent

A level setting means "this level and everything more serious". logging trap warnings sends levels 0 to 4 to the server. The default trap level is informational (6), which would send almost everything.

The local buffer, read with show logging, keeps its own copy regardless of the trap level. That matters in this lab: when R2 shuts its only link, its "down" messages cannot reach LOG1 at all.

How it is set up here

On both routers: ntp server 192.168.1.50 makes them clients of NTP1. service timestamps log datetime msec stamps each message with the date and time to the millisecond, instead of the router's uptime. logging host 192.168.1.60 names LOG1, and logging trap warnings sets the filter.

Check it worked

show ntp associations lists the servers, with a * beside the one the router is synchronised to. show ntp status should say synchronised, stratum 2. Note the two different stars: in show clock a * is bad, in the associations list it is good. Synchronisation can take a minute or more.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. R2 asks for the time R2 sends an NTP request to 192.168.1.50. It crosses R1 like any other routed packet.
  2. R2 synchronises NTP1 answers with stratum 1 time from GPS. R2 corrects its clock and becomes stratum 2, one step from the reference.
  3. R2 G0/1 is shut down R2 logs an administrative shutdown at severity 5, notifications. It goes into the local buffer, but the trap level of warnings keeps it from LOG1.
  4. R1 reports a link down R1 saw its link drop without anyone touching it, an error at severity 3. That passes the warnings filter and reaches LOG1 on UDP 514, with an accurate timestamp.
  5. R2 cannot report R2's path to LOG1 was the link that just went down, so nothing it logs now can leave. Only its local buffer keeps the record.

Key terms

NTP
Network Time Protocol. Sets device clocks from a time server over UDP 123.
Stratum
How many steps a clock is from a reference source. 1 is closest; 16 means not synchronised.
Syslog
A standard way to send log messages to a central server, over UDP 514.
Severity level
A number from 0 (emergencies) to 7 (debugging). Lower is more serious.
Facility
The part of the system that produced a message, such as LINK or LINEPROTO.
Trap level
The least serious severity a device sends to its syslog server.
Logging buffer
A copy of recent messages kept in the device's own memory, read with show logging.

For the exam

  • 4.2: configure and verify NTP operating in client and server mode. 4.5: describe the use of syslog features including facilities and severity levels.
  • Know all eight severity levels in order, with their numbers. A level setting includes that level and every lower number.
  • Ports: NTP UDP 123, syslog UDP 514.
  • ntp server makes a device a client; ntp master makes it an authoritative source.
  • Read a message name: in %LINK-3-UPDOWN, 3 is the severity (errors).

Common mistakes

  • Expecting logging trap warnings to send only warnings: it sends 0 to 4.
  • Forgetting service timestamps log datetime: messages show uptime, which cannot be compared between devices.
  • Judging NTP straight after configuring it: synchronisation takes a while, so show ntp status says unsynchronised at first.
  • No route to the NTP or syslog server: nothing arrives and nothing on the router warns you.

Quick check

1. A router is configured with logging trap warnings. Which messages reach the syslog server?

  1. Only severity 4
  2. Severities 4 to 7
  3. Severities 0 to 4
  4. Severities 0 to 3
Show the answer

C. Severities 0 to 4

A level includes itself and everything more serious, and lower numbers are more serious. Warnings is 4, so 0 to 4 are sent.

2. R1 learns its time from a stratum 1 GPS server. What stratum does R1 report?

  1. 1
  2. 2
  3. 0
  4. 16
Show the answer

B. 2

Each step away from the reference adds one. Stratum 16 means unsynchronised.

3. Which transport and port does syslog use by default?

  1. TCP 514
  2. UDP 123
  3. UDP 69
  4. UDP 514
Show the answer

D. UDP 514

Syslog is UDP 514. UDP 123 is NTP and UDP 69 is TFTP.

4. A message reads %LINEPROTO-5-UPDOWN. What does the 5 mean?

  1. Severity 5, notifications
  2. Interface number 5
  3. Facility number 5
  4. Severity 5, errors
Show the answer

A. Severity 5, notifications

The number between the facility and the name is the severity. 5 is notifications; errors is 3.

5. show clock on a router shows * before the time. What does that tell you?

  1. The router is the NTP master
  2. The clock is not authoritative, so it is not synchronised
  3. The time is in UTC
  4. NTP is synchronised
Show the answer

B. The clock is not authoritative, so it is not synchronised

In show clock a star means the time is not trusted. In show ntp associations a star marks the server in use, which is good news.

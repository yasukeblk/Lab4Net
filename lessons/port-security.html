Port security

How a switch decides who may plug in

  • 5.7Layer 2 security

The problem: any device can plug in

A switch port forwards for whatever is connected to it. Anyone who unplugs a desk PC, or finds a live wall jack, gets onto the LAN. They could also flood the switch with fake source MAC addresses to fill its MAC address table.

Port security limits which and how many MAC addresses (the hardware address of a network card) may send frames into a port. A frame from any other address is a violation, and the switch takes the action you chose.

How it works

  1. You set a maximum number of secure MAC addresses per port. The default is 1.
  2. The switch learns secure addresses, either typed in by hand or learned from the first frames it sees, up to the maximum.
  3. A frame from a new address after the maximum is reached is a violation.

Port security only works on a port fixed as access (or trunk). A port left in a dynamic mode, which could negotiate either way, refuses the command. That is why the lab starts with switchport mode access.

Sticky learning

Typing every MAC address by hand is slow. switchport port-security mac-address sticky learns the addresses currently plugged in and writes them into the running configuration as if you had typed them. Save with copy running-config startup-config and they survive a reload. Without saving, they are lost when the switch restarts.

Three violation modes

  • shutdown (the default): the port goes into the err-disabled state and stops all traffic, including the legitimate device. It stays down until an administrator runs shutdown then no shutdown, or automatic recovery is set up.
  • restrict: frames from the unknown address are dropped, a log message is sent, and the violation counter goes up. The port stays up.
  • protect: frames from the unknown address are dropped silently. No log, no counter.

How it is configured here

Fa0/1 has one PC, so it keeps the defaults: maximum 1, shutdown. Fa0/2 has a PC and an IP phone, so it allows a maximum of 2 with violation restrict, so one wrong device does not take the whole desk offline. Both use sticky learning. The unused ports Fa0/3 to Fa0/8 are simply shut down: a port that is off cannot be used at all, which is the simplest security there is.

Check it worked

show port-security lists each secured port with its maximum, current count, violation count and action. show port-security interface f0/2 gives the detail, including the last source address seen. show running-config shows the sticky addresses. A port in err-disabled shows in show interfaces status. Finally, ping PC2 from PC1 to show legitimate traffic still flows.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. SW1 learns PC1 PC1 sends its first frame into Fa0/1. Sticky learning records its MAC address as secure and writes it into the running configuration. Fa0/1 is now full at its maximum of 1.
  2. Fa0/2 learns two addresses The PC and the IP phone on Fa0/2 both send frames. With maximum 2, both MAC addresses are learned as secure.
  3. Legitimate traffic flows PC1 pings PC2. Both source addresses are secure on their ports, so SW1 forwards normally.
  4. A third device on Fa0/2 Someone adds a laptop to the desk at Fa0/2. Its MAC address would be the third, so SW1 drops its frames, logs it and counts a violation. The PC and phone keep working.
  5. A different device on Fa0/1 PC1 is unplugged and a laptop is plugged into the same jack. Its address is not the sticky one, so the default shutdown mode puts Fa0/1 into err-disabled and the port stops passing any traffic.
  6. The admin brings it back With PC1 back on the jack, an administrator runs shutdown and then no shutdown on Fa0/1. The port comes up and PC1 is accepted again.

Key terms

Port security
A switch feature that limits which and how many MAC addresses may use a port.
Secure MAC address
An address the port is allowed to accept, typed in or learned.
Sticky learning
Learning the connected MAC addresses and saving them into the running configuration.
Violation
A frame from a MAC address that is not allowed once the maximum is reached.
err-disabled
The state a port is put into by the shutdown violation mode. It passes no traffic until reset.
restrict
Violation mode that drops, logs and counts offending frames while keeping the port up.
protect
Violation mode that drops offending frames silently, with no log or counter.

For the exam

  • 5.7: configure and verify Layer 2 security features (DHCP snooping, dynamic ARP inspection, and port security).
  • Defaults: maximum 1 address, violation mode shutdown.
  • Compare the modes: shutdown err-disables the port; restrict drops, logs and counts; protect drops silently.
  • Sticky addresses go into the running configuration and must be saved to survive a reload.
  • Recover an err-disabled port with shutdown then no shutdown on the interface.

Common mistakes

  • Enabling port security on a port still in a dynamic mode: the command is rejected.
  • Leaving maximum 1 on a desk with a PC and a phone: the second device causes a violation and, in shutdown mode, takes the port down.
  • Forgetting to save after sticky learning: after a reload the switch learns whatever is plugged in first, which may not be the right device.
  • Clearing the cause of a violation but not bouncing the port: it stays err-disabled until shutdown and no shutdown.

Quick check

1. A port is configured with switchport port-security and nothing else. A second MAC address appears. What happens?

  1. The frames are dropped silently
  2. The frames are dropped and logged, and the port stays up
  3. The port goes into err-disabled
  4. The second address is learned and allowed
Show the answer

C. The port goes into err-disabled

The defaults are maximum 1 and violation shutdown, so the second address err-disables the port.

2. Which violation mode drops the offending frames and logs them but keeps the port up?

  1. shutdown
  2. protect
  3. disable
  4. restrict
Show the answer

D. restrict

restrict drops, logs and increments the violation counter. protect also keeps the port up but drops silently, with no log or counter.

3. Why does the lab set Fa0/1 and Fa0/2 to switchport mode access first?

  1. Port security is refused on a port that could still negotiate its mode
  2. Access mode is needed for sticky learning to save
  3. It raises the maximum to 2
  4. It turns off CDP
Show the answer

A. Port security is refused on a port that could still negotiate its mode

Port security needs a port fixed in access (or trunk) mode. A port in a dynamic mode rejects the command.

4. After sticky learning, the switch reloads and the learned addresses are gone. Why?

  1. Sticky addresses age out after one hour
  2. The running configuration was not saved to startup
  3. Sticky only works with violation protect
  4. The ports were shut down
Show the answer

B. The running configuration was not saved to startup

Sticky writes addresses into the running configuration. Like any change there, they must be saved with copy running-config startup-config to survive a reload.

5. Fa0/1 is err-disabled. The wrong device has been removed. What brings it back?

  1. It recovers on its own after the device is removed
  2. clear port-security only
  3. shutdown then no shutdown on the interface
  4. Reloading PC1
Show the answer

C. shutdown then no shutdown on the interface

An err-disabled port stays down until it is reset by hand (or automatic recovery is configured). Removing the cause is not enough.

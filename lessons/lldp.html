LLDP

How devices discover their neighbours

  • 2.3CDP and LLDP

The problem: what is on that port?

A contractor plugged a Linux file server into SW1 and nobody wrote down where. A Layer 2 discovery protocol solves this: each device regularly tells the device on the other end of each cable its name, its port, what kind of device it is and how to reach it.

Cisco devices already run CDP (Cisco Discovery Protocol), on by default. But CDP is Cisco's own protocol. The Linux server does not speak it, so show cdp neighbors on SW1 shows R1 and SW2 and nothing on Fa0/5.

LLDP: the open standard

LLDP (Link Layer Discovery Protocol) is the IEEE 802.1AB standard, so any vendor can run it. The server runs an LLDP agent (lldpd). On Cisco routers and switches LLDP is off by default, so you must turn it on with the global command lldp run.

Like CDP, LLDP only reaches the directly connected device. A switch does not forward LLDP frames, so SW1 learns about R1, SW2 and the server, but never about PC1 behind SW2.

What an advertisement contains

Each LLDP message is a set of fields called TLVs (type, length, value). The ones you will read most:

  • System name: what the device calls itself. Shown as Device ID.
  • Port ID: its own port on the other end of the cable.
  • Capabilities: R router, B bridge (switch), T telephone, W access point, S station (an end host).
  • System description and management address: often the exact OS version and an IP address to reach it.

LLDP sends every 30 seconds by default and neighbours keep the entry for 120 seconds (CDP: 60 and 180).

CDP and LLDP side by side

  • Owner: CDP is Cisco proprietary; LLDP is an IEEE standard.
  • Default on Cisco: CDP on; LLDP off.
  • Turn on globally: cdp run; lldp run.
  • Per interface: cdp enable; lldp transmit and lldp receive, set separately.
  • Timers: CDP 60 seconds and hold 180; LLDP 30 seconds and hold 120.

Both can run at the same time. Many networks keep CDP for Cisco gear and add LLDP for everything else, which is what this lab does on SW1, SW2 and R1.

Transmit and receive are separate

Each interface can send and listen independently. no lldp transmit on Fa0/5 stops SW1 telling the contractor's server anything about your switch, while the default lldp receive keeps listening, so the server stays in your neighbour table.

This matters because discovery data is useful to attackers too: model, software version and addresses. A common practice is to turn discovery off on ports facing devices you do not manage. no lldp run would do far more: it stops LLDP on every port.

Check it worked

show lldp neighbors lists Device ID, local interface, hold time, capabilities and port ID. On SW1 you find the server on Fa0/5 with capability S. show lldp neighbors detail adds the system description and management address, which you can ping from R1. show lldp interface shows Tx and Rx state per port, and show lldp shows the timers.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. CDP sees Cisco devices SW1 and SW2 exchange CDP every 60 seconds, so each knows the other. R1 shows up the same way.
  2. The server speaks LLDP only The Linux server sends LLDP frames, but LLDP is off on SW1, so they are dropped and Fa0/5 shows no neighbour.
  3. lldp run With LLDP on, SW1 reads the server's advertisement: its system name, capability S, its OS description and a management address.
  4. Use what you learned R1 pings the management address read from show lldp neighbors detail. Now you know where the box is and how to reach it.
  5. Stop advertising to it no lldp transmit on Fa0/5 means SW1 tells the contractor's server nothing about itself.
  6. Receive is still on The server keeps advertising and SW1 keeps listening, so the entry stays in the neighbour table.

Key terms

CDP
Cisco Discovery Protocol. Cisco-only, enabled by default on Cisco devices.
LLDP
Link Layer Discovery Protocol, IEEE 802.1AB. Vendor-neutral, disabled by default on Cisco routers and switches.
TLV
Type, length, value: one field of information in an LLDP message.
Device ID
The name a neighbour calls itself, from its system name.
Capability S
Station: the neighbour is an end host, not a network device.
Hold time
How long a neighbour entry is kept without a fresh advertisement. LLDP default 120 seconds.
Management address
An address the neighbour advertises for reaching and managing it.

For the exam

  • 2.3: configure and verify Layer 2 discovery protocols (Cisco Discovery Protocol and LLDP).
  • CDP is Cisco proprietary and on by default; LLDP is IEEE 802.1AB and off by default on Cisco.
  • Global commands: cdp run and lldp run. Per interface: cdp enable, lldp transmit, lldp receive.
  • LLDP timers: 30 seconds between advertisements, 120 seconds hold time. CDP: 60 and 180.
  • Both only see directly connected neighbours.

Common mistakes

  • Expecting LLDP to work without lldp run: the neighbour table stays empty.
  • Running LLDP on one end only: the other end never advertises, so you see it from one side only.
  • Using no lldp run to hide from one port: the switch goes blind on every port.
  • Turning off receive instead of transmit: you stop learning about the server while still telling it about you.
  • Looking for a host two switches away in the LLDP table: discovery is one hop only.

Quick check

1. A Linux server is plugged into a Cisco switch. show cdp neighbors does not list it. Why?

  1. The server is on the wrong VLAN
  2. CDP is Cisco proprietary and the server does not run it
  3. CDP only lists routers
  4. The hold time has expired
Show the answer

B. CDP is Cisco proprietary and the server does not run it

CDP is Cisco's own protocol. Non-Cisco devices use LLDP, which must be enabled on the switch.

2. What is the default state of LLDP on a Cisco switch?

  1. Enabled globally, disabled per port
  2. Enabled on trunk ports only
  3. Disabled; enable it with lldp run
  4. Enabled on all ports
Show the answer

C. Disabled; enable it with lldp run

LLDP is off by default on Cisco routers and switches. CDP is the one that is on by default.

3. You want SW1 to keep learning about the server on Fa0/5 but stop telling it anything. What do you configure?

  1. no lldp transmit on Fa0/5
  2. no lldp receive on Fa0/5
  3. no lldp run
  4. no cdp enable on Fa0/5
Show the answer

A. no lldp transmit on Fa0/5

Transmit and receive are separate. Turning off transmit hides the switch; receive stays on. no lldp run would stop LLDP on every port.

4. What does capability code S mean in show lldp neighbors?

  1. Switch
  2. Server only
  3. Secure port
  4. Station, an end host
Show the answer

D. Station, an end host

S is station. A switch is shown as B, for bridge.

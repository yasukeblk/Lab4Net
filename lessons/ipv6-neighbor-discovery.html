IPv6 neighbor discovery

How IPv6 hosts find routers and each other

  • CCNA 1.8IPv6 addressing and prefixes
  • CCNA 1.9IPv6 address types

IPv6 has no ARP and no broadcast

IPv4 uses ARP broadcasts to find MAC addresses and DHCP broadcasts to find a server. IPv6 has no broadcast at all. Both jobs, and several more, are done by the Neighbor Discovery Protocol (NDP), which uses ICMPv6 messages sent to multicast groups.

The gain is that only the devices that need a message have to process it.

The multicast groups to know

  • FF02::1: all nodes on the link. The closest thing IPv6 has to a broadcast.
  • FF02::2: all routers on the link.
  • FF02::5 and FF02::6: OSPFv3 routers and designated routers.
  • Solicited-node addresses: FF02::1:FF followed by the last 24 bits of a unicast address. Every address a device has joins one.

FF02 means the group is link-local in scope: these packets are never routed.

Finding a neighbour: NS and NA

This pair replaces ARP.

  1. A host wants the MAC for 2001:DB8:1:1::10. It sends a Neighbor Solicitation (NS) to that address's solicited-node group, FF02::1:FF00:10.
  2. Only devices whose address ends in the same 24 bits listen to that group. In practice that is the one target.
  3. The target answers with a Neighbor Advertisement (NA) carrying its MAC address.
  4. The host stores the pair in its neighbor table.

show ipv6 neighbors on a router is the IPv6 version of show ip arp.

Finding a router: RS and RA

  1. A host that has just connected sends a Router Solicitation (RS) to FF02::2.
  2. Each router answers with a Router Advertisement (RA), sent to FF02::1. Routers also send RAs on a timer without being asked.
  3. The RA carries the link's prefix and prefix length, and flags that say whether to use DHCPv6.
  4. The host uses the RA's source, the router's link-local address, as its default gateway.

A Cisco router only sends RAs when ipv6 unicast-routing is enabled. Without that command it has IPv6 addresses but does not act as an IPv6 router.

Three ways to get an address

  • SLAAC: the host takes the prefix from the RA and builds its own interface ID, with EUI-64 or a random value. No server is involved.
  • Stateless DHCPv6: the host still builds its address with SLAAC, and asks a DHCPv6 server only for extras such as the DNS server.
  • Stateful DHCPv6: a DHCPv6 server assigns the address and keeps track of it, as DHCP does in IPv4.

In every case the default gateway comes from the RA. DHCPv6 does not supply one.

Duplicate address detection

Before using any address, a device checks that nobody else has it. It sends an NS for its own new address. If an NA comes back, the address is a duplicate and is not used. If there is silence, the address is safe. This is DAD, and it runs for link-local addresses too.

One more address type: anycast

An anycast address is one address configured on several devices. Routing delivers a packet to the nearest of them. It is taken from the unicast range, so it looks like any other address; what differs is that more than one device answers to it.

Summary: unicast is one to one, multicast is one to many, anycast is one to nearest. IPv6 has no broadcast.

Key terms

NDP
Neighbor Discovery Protocol: the ICMPv6-based protocol that replaces ARP and adds router discovery in IPv6.
Neighbor Solicitation
The NDP message that asks for the MAC address of an IPv6 address; also used for duplicate address detection.
Router Advertisement
The NDP message a router sends with the link prefix and other settings.
Solicited-node multicast
The group FF02::1:FF plus the last 24 bits of an address; where an NS for that address is sent.
SLAAC
Stateless address autoconfiguration: a host builds its own address from the prefix in an RA.
DAD
Duplicate address detection: checking that an address is unused before taking it.
Anycast
One address on several devices; traffic goes to the nearest.

For the exam

  • 1.8: configure and verify IPv6 addressing and prefix. 1.9: describe IPv6 address types, including anycast, multicast and modified EUI-64.
  • NS and NA replace ARP. RS and RA let hosts find routers and prefixes.
  • FF02::1 is all nodes; FF02::2 is all routers.
  • A router sends RAs only with ipv6 unicast-routing configured.
  • With SLAAC and with DHCPv6, the default gateway is the router's link-local address learned from the RA.

Common mistakes

  • Forgetting ipv6 unicast-routing. Interfaces have addresses and can be pinged, but hosts never get a prefix or a gateway and the router does not forward IPv6.
  • Looking for an IPv6 broadcast address. There is none; FF02::1 does that job.
  • Expecting DHCPv6 to hand out a default gateway. It does not.

Quick check

1. Which IPv6 messages do the job that ARP does in IPv4?

  1. Router Solicitation and Router Advertisement
  2. Neighbor Solicitation and Neighbor Advertisement
  3. DHCPv6 Solicit and Advertise
  4. Echo Request and Echo Reply
Show the answer

B. Neighbor Solicitation and Neighbor Advertisement

NS asks who has an address and NA answers with the MAC. RS and RA are for finding routers and prefixes.

2. To which address does a host send a Router Solicitation?

  1. FF02::1
  2. FE80::1
  3. FF02::2
  4. ::1
Show the answer

C. FF02::2

FF02::2 is the all-routers group. FF02::1 is all nodes, which is where routers send their advertisements.

3. A host uses SLAAC. Where does it learn its default gateway?

  1. From the source address of the Router Advertisement
  2. From a DHCPv6 server
  3. From the DNS server
  4. From its own EUI-64 calculation
Show the answer

A. From the source address of the Router Advertisement

The gateway is the link-local address of the router that sent the RA. DHCPv6 never supplies a gateway.

4. R1 has IPv6 addresses on its interfaces, but hosts on its LAN get no global address by SLAAC. What is the most likely cause?

  1. The interfaces need EUI-64
  2. The LAN prefix must be /48
  3. A DHCPv6 pool is missing
  4. ipv6 unicast-routing is not configured
Show the answer

D. ipv6 unicast-routing is not configured

Without ipv6 unicast-routing the router does not send Router Advertisements, so hosts never learn the prefix.

5. Which statement describes an anycast address?

  1. It is delivered to every node on the link
  2. It is assigned to several devices and reaches the nearest one
  3. It is only valid on one link
  4. It always starts with FF
Show the answer

B. It is assigned to several devices and reaches the nearest one

Anycast is one address on several devices, with routing choosing the closest. Addresses starting FF are multicast.

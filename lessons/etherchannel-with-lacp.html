EtherChannel with LACP

How two cables become one link

  • 2.4LACP EtherChannel

The problem: spanning tree wastes the second cable

SW1 and SW2 are joined by two cables, Gi0/1 and Gi0/2. Two parallel links between the same switches form a loop, so spanning tree (STP, the protocol that stops Layer 2 loops) blocks one of them. The second cable just sits there as a spare. You paid for two links and use one.

EtherChannel fixes this by bundling the physical links into one logical link called a port-channel. Spanning tree sees a single link, so nothing is blocked. Both cables carry traffic, and if one fails the bundle stays up on the other with no spanning tree change.

How traffic is shared

The switch does not split one conversation across both cables. That could deliver frames out of order. Instead it runs a hash on addresses in each frame (for example source and destination MAC or IP) and the result picks a member link. Every frame of the same flow takes the same link.

So one big transfer between two hosts still uses one cable. The gain comes from many flows spread over the members. A bundle can have up to 8 active links.

LACP: agreeing on the bundle

Both switches must agree which ports belong together. If one side bundled and the other did not, frames could loop or be lost. A negotiation protocol checks this first.

  • LACP (Link Aggregation Control Protocol, IEEE 802.3ad) is the open standard. Its modes are active (sends LACP messages and starts negotiation) and passive (only answers).
  • PAgP is the older Cisco-only protocol, with modes desirable and auto.
  • Mode on forces the bundle with no negotiation at all. Both ends must then be on.

At least one LACP side must be active. Active with active, or active with passive, forms a bundle. Passive with passive never does, because both wait for the other to speak.

Members must match

Every member port must have the same speed, duplex, access or trunk mode, allowed VLANs and native VLAN. A port that differs is suspended from the bundle. The safe habit is to configure Layer 2 settings on interface port-channel 1, not on the members. The members inherit them, so they stay identical.

How it is configured here

On SW1, interface range g0/1 - 2 then channel-group 1 mode active puts both ports in group 1 and creates Port-channel 1. SW2 gets the same (active or passive). Then switchport mode trunk on Port-channel 1 on both switches lets VLAN 10 cross, so PC1 (192.168.10.11) can reach PC2 (192.168.10.12).

Check it worked

show etherchannel summary lists each bundle. Po1(SU) means Layer 2 and in use. (P) after a member means bundled. Watch for (s) suspended, (I) stand-alone (the other side is not negotiating) and (D) down. Then ping PC2 from PC1 to prove VLAN 10 crosses the trunk.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. SW1 starts the negotiation Gi0/1 and Gi0/2 on SW1 are in channel group 1 in active mode, so SW1 sends LACP messages down both cables asking SW2 to bundle them.
  2. SW2 agrees SW2 answers on the same two ports. Both switches now know the two cables lead to the same neighbour and the settings match.
  3. The bundle comes up The two ports become one logical link, Port-channel 1. Spanning tree sees a single link, so neither cable is blocked.
  4. Traffic crosses the trunk PC1 pings 192.168.10.12. SW1 tags the frame for VLAN 10 on the Port-channel 1 trunk, and its hash picks one member link to carry this flow.
  5. One cable is cut Gi0/1 goes down. The bundle loses a member but Port-channel 1 itself stays up, so spanning tree does not need to recalculate.
  6. Traffic moves to Gi0/2 Flows that used Gi0/1 are rehashed onto Gi0/2. The pings keep working, at half the total capacity, until the cable is fixed.

Key terms

EtherChannel
Several physical links bundled into one logical link.
Port-channel
The logical interface that represents the bundle.
LACP
Link Aggregation Control Protocol, the IEEE standard for negotiating a bundle. Modes active and passive.
PAgP
Port Aggregation Protocol, the Cisco-only alternative. Modes desirable and auto.
Mode on
Bundles the ports without any negotiation protocol.
Load-balancing hash
The calculation on frame addresses that chooses which member link carries a flow.
Suspended port
A member that does not match the bundle and has been left out of it.

For the exam

  • 2.4: configure and verify (Layer 2/Layer 3) EtherChannel (LACP).
  • LACP is open standard (802.3ad); PAgP is Cisco proprietary. Know which mode pairs form a bundle: active/active and active/passive yes, passive/passive no.
  • Mode on only works with on at the other end. It never forms with an LACP or PAgP mode.
  • Load balancing is per flow, not per frame, so one flow never exceeds one link's speed.
  • Spanning tree treats the port-channel as one link, so no member is blocked.

Common mistakes

  • Both ends passive: no bundle forms, the ports show (I) stand-alone, and spanning tree blocks one link again.
  • Changing trunk settings on one member instead of the port-channel: that member no longer matches and is shown (s) suspended.
  • Port-channel left as an access port in VLAN 1: the bundle is up but PC1 cannot reach PC2 in VLAN 10.
  • Mixing on at one end with active at the other: no bundle forms, and the two sides can disagree about whether a loop exists.

Quick check

1. SW1 is set to LACP passive and SW2 is also passive. What happens?

  1. The bundle forms using LACP
  2. No bundle forms, because neither side starts the negotiation
  3. The bundle forms using PAgP instead
  4. The bundle forms but only one link carries traffic
Show the answer

B. No bundle forms, because neither side starts the negotiation

Passive only answers LACP messages. With two passive ends nobody sends the first one, so the ports stay separate and spanning tree blocks one.

2. Why does one large file copy between PC1 and PC2 not go faster with a two-link bundle?

  1. LACP only uses the second link as a backup
  2. Spanning tree still blocks one member
  3. Port-channels are limited to the speed of the slowest member
  4. The hash sends every frame of one flow over the same member link
Show the answer

D. The hash sends every frame of one flow over the same member link

Load sharing is per flow. Keeping a flow on one link keeps its frames in order, so one flow is limited to one link's speed.

3. Which pair of modes forms an EtherChannel?

  1. active and passive
  2. on and active
  3. desirable and active
  4. auto and passive
Show the answer

A. active and passive

Active and passive are both LACP and one side starts. Mode on does not negotiate, and desirable/auto are PAgP, which cannot talk to LACP.

4. show etherchannel summary shows Gi0/2 with the flag (s). What does that mean?

  1. The port is bundled and working
  2. The port is a Layer 3 member
  3. The port is suspended because its settings do not match the bundle
  4. The port is in standby, waiting for a ninth link to fail
Show the answer

C. The port is suspended because its settings do not match the bundle

(s) is suspended, usually from a mismatch such as a different trunk or VLAN setting. (P) would mean bundled.

5. Where should you configure switchport mode trunk for the bundle?

  1. On Gi0/1 only
  2. On interface port-channel 1
  3. On VLAN 10
  4. On the PC-facing ports
Show the answer

B. On interface port-channel 1

Settings on the port-channel are inherited by every member, which keeps them identical. Setting members one by one risks a mismatch and a suspended port.

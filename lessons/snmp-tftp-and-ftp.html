SNMP, TFTP and FTP

How devices are monitored and files moved

  • 4.4
  • 4.9

The problems these solve

A network team needs to know how its devices are doing without logging in to each one: is an interface down, is the CPU busy, how much traffic crossed a link. SNMP (Simple Network Management Protocol) answers that. A team also needs to move files to and from devices: back up a configuration, or load a new IOS image. TFTP and FTP do that.

SNMP: managers, agents and the MIB

SNMP has two roles. The manager (often called the NMS, network management station) is the monitoring server. The agent is software on each router, switch or server that answers it.

Every value an agent can report is stored in its MIB (Management Information Base), a tree of variables. Each variable has an OID (object identifier), a dotted number such as 1.3.6.1.2.1.1.5 (the device name). The manager asks for OIDs, and the agent replies with their values.

SNMP messages and ports

  • Get, GetNext and GetBulk: the manager reads values. GetBulk (v2c and later) fetches many at once.
  • Set: the manager changes a value on the device.
  • Trap: the agent tells the manager about an event without being asked, such as an interface going down. Traps are not acknowledged.
  • Inform: like a trap, but the manager acknowledges it, so the agent can resend if it is lost.

SNMP runs over UDP. The agent listens on port 161 for Gets and Sets. The manager listens on port 162 for traps and informs.

SNMP versions and security

SNMPv1 and SNMPv2c use a community string, which works like a shared password and is sent in clear text. A community can be read-only (ro) or read-write (rw).

SNMPv3 adds real security: users instead of communities, authentication (proof the message came from that user and was not changed) and encryption (privacy). Its three levels are noAuthNoPriv, authNoPriv and authPriv. Only authPriv both authenticates and encrypts.

On IOS, snmp-server community NAME ro allows v2c reads, snmp-server host names the manager that receives traps, and snmp-server enable traps turns traps on.

TFTP: simple and unprotected

TFTP (Trivial File Transfer Protocol) uses UDP port 69. It has no login, no encryption and cannot list a directory: you must know the file name. It sends the file in small blocks, and waits for an acknowledgement of each block before sending the next. That makes it reliable but slow over long distances.

Because it is so small, TFTP is built into devices and boot loaders. copy running-config tftp: backs up a configuration, and copy tftp: flash: loads a new IOS image. The router prompts for the server address and file name.

FTP: logins and two connections

FTP (File Transfer Protocol) uses TCP, so it is reliable and better for large files. It needs a username and password, and it can list, rename and delete files.

FTP uses two connections. The control connection goes to TCP port 21 and carries commands. A separate data connection carries the file. In active mode the server opens the data connection back to the client, from port 20. In passive mode the client opens it to a port the server chooses, which works better through firewalls and NAT.

FTP sends its password in clear text. On IOS, ip ftp username and ip ftp password set the login, then copy ftp: flash: works like the TFTP version. SFTP and SCP are the encrypted alternatives.

Upgrading IOS, in order

  1. Check there is room: show flash: or dir flash:.
  2. Copy the image from the TFTP or FTP server into flash.
  3. Optionally check the file is intact with verify /md5.
  4. Point the router at it with boot system flash: and the file name, then save the configuration.
  5. Reload, and confirm the version with show version.

Key terms

SNMP manager (NMS)
The monitoring server that polls devices and receives their traps.
SNMP agent
Software on a network device that answers the manager and sends traps.
MIB
The tree of variables an agent can report or change.
OID
The dotted number that identifies one variable in the MIB.
Trap
An unrequested, unacknowledged alert sent from agent to manager.
Inform
An alert like a trap that the manager acknowledges.
Community string
The clear-text shared password used by SNMPv1 and v2c.
TFTP
A minimal file transfer protocol on UDP port 69 with no login.
FTP
A file transfer protocol on TCP with logins, using port 21 for control.

For the exam

  • 4.4: explain the function of SNMP in network operations. 4.9: describe the capabilities and functions of TFTP/FTP in the network.
  • SNMP uses UDP 161 on the agent (Get, Set) and UDP 162 on the manager (Trap, Inform).
  • Only SNMPv3 offers authentication and encryption. v1 and v2c use clear-text community strings.
  • Informs are acknowledged, traps are not. GetBulk and Inform arrived with v2c.
  • TFTP: UDP 69, no authentication, no directory listing. FTP: TCP 21 for control, TCP 20 for data in active mode.

Common mistakes

  • Using a read-write community when read-only is enough: anyone who sniffs the clear-text string can change the device.
  • Expecting traps on port 161: the manager listens on 162, so a firewall that only allows 161 silently drops every trap.
  • Calling TFTP secure because it is used for IOS images: it has no login and no encryption at all.
  • Copying a new image without checking free space in flash: the copy fails part way, or an old image is deleted with nothing to boot.

Quick check

1. A router sends an alert to the NMS when an interface goes down and the NMS sends back an acknowledgement. Which SNMP message was it?

  1. Trap
  2. Inform
  3. GetResponse
  4. Set
Show the answer

B. Inform

An Inform is acknowledged by the manager, so the agent knows it arrived. A Trap carries the same kind of alert but nobody acknowledges it.

2. Which SNMP version and level both authenticates and encrypts messages?

  1. SNMPv2c with a read-only community
  2. SNMPv3 authNoPriv
  3. SNMPv1 with a read-write community
  4. SNMPv3 authPriv
Show the answer

D. SNMPv3 authPriv

authPriv adds privacy (encryption) on top of authentication. authNoPriv proves who sent the message but leaves it readable, and v1 and v2c only have clear-text communities.

3. Which statement about TFTP is true?

  1. It uses UDP port 69 and has no username or password
  2. It uses TCP port 21 and requires a login
  3. It encrypts files in transit
  4. It can list the files on the server
Show the answer

A. It uses UDP port 69 and has no username or password

TFTP is deliberately minimal: UDP 69, no authentication, no encryption and no directory listing. TCP 21 and logins belong to FTP.

4. On which port does an SNMP manager receive traps?

  1. UDP 161
  2. TCP 162
  3. UDP 162
  4. UDP 69
Show the answer

C. UDP 162

Agents listen on UDP 161 for Gets and Sets, and managers listen on UDP 162 for traps and informs. SNMP does not use TCP for these.

5. Why does FTP passive mode work better than active mode through a firewall?

  1. Passive mode encrypts the data
  2. In passive mode the client opens the data connection, so nothing has to come in from outside
  3. Passive mode uses UDP instead of TCP
  4. Passive mode uses only port 21
Show the answer

B. In passive mode the client opens the data connection, so nothing has to come in from outside

In active mode the server connects back to the client, which a firewall or NAT usually blocks. In passive mode the client opens both connections outward.

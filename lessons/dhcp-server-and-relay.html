DHCP server and relay

How devices get their addresses

  • 1.10Client IP parameters
  • 4.3DHCP and DNS concepts
  • 4.6DHCP client and relay

The problem DHCP solves

Every device needs four settings before it can talk beyond itself: an IP address, a subnet mask, a default gateway (the router that leads off its subnet) and a DNS server (which turns names like example.com into addresses).

Typing those by hand on every laptop, phone and printer is slow, and one typo or one address used twice breaks a device. DHCP (Dynamic Host Configuration Protocol) hands them out automatically. In this lab R1 is the DHCP server.

Pools: one per subnet

A DHCP pool (Windows servers call it a scope) is the server's settings for one subnet. It says which network to hand addresses from, and which options to give clients with them: at least default-router (the gateway) and dns-server.

R1 serves two subnets, so it needs two pools: LAN10 for 192.168.10.0/24 and LAN20 for 192.168.20.0/24. When a request arrives, the server uses the pool whose network contains the address of the interface the request came in on. That is how one server serves many subnets without mixing them up.

Leases and exclusions

An address is not given away for ever. It is leased for a set time (one day by default on a Cisco router). About halfway through, the client asks its server to renew. If a device leaves and stops renewing, the address returns to the pool. The server records who has which address in its binding table.

Some addresses are set by hand: router interfaces, switches, servers and printers. ip dhcp excluded-address keeps them out of the pool, so the server never leases one of them to someone else and causes a duplicate. Here .1 to .10 in each LAN are kept for that.

DORA: the four messages

Getting an address takes four messages, remembered as DORA. Use See it happen below to watch them cross this lab's map.

  1. Discover: the client has no address and does not know where the server is, so it broadcasts to everyone: from 0.0.0.0 to 255.255.255.255, UDP port 68 to port 67.
  2. Offer: a server answers with an address it is willing to lease, plus the options.
  3. Request: the client asks for that address. This is broadcast too, so any other server that made an offer knows it was not chosen.
  4. Acknowledge: the server confirms. The lease starts and the client configures itself.

Remote subnets need a relay

Routers do not forward broadcasts, so PC3's Discover reaches R2 and goes no further. R1 never hears it.

ip helper-address 10.0.0.1 on R2 fixes that. It goes on the interface that receives the client broadcasts: R2 G0/1, facing PC3. R2 then relays each DHCP broadcast to R1 as a normal unicast packet, and writes its own interface address (192.168.20.1) into the message. That address, called the giaddr, tells R1 which pool to use: LAN20.

Check it worked

On the server: show ip dhcp binding lists every lease (address, client, expiry). show ip dhcp pool shows each pool and how many addresses are in use. On a PC: ipconfig /renew asks again, and ipconfig shows the result. An address starting 169.254 means no server answered and the PC gave itself a placeholder that cannot reach other networks.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Discover PC1 has no address, so it broadcasts: "Is there a DHCP server out there?" SW1 floods the broadcast and it reaches R1.
  2. Offer R1 picks the LAN10 pool, because the request arrived on G0/0 in 192.168.10.0/24. It skips the excluded .1 to .10 and offers 192.168.10.11, with gateway 192.168.10.1 and DNS 8.8.8.8.
  3. Request PC1 broadcasts again: "I would like 192.168.10.11, from R1." Broadcasting tells any other server that its offer was turned down.
  4. Acknowledge R1 confirms and records the binding. PC1 configures the address, mask, gateway and DNS. The lease has started.
  5. Remote subnet, no relay PC3 broadcasts a Discover too, but routers do not forward broadcasts. Without a helper address it stops at R2, and PC3 ends up with a 169.254 address.
  6. With ip helper-address With ip helper-address 10.0.0.1 on G0/1, R2 relays the Discover to R1 as unicast and stamps it with 192.168.20.1. R1 reads that and chooses the LAN20 pool.
  7. The reply comes back through R2 R1 sends its Offer to R2, which passes it to PC3. Request and Acknowledge follow the same way. PC3 ends up with 192.168.20.11.

Key terms

DHCP pool (scope)
The server's settings for one subnet: the network to lease from, plus options such as gateway and DNS.
Lease
An address lent to a client for a set time. Renewed at about half the time.
Excluded address
An address the server will never lease, because it is set by hand on some device.
Binding
The server's record that a client has a particular address.
Default router (option 3)
The gateway address handed to clients.
DNS server (option 6)
The name server address handed to clients.
DHCP relay / helper address
A router setting that forwards DHCP broadcasts from its LAN to a server elsewhere as unicast.
APIPA (169.254.x.x)
The address a Windows client gives itself when no DHCP server answers.

For the exam

  • 4.3: explain the role of DHCP and DNS in the network. 4.6: configure and verify a DHCP client and relay.
  • Know DORA in order, and that Discover and Request are broadcasts.
  • Ports: the server listens on UDP 67, the client on UDP 68.
  • The helper address goes on the interface facing the clients, not the one facing the server.
  • ip address dhcp makes a router interface a DHCP client (common on ISP links).

Common mistakes

  • Helper address on the wrong interface: the broadcast never reaches the interface that would relay it.
  • Pool without default-router: clients get an address but cannot leave their own subnet.
  • Pool network that does not match the subnet: the server has no pool for requests from that LAN, so nobody gets an address.
  • No exclusions: a client can be leased the same address as a printer or server.

Quick check

1. A PC has just been plugged in and has no address. What is the first DHCP message it sends, and how?

  1. A Discover, broadcast to every device on the LAN
  2. A Request, sent straight to the DHCP server
  3. An Offer, broadcast to every device on the LAN
  4. A Discover, sent to its default gateway
Show the answer

A. A Discover, broadcast to every device on the LAN

It has no address and does not know the server or the gateway yet, so the only thing it can do is broadcast a Discover.

2. PC3 is on R2's LAN and the DHCP server is R1. Where does ip helper-address 10.0.0.1 go?

  1. On R2 G0/1, the interface facing PC3
  2. On R2 G0/0, the interface facing R1
  3. On R1 G0/1, facing R2
  4. On PC3
Show the answer

A. On R2 G0/1, the interface facing PC3

The relay has to be on the interface that receives the client's broadcast. That is the LAN interface, G0/1.

3. Clients get addresses but cannot reach anything outside their own subnet. What is the pool most likely missing?

  1. default-router
  2. dns-server
  3. network
  4. lease
Show the answer

A. default-router

Without default-router the clients have no gateway, so they can only talk inside their own subnet. A missing dns-server would break names, not addresses.

4. What does ip dhcp excluded-address 192.168.10.1 192.168.10.10 do?

  1. Stops the server leasing those addresses, so they can be set by hand
  2. Blocks DHCP requests from those hosts
  3. Reserves them for particular MAC addresses
  4. Makes them the pool's gateways
Show the answer

A. Stops the server leasing those addresses, so they can be set by hand

Exclusions keep hand-set addresses (gateway, switches, servers) out of the pool so no client gets a duplicate.

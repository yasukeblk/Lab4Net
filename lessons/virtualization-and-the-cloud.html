Virtualization and the cloud

How virtual machines, containers and VRFs work

  • 1.12

The problem virtualization solves

Running one application per physical server wastes money. Most servers sit mostly idle, yet each needs its own power, cooling, rack space and cabling. Virtualization splits one physical machine into many independent virtual ones, so the hardware is shared and used far more fully. The same idea applies to the network: one router can hold several separate routing tables.

Virtual machines and hypervisors

A virtual machine (VM) is a complete computer in software: virtual CPU, memory, disk and network card, running its own operating system. The hypervisor is the software that creates VMs and shares the real hardware between them.

  • A Type 1 (bare-metal) hypervisor runs directly on the hardware. VMware ESXi, Microsoft Hyper-V and KVM are examples. Data centers use this type.
  • A Type 2 (hosted) hypervisor runs as an application on a normal operating system, such as VirtualBox or VMware Workstation on a laptop.

Because a VM is just files, it can be copied, backed up, or moved to another host while it is running.

The virtual switch

VMs on one host still need a network. The hypervisor provides a virtual switch (vSwitch) in software. Each VM's virtual network card plugs into it, and it forwards frames between VMs on the same host by MAC address, just like a physical switch. The host's real network cards are the vSwitch's uplinks to the physical network.

Because VMs on one host often belong to different VLANs, the physical switch port facing the host is usually an 802.1Q trunk, and the vSwitch tags each VM's traffic with its VLAN.

This matters when a VM moves to another host. It keeps its IP address and MAC address, so its VLAN must exist on the new host's trunk as well. If it does not, the VM arrives on a host where its VLAN goes nowhere and it drops off the network. Traffic between VMs on the same host may never touch a physical switch at all, which also means a physical switch cannot see or filter it.

Containers

A container packages an application with the libraries it needs, but not a whole operating system. All containers on a host share the host's operating system kernel and are kept apart from each other by it. That makes them much smaller than VMs and quick to start, usually in seconds. Docker is a common container engine, and Kubernetes orchestrates containers across many hosts, starting, stopping and moving them as demand changes.

In short: a VM virtualizes the hardware, a container virtualizes the operating system.

VRFs: virtual routers

A VRF (virtual routing and forwarding instance) gives a router several separate routing tables. Each interface is placed in one VRF, and traffic in one VRF can only use that VRF's routes. It is like having several routers in one box.

Because the tables are separate, two VRFs can even use the same overlapping IP addresses, for example two customers both using 10.1.1.0/24. Service providers use this to carry many customers on shared routers. Using VRFs without MPLS is called VRF-Lite.

Commands to recognise: ip vrf forwarding NAME on an interface (it removes the interface's IP address, which must then be configured again), show ip route vrf NAME and ping vrf NAME.

The cloud

Cloud computing is virtualization offered as a service. Its defining traits (from NIST) are on-demand self-service, broad network access, resource pooling, rapid elasticity (grow and shrink quickly) and measured service (pay for what you use).

  • IaaS (infrastructure): you rent VMs, storage and networks and manage everything above them.
  • PaaS (platform): the provider also runs the operating system and tools; you supply the application.
  • SaaS (software): you just use a finished application, such as web email.

A public cloud is shared by many customers, a private cloud serves one organisation, and a hybrid cloud combines them.

Key terms

Virtual machine
A software computer with its own operating system, running on a hypervisor.
Hypervisor
Software that creates virtual machines and shares physical hardware between them.
Type 1 hypervisor
A bare-metal hypervisor that runs directly on the server hardware.
Virtual switch
A software switch inside a host that connects VMs to each other and to the physical network.
Container
An isolated application package that shares the host operating system kernel.
VRF
A separate routing table on a router; interfaces in one VRF use only its routes.
IaaS
Infrastructure as a Service: rented virtual servers, storage and networking.

For the exam

  • 1.12: explain virtualization fundamentals (server virtualization, containers, and VRFs).
  • Type 1 hypervisors run on bare metal; Type 2 run on a host operating system.
  • VMs each run a full operating system; containers share the host kernel, so they are lighter and start faster.
  • VRFs separate routing tables on one router and allow overlapping IP addresses.
  • Cloud service models: IaaS, PaaS, SaaS. Deployment models: public, private, hybrid.

Common mistakes

  • Saying a container includes its own operating system kernel: it shares the host's; a VM has its own.
  • Applying ip vrf forwarding to a configured interface and forgetting the IP address is removed: the interface goes quiet until it is readdressed.
  • Leaving the switch port to a VM host as an access port: only one VLAN's VMs can reach the network.
  • Pinging inside a VRF with a plain ping: it uses the global table and fails; use ping vrf NAME.

Quick check

1. What is the main difference between a virtual machine and a container?

  1. A VM runs its own operating system; containers share the host's kernel
  2. Containers need a Type 1 hypervisor
  3. VMs cannot be moved between hosts
  4. Containers have their own virtual hardware
Show the answer

A. A VM runs its own operating system; containers share the host's kernel

A VM virtualizes the hardware and carries a full operating system. Containers virtualize the operating system, which is why they are smaller and start quickly.

2. Two customers both use 10.1.1.0/24 and connect to the same provider router. What keeps their traffic apart?

  1. NAT on every interface
  2. Separate VLANs on the router's routing table
  3. Different VRFs, each with its own routing table
  4. A Type 2 hypervisor
Show the answer

C. Different VRFs, each with its own routing table

Each VRF has its own routing table, so overlapping addresses can exist side by side without being confused.

3. Which is a Type 1 hypervisor?

  1. VirtualBox on a laptop
  2. VMware Workstation
  3. Docker
  4. VMware ESXi
Show the answer

D. VMware ESXi

ESXi runs directly on the server hardware. VirtualBox and Workstation run on top of an operating system (Type 2), and Docker is a container engine.

4. A company rents virtual servers and installs and patches its own operating systems on them. Which cloud model is this?

  1. SaaS
  2. IaaS
  3. PaaS
  4. On-premises
Show the answer

B. IaaS

With IaaS the provider supplies the virtual hardware and the customer manages the operating system and everything above it.

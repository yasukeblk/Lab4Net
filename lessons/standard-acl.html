Standard ACL

How a router filters by source address

  • 5.6Access control lists

The problem: some traffic should not get through

Routing makes every network reachable from every other. That is usually the goal, but not always. Guests on 192.168.2.0/24 should not reach the server LAN, 192.168.3.0/24, while staff on 192.168.1.0/24 should.

An access control list (ACL) is an ordered list of permit and deny lines. Applied to an interface, it makes the router check every packet against the list as it passes, and either forward or drop it.

How a router reads an ACL

  1. It checks the packet against the first line, then the next, from the top down.
  2. The first match wins. The router permits or denies the packet and stops reading.
  3. If no line matches, the packet hits the implicit deny: an invisible deny any at the end of every ACL.

That last rule is why ACL 10 needs permit any after its deny line. Without it, staff traffic would match nothing and be dropped too.

Standard ACLs and wildcard masks

A standard ACL matches on the source address only. Numbered standard ACLs use 1 to 99 and 1300 to 1999.

The address is followed by a wildcard mask. A 0 bit means "this bit must match" and a 1 bit means "ignore it". So 192.168.2.0 0.0.0.255 matches anything starting 192.168.2. The keyword host means a wildcard of 0.0.0.0 (one exact address), and any means 255.255.255.255 (every address). A quick way to find the wildcard is 255.255.255.255 minus the subnet mask.

Direction and placement

An ACL does nothing until it is applied with ip access-group, inbound (in, as packets enter) or outbound (out, as they leave). Each interface can have one ACL per direction for IPv4.

Because a standard ACL cannot see the destination, put it as close to the destination as possible. Applied on R1 near the guests, ACL 10 would block guests from everything beyond R1. Applied outbound on R2 G0/1, the interface facing SRV1, it only affects traffic going to the server LAN.

How it is configured here

On R2: access-list 10 deny 192.168.2.0 0.0.0.255, then access-list 10 permit any, then ip access-group 10 out on G0/1. Test it both ways: PC1 (192.168.1.10) still reaches SRV1 (192.168.3.10), PC2 (192.168.2.10) does not, and PC2 can still ping R2 at 10.0.0.2, because that traffic never leaves G0/1.

Check it worked

show access-lists shows each line with a match counter. When PC2 pings the server, the counter on the deny line should rise. show ip interface g0/1 confirms which ACL is applied and in which direction. A counter that never moves means the ACL is not in the path you think it is.

See it happen

In the app, these steps play out as packets moving across the lab's map.

  1. Staff traffic passes PC1 pings 192.168.3.10. As the packet leaves R2 G0/1, ACL 10 checks the source 192.168.1.10. It does not match the deny line, so the permit any line lets it through.
  2. The reply comes back The reply enters R2 on G0/1. ACL 10 is outbound only, so it does not check traffic coming in from the server.
  3. Guest traffic is dropped PC2 pings the server. R2 routes the packet toward G0/1, and ACL 10 checks it on the way out. The source matches the deny line, so R2 drops it and the counter on that line goes up.
  4. The guest can still reach R2 PC2 pings 10.0.0.2, R2's own address. That packet is for R2 itself and never leaves G0/1, so ACL 10 never sees it.
  5. Why not filter on R1? A standard ACL cannot see the destination. Denying guests near the source would block them from everything beyond R1, not just the server LAN, so it goes near the destination.

Key terms

ACL
Access control list: an ordered list of permit and deny lines a router checks packets against.
Standard ACL
An ACL that matches only the source IP address. Numbered 1 to 99 or 1300 to 1999.
Wildcard mask
A mask where 0 bits must match and 1 bits are ignored.
Implicit deny
The invisible deny any at the end of every ACL that drops anything not matched.
Inbound / outbound
Whether the ACL checks packets as they enter or as they leave the interface.
host / any
Shorthand for wildcard 0.0.0.0 (one address) and 255.255.255.255 (all addresses).

For the exam

  • 5.6: configure and verify access control lists.
  • Standard ACLs: source only, numbers 1 to 99 and 1300 to 1999. Place them close to the destination.
  • Lines are read top down, first match wins, and every ACL ends with an implicit deny.
  • Know how to turn a subnet mask into a wildcard: /24 is 0.0.0.255, /26 is 0.0.0.63.
  • One ACL per interface, per direction, per protocol.

Common mistakes

  • Only a deny line and no permit any: the implicit deny drops everyone, so staff lose the server too.
  • Using the subnet mask instead of the wildcard (255.255.255.0): the line matches the wrong addresses.
  • Placing the standard ACL near the source: guests are cut off from every network beyond R1, not just the servers.
  • Creating the ACL but never applying it with ip access-group: nothing is blocked and the counters stay at zero.

Quick check

1. What does a standard ACL match on?

  1. Source and destination address
  2. Source address only
  3. Destination address and port
  4. Protocol and source address
Show the answer

B. Source address only

Standard ACLs only look at the source IP. Matching on destination, protocol or port needs an extended ACL.

2. ACL 10 has only deny 192.168.2.0 0.0.0.255. What happens to staff traffic from 192.168.1.10?

  1. It is permitted, because it does not match the deny
  2. It is dropped by the implicit deny at the end
  3. It is permitted, but logged
  4. It is dropped only if it is ICMP
Show the answer

B. It is dropped by the implicit deny at the end

A packet that matches no line hits the invisible deny any. That is why the lab adds permit any as the second line.

3. Which wildcard mask matches the subnet 10.1.1.0/26?

  1. 255.255.255.192
  2. 0.0.0.192
  3. 0.0.0.31
  4. 0.0.0.63
Show the answer

D. 0.0.0.63

Wildcard = 255.255.255.255 minus the mask. A /26 mask is 255.255.255.192, so the wildcard is 0.0.0.63.

4. Why is ACL 10 applied outbound on R2 G0/1 rather than on R1?

  1. A standard ACL cannot see the destination, so near the source it would block guests from everything
  2. Standard ACLs only work outbound
  3. R1 has no free interfaces
  4. ACLs must be on the router closest to the server
Show the answer

A. A standard ACL cannot see the destination, so near the source it would block guests from everything

Placing a source-only filter near the destination limits its effect to traffic heading there. Standard ACLs can be applied in either direction.

5. PC2 still pings 10.0.0.2 after the ACL is applied. Why?

  1. 10.0.0.2 is on the permit list
  2. ACLs never filter ICMP
  3. The packet is addressed to R2 itself and never leaves G0/1
  4. The implicit deny only applies to TCP
Show the answer

C. The packet is addressed to R2 itself and never leaves G0/1

An outbound ACL on G0/1 only checks packets leaving G0/1. Traffic for R2's own address is handled by R2 and never goes out that interface.

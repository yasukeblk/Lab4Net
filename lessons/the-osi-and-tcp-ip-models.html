The OSI and TCP/IP models

How the layers fit together

  • CCNA 1.5
  • CCNA 1.13Switching concepts

Why split networking into layers

Sending a web page involves many separate jobs: electrical signals, addressing on a link, finding a path across networks, keeping data in order, and the web protocol itself. A layered model gives each job its own layer. Each layer only has to work with the one above and below it.

The layers are also the shared language of troubleshooting. "It is a layer 1 problem" tells a colleague to look at cables, not routes.

The seven OSI layers

  1. Physical: bits on a cable, fiber or radio. Connectors, speed, signal.
  2. Data link: frames between devices on the same link. MAC addresses, Ethernet, VLANs, error checking.
  3. Network: packets between networks. IP addresses and routing.
  4. Transport: delivery between applications. TCP and UDP, port numbers.
  5. Session: starting, keeping and ending conversations.
  6. Presentation: data format, encryption and compression.
  7. Application: the protocol the program uses, such as HTTP, DNS or SSH.

One way to remember the order from 1 to 7: Please Do Not Throw Sausage Pizza Away.

Names for the data at each layer

The unit of data has a different name at each of the lower layers. These names are tested.

  • Layer 4: a segment (TCP) or datagram (UDP).
  • Layer 3: a packet.
  • Layer 2: a frame.
  • Layer 1: bits.

When a host sends, each layer wraps what it gets from above in its own header. This is encapsulation: data goes in a segment, the segment in a packet, the packet in a frame. The receiver unwraps in the opposite order.

Which device works at which layer

  • Layer 1: cables, hubs and repeaters. They pass bits and understand nothing.
  • Layer 2: switches and access points. They read MAC addresses.
  • Layer 3: routers and Layer 3 switches. They read IP addresses.
  • Layers 4 to 7: firewalls and load balancers can read ports and application data.

A device understands its own layer and every layer below it. A router reads the frame before it reads the packet.

The TCP/IP model

Real networks run the TCP/IP suite, which is described with fewer layers:

  • Application: covers OSI layers 5, 6 and 7.
  • Transport: the same as OSI layer 4.
  • Internet: the same as OSI layer 3.
  • Network access (also called link): covers OSI layers 1 and 2.

People still use the OSI numbers in daily speech. A "layer 3 switch" and a "layer 2 loop" are OSI terms.

Where common protocols sit

  • Layer 7: HTTP, HTTPS, DNS, DHCP, SSH, Telnet, FTP, TFTP, SNMP, NTP.
  • Layer 4: TCP and UDP.
  • Layer 3: IPv4, IPv6, ICMP. Routing protocols such as OSPF belong here too.
  • Layer 2: Ethernet, 802.1Q, STP, CDP, LLDP. ARP works between layers 2 and 3 and is usually listed with layer 2.

Using the layers to find a fault

Work upwards from the bottom, because each layer depends on the ones beneath it.

  1. Layer 1: is the interface up? Is there a link light?
  2. Layer 2: right VLAN, trunk working, MAC address learned?
  3. Layer 3: right address, mask and gateway? Is there a route, both ways?
  4. Layer 4 and above: is an ACL blocking the port? Is the service running?

show ip interface brief shows layers 1 and 2 at a glance: the Status column is layer 1 and the Protocol column is layer 2.

Key terms

OSI model
A seven-layer reference model for how network communication is divided up.
Encapsulation
Adding a layer's header (and sometimes trailer) around the data from the layer above.
PDU
Protocol data unit: the name for the data at a given layer.
Segment
The layer 4 PDU for TCP.
Packet
The layer 3 PDU.
Frame
The layer 2 PDU.
TCP/IP model
The four-layer model that describes the protocol suite used on real networks.

For the exam

  • The models support 1.5 (TCP and UDP at the transport layer) and 1.13 (switching at the data link layer), and they are assumed knowledge throughout.
  • Know the PDU names: segment at layer 4, packet at layer 3, frame at layer 2, bits at layer 1.
  • Switches forward on MAC addresses at layer 2. Routers forward on IP addresses at layer 3.
  • The TCP/IP application layer covers OSI layers 5 to 7; its network access layer covers OSI layers 1 and 2.

Common mistakes

  • Mixing up frame and packet. A switch forwards frames; a router forwards packets.
  • Starting at the top when troubleshooting. Checking an ACL is a waste of time if the cable is unplugged.
  • Thinking a router ignores layer 2. It must receive and rebuild a frame on every link.

Quick check

1. What is the layer 2 PDU called?

  1. Packet
  2. Segment
  3. Bits
  4. Frame
Show the answer

D. Frame

Layer 2 uses frames. Packets are layer 3, segments are layer 4 and bits are layer 1.

2. At which OSI layer does a router make its forwarding decision?

  1. Layer 2
  2. Layer 3
  3. Layer 4
  4. Layer 7
Show the answer

B. Layer 3

A router forwards on the destination IP address, which is a layer 3 address. A switch decides at layer 2 using MAC addresses.

3. Which OSI layers are covered by the TCP/IP application layer?

  1. 5, 6 and 7
  2. 1 and 2
  3. 4 and 5
  4. Only 7
Show the answer

A. 5, 6 and 7

The TCP/IP model folds session, presentation and application into one application layer.

4. During encapsulation on a sending host, what is the correct order?

  1. Frame, packet, segment, data
  2. Data, packet, segment, frame
  3. Data, segment, packet, frame
  4. Segment, data, frame, packet
Show the answer

C. Data, segment, packet, frame

Data is wrapped in a segment at layer 4, then a packet at layer 3, then a frame at layer 2, and sent as bits.

5. In show ip interface brief, an interface shows Status up and Protocol down. Which layer has the problem?

  1. Layer 1
  2. Layer 3
  3. Layer 2
  4. Layer 4
Show the answer

C. Layer 2

Status is the physical layer and Protocol is the data link layer. Up and down means the cable is good but layer 2 is not working.

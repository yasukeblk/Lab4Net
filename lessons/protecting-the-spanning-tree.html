Protecting the spanning tree

How to keep spanning tree stable

  • CCNA 2.5Rapid PVST+ interpretation

What can go wrong

Spanning tree keeps a switched network free of loops by electing a root bridge and blocking spare paths. Three things can upset it:

  • Someone plugs a switch into an access port, which adds a path spanning tree did not plan for.
  • A new or misconfigured switch claims to be the root bridge and drags traffic through the wrong place.
  • A link goes one-way: a blocked port stops hearing BPDUs, decides the path is clear, and starts forwarding into a loop.

Cisco switches have a feature for each. Objective 2.5 names all of them.

Recap: Rapid PVST+ roles and states

Rapid PVST+ runs one rapid spanning tree per VLAN. A port has a role:

  • Root: this switch's best path to the root bridge.
  • Designated: the port that forwards for a segment.
  • Alternate: a blocked backup for the root port.
  • Backup: a blocked backup for a designated port on the same segment.

And a state: discarding, learning or forwarding. Root and designated ports end up forwarding. Alternate and backup ports stay discarding.

PortFast and BPDU Guard

PortFast is for ports that connect to end devices. The port goes straight to forwarding when it comes up, so a PC does not wait while spanning tree checks for a loop. PortFast does not turn spanning tree off on the port.

BPDU Guard protects those ports. A PC never sends BPDUs, so a BPDU arriving on an access port means a switch has been connected. BPDU Guard puts the port in err-disabled and it stays down until someone fixes it.

  • Per port: spanning-tree portfast and spanning-tree bpduguard enable.
  • For every access port at once: spanning-tree portfast default and spanning-tree portfast bpduguard default.

To recover a port, remove the cause, then shutdown and no shutdown.

BPDU Filter

BPDU Filter stops a port sending BPDUs. It behaves differently depending on where it is set, and the exam likes the difference.

  • Globally, with spanning-tree portfast bpdufilter default: applies to PortFast ports. They stop sending BPDUs. If one of them receives a BPDU, it gives up PortFast and the filter and becomes a normal spanning-tree port. This is fairly safe.
  • On an interface, with spanning-tree bpdufilter enable: the port neither sends BPDUs nor listens to them. Spanning tree is in effect off on that port, and a loop there will not be caught.

Root Guard

Root Guard goes on ports where the root bridge should never appear, such as ports that face access switches or another company.

If a superior BPDU arrives, one that claims a better root than the current one, the port is put in the root-inconsistent state and stops forwarding. The current root stays the root. When the superior BPDUs stop, the port recovers by itself.

Command: spanning-tree guard root on the interface.

Loop Guard

Loop Guard protects against one-way links. It watches ports that are supposed to receive BPDUs: root ports and alternate ports.

Normally, a blocked port that stops hearing BPDUs assumes the other side has gone and moves to forwarding. With Loop Guard it goes to the loop-inconsistent state and stays blocked. It recovers by itself when BPDUs return.

Commands: spanning-tree guard loop on an interface, or spanning-tree loopguard default for the whole switch. Root Guard and Loop Guard cannot both be active on the same port.

Checking

  • show spanning-tree vlan 10 shows each port's role and state. Guarded ports show BKN* with the reason ROOT_Inc or LOOP_Inc.
  • show spanning-tree inconsistentports lists every port a guard has blocked.
  • show interfaces status err-disabled lists ports shut by BPDU Guard.
  • show spanning-tree summary shows which features are on by default.

Key terms

PortFast
Lets an edge port go straight to forwarding when it comes up.
BPDU Guard
Err-disables a port that receives a BPDU.
BPDU Filter
Stops a port sending BPDUs; on an interface it also ignores received ones.
Root Guard
Blocks a port that receives a superior BPDU, so the root bridge cannot move there.
Loop Guard
Keeps a port blocked if it stops receiving BPDUs, instead of letting it forward.
Superior BPDU
A BPDU advertising a better root bridge than the one currently known.
Err-disabled
A state in which the switch has shut a port because of a fault or violation.

For the exam

  • 2.5: interpret basic operations of Rapid PVST+, including root port, root bridge, port states and roles, PortFast, root guard, loop guard, BPDU filter and BPDU guard.
  • BPDU Guard err-disables the port and needs manual recovery. Root Guard and Loop Guard put the port in an inconsistent state and recover by themselves.
  • Root Guard reacts to superior BPDUs arriving. Loop Guard reacts to BPDUs going missing.
  • PortFast and BPDU Guard belong on access ports to end devices, never on links to other switches.
  • Rapid PVST+ states: discarding, learning, forwarding.

Common mistakes

  • Enabling PortFast on a link to another switch. The port forwards at once and can create a short loop.
  • Using interface-level BPDU Filter to "tidy up" an access port. It switches spanning tree off there.
  • Reading a root-inconsistent port as a cabling fault. It means another switch is claiming to be root.

Quick check

1. An access port with BPDU Guard receives a BPDU. What happens?

  1. The port becomes a root port
  2. The port is put in err-disabled
  3. The BPDU is silently dropped
  4. The port goes to root-inconsistent
Show the answer

B. The port is put in err-disabled

BPDU Guard shuts the port by putting it in err-disabled. Dropping silently is what interface-level BPDU Filter does, and root-inconsistent is Root Guard.

2. Which feature stops a newly connected switch with a lower priority from becoming the root bridge?

  1. Loop Guard
  2. PortFast
  3. BPDU Filter
  4. Root Guard
Show the answer

D. Root Guard

Root Guard blocks a port that hears a superior BPDU, so the root cannot move behind it.

3. What does Loop Guard do when a blocked port stops receiving BPDUs?

  1. Keeps it blocked in the loop-inconsistent state
  2. Moves it to forwarding
  3. Err-disables it
  4. Makes it a designated port
Show the answer

A. Keeps it blocked in the loop-inconsistent state

Without Loop Guard the port would move to forwarding and could cause a loop. With it, the port stays blocked until BPDUs are heard again.

4. What is the effect of spanning-tree bpdufilter enable on an interface?

  1. The port err-disables when a BPDU arrives
  2. The port sends BPDUs but ignores received ones
  3. The port stops sending BPDUs and ignores received ones
  4. PortFast is enabled on the port
Show the answer

C. The port stops sending BPDUs and ignores received ones

At interface level the filter works in both directions, which in effect turns spanning tree off on that port.

5. Which are the port states in Rapid PVST+?

  1. Blocking, listening, learning, forwarding
  2. Discarding, learning, forwarding
  3. Disabled, blocking, forwarding
  4. Listening, learning, forwarding
Show the answer

B. Discarding, learning, forwarding

Rapid spanning tree has three states. Blocking and listening belong to the original 802.1D.
